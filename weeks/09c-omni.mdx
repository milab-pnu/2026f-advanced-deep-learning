Omni-modal large language model(Omni-modal LLM)은 여러 종류의 입력을 함께 해석하고, 모델에 따라서는 텍스트 외의 형태로도 출력하는 모델이다.[^survey]
많은 Omni 모델은 modality별 encoder, LLM(large language model), 출력 쪽 생성기로 이루어진다.

<Figure src="https://raw.githubusercontent.com/vllm-project/vllm-omni/0c245dd1f9740ddae8f4a50019b8e6c05e197859/docs/source/architecture/omni-modality-model-architecture.png" alt="Omni 모델의 일반적인 구성. 왼쪽의 text, image, audio, video 입력이 Whisper나 ViT 같은 modality encoder로 들어가고, 가운데의 autoregressive LLM을 거쳐, DiT 같은 modality generator가 오른쪽의 text, image, audio, video 출력을 만든다." caption="Omni 모델의 일반적인 구성. 입력마다 encoder를 두고, 가운데 LLM이 autoregressive하게 생성하며, 출력 쪽 생성기가 텍스트 외의 출력을 만든다." source="vLLM-Omni Project, GitHub README 구조 그림 · Apache-2.0" />

## 1. 여러 modality의 연결

### 1-1. 공통 표현 공간

CLIP과 CLAP처럼 두 modality를 쌍으로 정렬하는 방식을 여러 modality로 넓히면, modality 쌍마다 대응 자료가 필요하다.
ImageBind는 이미지를 공통 연결점으로 삼아 이 문제를 푼다.[^imagebind]
이미지와 텍스트가 이미 정렬된 공간에서 출발해, audio·깊이·열영상 같은 다른 modality의 encoder를 각각 대응 이미지의 표현과 가까워지도록 학습한다.
그러면 짖는 소리와 “개가 짖는다”라는 텍스트의 쌍을 직접 보지 않았더라도, 두 표현이 개 사진을 거쳐 가까워질 수 있다.
ImageBind 원논문은 이처럼 직접 학습하지 않은 조합에서 나타나는 정렬을 emergent alignment라 부른다.
다만 공통 공간은 표현의 유사도를 비교하게 해 줄 뿐, 시간 관계를 추론하거나 문장으로 답하는 기능까지 주지는 않는다.

### 1-2. Modality별 경로

질문에 답하려면 LLM이 각 modality의 표현을 읽어야 한다.
초기 audio-visual 모델인 Video-LLaMA는 영상과 audio에 경로를 따로 두고, 경로마다 Q-Former로 frame이나 소리 구간의 정보를 정해진 수의 벡터로 요약해 LLM에 넣는다.[^videollama]
Audio encoder로는 ImageBind를 쓴다.

<Figure src="https://arxiv.org/html/2306.02858v4/video_llama_architecture_v7.png" alt="Video-LLaMA 구조. 왼쪽 vision-language branch에서는 고정된 visual encoder가 비디오 frame마다 feature를 내고, 시간 위치 embedding을 더한 뒤 Video Q-Former와 선형층을 거쳐 LLM으로 들어간다. 오른쪽 audio-language branch에서는 고정된 audio encoder가 소리 구간마다 feature를 내고, 시간 위치를 더한 뒤 Audio Q-Former와 선형층을 거친다. 맨 위의 LLM은 고정되어 있고 두 branch의 출력과 텍스트 지시를 받아 설명을 생성한다." caption="Video-LLaMA의 두 경로. 눈꽃 표시는 고정된 모델, 불꽃 표시는 학습하는 모듈이다. 영상과 audio가 각각 Q-Former로 요약되어 LLM에 들어가며, 두 경로는 LLM 안에서 처음 만난다." source="Zhang et al. (2023), Figure 1 · CC BY 4.0" />

이 구조에서 영상과 audio는 각자 고정 개수의 벡터로 요약된 뒤 LLM 안에서야 처음 만난다.
그래서 두 신호 사이의 세밀한 시간 관계가 LLM에 충분히 전달되지 않을 수 있다.

## 2. 영상과 소리의 시간 정렬

### 2-1. 같은 순간의 두 신호

두 사람이 차례로 말하는 영상에서 “누가 박수가 들릴 때 말했는가?”를 묻는다고 하자.
모델은 박수 소리 주변의 frame에서 입의 움직임을 보고 음성과 대조해야 하므로, 두 신호에서 같은 순간을 찾을 수 있어야 한다.
그런데 영상과 audio는 보통 서로 다른 간격으로 뽑힌다.
예를 들어 0초와 1초에 영상 frame을 뽑고 audio를 0.5초 구간으로 나누면, 0.7초의 박수는 두 번째 audio 구간에 들어가지만 그 순간의 화면은 입력에 없다.

두 신호를 강하게 압축할수록 입력은 짧아지지만, 입 모양과 음절이 맞는지 같은 두 신호 사이의 대응이 사라질 수 있다.

### 2-2. 실제 시간에 맞춘 위치

Audio encoder는 영상 encoder와 다른 속도로 표현을 만든다.
그래서 입력에 순번만 매기면, 서로 다른 modality의 두 표현이 실제 시간에서 얼마나 떨어져 있는지 알 수 없다.
Qwen2.5-Omni의 TMRoPE(time-aligned multimodal rotary position embedding)는 시간 성분을 실제 시각에 맞춘 M-RoPE를 audio까지 넓힌다.[^qwen25]
시간 번호 하나는 40 ms에 해당한다.
Audio는 공간 위치가 없으므로 세 성분에 같은 시간 번호를 쓴다.

<Figure src="https://arxiv.org/html/2503.20215v1/figures/ATMRoPE.png" alt="TMRoPE의 위치 부여. 영상 frame의 patch마다 (시간, 높이, 너비) 세 숫자가 붙어 있다. 첫 frame의 patch는 (0, 0, 0)부터 (0, 2, 2)까지이고 다음 frame은 시간 성분이 25, 그다음은 50, 75로 늘어난다. 아래의 audio 파형에는 (0, 0, 0), (25, 25, 25), (50, 50, 50)처럼 세 성분이 같은 값으로 붙고, 2초마다 구간이 나뉜다." caption="TMRoPE의 위치 ID (시간, 높이, 너비). 한 frame의 patch는 시간 ID를 공유하고 높이·너비가 다르며, audio는 세 성분이 같은 시간 ID로 함께 늘어난다. 시간 ID 25칸이 1초이므로, 같은 순간의 영상 patch와 audio 표현은 시간 ID가 같다." source="Xu et al. (2025), Figure 3 · CC BY 4.0" wide />

그래서 같은 순간의 영상과 audio는 sequence 안에서 멀리 떨어져 있어도 같은 시간 번호를 받는다.
다만 위치 번호가 뽑히지 않은 frame을 채워 주지는 않는다.
앞의 예에서 0.7초의 화면은 여전히 없다.
모델이 위치 번호로 알 수 있는 것은 박수가 든 0.5–1초 audio 구간이 0초 frame보다 1초 frame에 가깝다는 사실까지다.

Sequence 안의 배치는 따로 정한다.
Qwen2.5-Omni는 영상과 audio를 실제 시간 기준 2초 구간(chunk)으로 나누고, 구간마다 영상 표현 다음에 audio 표현을 둔다.

```text
[영상: 0–2초] [audio: 0–2초] [영상: 2–4초] [audio: 2–4초] … [질문] [답변]
```

후속 모델인 Qwen3-Omni는 고정된 2초 chunk를 없애고 시간 번호만으로 영상과 audio를 정렬해, 길이에 제한 없는 streaming 입력을 받을 수 있게 했다.[^qwen3]
MiniCPM-o 4.5는 입력뿐 아니라 모델의 텍스트·음성 출력까지 같은 시간축에 맞춘다.[^minicpmo45]
이 모델은 동시에 흐르는 영상·audio 입력과 출력을 짧은 주기의 시간 구간마다 묶어 LLM에 차례로 넣는다.
그래서 사용자의 영상과 음성을 계속 받으면서 음성으로 응답할 수 있다.

## 3. 여러 modality의 학습

### 3-1. 함께 쓰는 데이터

여러 modality를 각각 다루는 데이터를 섞는 것과, 한 예제에서 여러 modality를 **함께 사용하도록 요구하는 것**은 다르다.
모델이 이미지 질문과 audio 질문을 각각 잘 푼다고 해서, 화면의 특정 인물과 동시에 들리는 목소리를 연결할 수 있다고 결론 낼 수는 없다.
카카오는 Kanana-o를 개발하며 이 차이를 직접 겪었다.[^kanana-o]
이미지–텍스트 자료와 audio–텍스트 자료만으로 학습하자, 학습에서 보지 못한 modality 조합이 들어올 때 모델의 반응이 불안정한 경우가 있었다.
이미지·음성·텍스트가 함께 들어오는 공개 자료는 드물어서, 카카오는 이미지–텍스트 자료의 질문이나 답변을 TTS로 음성으로 합성해 세 modality가 함께 쓰이는 예시를 만들었다.
합성 음성은 자료를 쉽게 늘려 주지만, 실제 환경의 잡음과 말투를 모두 담기는 어렵다.

### 3-2. 함께 학습과 model merging

여러 modality를 한 모델에 담는 방법은 처음부터 함께 학습하는 쪽과, 따로 학습한 모델을 나중에 합치는 쪽으로 나뉜다.
여기서 “함께”는 학습의 순서를 말한다.
한 예제 안에서 여러 modality를 함께 쓰게 하는 데이터는 어느 쪽에서든 따로 필요하다.

**처음부터 함께 학습.**
Modality를 하나씩 차례로 학습하는 대신, 처음부터 모든 modality의 데이터를 섞어 학습할 수 있다.
카카오는 이렇게 함께 학습(joint training)할 때 최종 성능이 더 좋다는 EMOVA의 결과를 근거로, 이 방식을 기본 전략으로 삼았다.[^kanana-o]
함께 학습에서 흔히 걱정하는 것은 새 modality를 배우는 동안 텍스트 같은 기존 능력이 떨어지는 것이다.
Qwen3-Omni는 텍스트 사전학습의 초기 단계부터 단일 modality 데이터와 여러 modality가 섞인 데이터를 함께 넣었다.[^qwen3]
Qwen3-Omni 보고서는 같은 크기로 학습한 텍스트 전용, 시각 포함, audio 포함의 세 모델을 비교해, audio를 더해도 텍스트와 시각 성능이 떨어지지 않았다고 보고한다.
다만 일부 텍스트 점수는 조금 낮았고, 모든 모델 크기에서 실험하지는 못했다고 함께 밝힌다.
학습 순서뿐 아니라 표현까지 하나로 합칠 수도 있다.
AnyGPT는 이미지·음성·음악을 모두 discrete token으로 바꾸어, 텍스트 token과 하나의 sequence로 학습한다.[^anygpt]
모든 modality가 처음부터 하나의 token 공간을 공유하는 셈이다.

**따로 학습한 뒤 합치기.**
함께 학습은 모든 단계에서 모든 modality의 데이터를 쓰므로 학습이 길다.
그래서 학습률이나 데이터 비율을 바꿔 보는 실험을 여러 번 하기 어렵고, 시각이나 음성 한쪽의 학습 방법이 좋아지면 통합 모델을 처음부터 다시 학습해야 한다.
Kanana-o는 이 문제를 model merging으로 풀었다.[^kanana-o]
Model merging은 따로 학습한 여러 모델의 parameter를 합쳐 하나의 모델을 만드는 방법이며, 보통 같은 모델에서 출발한 모델들을 합친다.
가장 단순한 형태는 대응하는 parameter를 평균하는 것이다.[^modelsoups]
카카오의 시각 모델 Kanana-v와 음성 모델 Kanana-a는 같은 LLM에서 출발했으므로 parameter를 합칠 수 있다.
카카오는 두 모델을 병합한 뒤 마지막 학습 단계만 추가로 진행해, 처음부터 함께 학습한 모델과 비슷한 성능을 얻었다고 보고한다.
그래서 시각과 음성 모델을 각자 실험하고 개선하다가, 필요할 때 빠르게 합쳐 통합 모델을 만들 수 있다.

## 4. Thinker와 Talker

음성으로 답하는 모델은 흔히 답의 내용을 정하는 언어 모델과, 그 hidden state를 받아 음성 token을 만드는 Voice Token LM 같은 모델을 나눈다.
Qwen2.5-Omni는 이 구조에 Thinker와 Talker라는 이름을 붙였다.[^qwen25]
원논문은 한 모델이 텍스트와 음성을 함께 내면 두 출력이 서로 간섭할 수 있어 역할을 나눴다고 설명하며, Thinker를 뇌에, Talker를 입에 비유한다.
Thinker는 텍스트와 영상·audio 입력을 이해해 응답 텍스트를 생성한다.
Talker는 Thinker의 hidden 표현과 Thinker가 고른 텍스트 token을 함께 받아 음성 codec token을 생성한다.
두 부분은 나뉘어 있지만, 하나의 모델로 end-to-end 학습한다.

<Figure src="https://arxiv.org/html/2503.20215v1/figures/overview.png" alt="Qwen2.5-Omni 구조. 아래쪽에서 시간 순서로 놓인 영상 frame과 audio 파형이 vision encoder와 audio encoder를 거쳐 텍스트 token과 함께 Thinker에 들어간다. Thinker는 응답 텍스트 token을 차례로 sample하고, 그 위의 Talker는 Thinker의 hidden 표현과 sample된 텍스트 token을 받아 codec token을 생성한다. 맨 위의 streaming codec decoder가 codec token을 파형으로 바꾼다." caption="Qwen2.5-Omni의 Thinker–Talker 구조. Thinker가 입력을 이해해 텍스트를 생성하고, Talker는 Thinker의 hidden 표현과 생성된 텍스트를 받아 codec token을 낸다. 맨 위의 decoder가 이를 파형으로 바꾼다." source="Xu et al. (2025), Figure 2 · CC BY 4.0" />

그런데 Talker가 Thinker의 hidden 표현에 기대면, Thinker가 낸 텍스트를 중간에서 고치기 어렵다.
텍스트를 고쳐도 Talker는 고치기 전의 내용이 담긴 hidden 표현을 함께 받기 때문이다.
후속 모델인 Qwen3-Omni의 Talker는 Thinker의 텍스트 쪽 hidden 표현을 받지 않고, Thinker가 낸 텍스트와 audio·시각 feature를 조건으로 쓴다.[^qwen3]
원논문은 텍스트의 내용은 token만으로 충분히 전달되고, audio·시각 feature는 음성 번역에서 원래 화자의 운율과 음색을 살리는 데 필요하다고 설명한다.
이렇게 나누면 RAG(retrieval-augmented generation)나 safety filter 같은 외부 모듈이 Thinker의 텍스트를 고친 뒤 Talker에 넘길 수 있다.

## 5. Omni 모델의 평가

입력 modality별 점수와 modality를 함께 써야 하는 문제의 점수는 서로 다른 능력을 측정한다.
그래서 Omni 모델은 여러 입력을 함께 써야만 풀리는 벤치마크로 평가한다.

| 영역 | 묻는 능력 | 대표 벤치마크 |
| --- | --- | --- |
| 이미지·audio·텍스트 통합 | 세 입력을 함께 이해하고 추론하기 | OmniBench[^omnibench] |
| Audio-visual 비디오 이해 | 영상과 소리가 함께 담긴 실제 비디오에 대해 답하기 | WorldSense[^worldsense] |
| 영상과 소리 단서의 결합 | 영상과 소리의 단서를 모두 써야 풀리는 객관식 문제 풀기 | AV-Odyssey[^avodyssey] |

OmniBench에서는 이미지나 소리를 텍스트 설명으로 바꿔 줘도 대부분의 기준 모델이 정확도 50%에 못 미쳤다.
AV-Odyssey 원논문은 벤치마크에 앞선 예비 실험에서, 두 소리 가운데 어느 쪽이 더 크거나 높은지처럼 사람에게는 쉬운 문제도 모델들이 어려워한다고 보고한다.

한 modality만 보고도 맞힐 수 있는 지름길도 확인해야 한다.
예를 들어 같은 영상에서 A가 먼저 말하고 B가 나중에 말할 때, 박수를 A의 발화 구간에서 B의 발화 구간으로 옮기면 정답도 A에서 B로 바뀌어야 한다.
모델이 두 경우에 같은 답을 낸다면, 시간 위치를 입력받고도 박수와 발화의 시간 관계를 쓰지 못한 것이다.
