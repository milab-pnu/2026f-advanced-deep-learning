[2주차 Pre-training 노트](/lecture/2026f-advanced-deep-learning/02c-pre-training/)에서 만든 base model은 텍스트를 이어 쓰는 모델이다. 질문을 넣으면 답 대신 비슷한 질문을 더 만들어 내기도 하고, 답을 하더라도 어디서 멈출지 모른다. 우리가 쓰는 chat model은 이 base model에 **post-training**을 더한 결과다. 4주차와 5주차는 그 post-training을 다룬다. 이 노트는 그 첫 단계인 <strong>supervised fine-tuning(SFT)</strong>을 다룬다. 학습 목표는 pre-training과 같은 next-token prediction(NTP)인데, 어떤 데이터의 어느 토큰에 손실을 거는지가 다르다. 그 차이가 왜 모델의 행동을 바꾸는지, 얼마나 바꾸는지, 어디까지 바꾸지 못하는지를 따라간다.

전체 지도는 Han 등이 instruction tuning을 정리한 서베이[^survey]로 잡는다. 서베이의 §II(데이터 구성과 목적함수의 형식화)가 이 노트의 §2–3에, §VI(평가)이 §4에 대응한다. 서베이는 LoRA(low-rank adaptation) 같은 parameter-efficient fine-tuning도 §III에서 함께 다루지만, 이 노트는 어떤 파라미터를 갱신하는가보다 **어떤 데이터로 무엇을 학습하는가**에 집중한다.

두 주차의 노트 열 개는 base model에서 출발해 chat model, 그리고 추론 모델(reasoning model)까지 가는 post-training 단계를 하나씩 다룬다. 3주차와 마찬가지로 각 노트는 한 기법의 발전 계보를 따라가며, 아래 표는 그 색인이다. 표에 나오는 알고리즘 이름은 해당 노트에서 정의한다.

| 노트 | 다루는 단계 | 계보의 출발점과 도착점 |
|---|---|---|
| 04a (이 노트) | Supervised fine-tuning | Pre-training의 NTP → 응답 토큰에 손실을 거는 SFT → 지시 데이터의 구성 |
| 04b | RLHF(reinforcement learning from human feedback) | 시연을 모방하는 SFT의 한계 → 선호 비교로 학습한 reward model → 강화학습으로 정책 갱신 |
| 04c | DPO(direct preference optimization) | Reward model과 강화학습의 비용 → 선호쌍에 직접 거는 손실 → 변형과 online 확장 |
| 04d | Reward hacking과 평가 | Reward model과 judge는 대리 지표 → over-optimization·길이 편향 → 평가의 설계 |
| 05a | RLVR(reinforcement learning with verifiable rewards) | 학습된 보상의 한계 → 검증 가능한 보상 → DeepSeek-R1 |
| 05b | Long CoT(chain of thought)와 추론 시 계산 | 강화학습이 만든 긴 사고 사슬 → overthinking → test-time scaling |
| 05c | RLVR의 policy optimization | 비평가(critic)가 있는 알고리즘 → 그룹 상대 보상 → 안정화 변형 |
| 05d | RL 시스템 | Rollout 비용 → inference engine 재사용 → 비동기 학습 |
| 05e | Agentic RL | 단일 응답의 보상 → 도구 호출과 다중 턴 궤적 |
| 05f | Distillation | Teacher 출력의 모방 → on-policy distillation → multi-teacher |

## 1. Post-training의 단계

### 1-1. 실제 모델의 학습 흐름

최근 공개 모델의 post-training은 한 단계가 아니다. 아래는 Allen AI가 2025년에 공개한 Olmo 3의 전체 학습 흐름이다.[^olmo3] 왼쪽의 base model 학습이 pre-training, mid-training, long-context 확장의 세 단계로 나뉘고(토큰 수는 7B 기준이며 32B는 다르다), 오른쪽의 post-training은 SFT, DPO, RLVR로 이어진다. 같은 base model에서 세 가지 모델이 갈라진다는 점도 보자. 긴 사고 과정을 생성하는 Think, 바로 답하는 Instruct, 그리고 SFT 없이 base model에 RLVR만 적용한 RL-Zero다.

### 1-2. 네 recipe 비교

공개 보고서가 단계를 밝힌 네 모델의 post-training을 나란히 놓으면 다음과 같다. 단계 이름은 각 보고서의 표현을 따랐다.

| 모델 | 단계 순서 | 각 단계의 데이터 |
|---|---|---|
| Llama 3 (2024)[^llama] | Reward model 학습 → rejection sampling → SFT → DPO를 한 라운드로 하여 6라운드 반복 | 사람이 쓴 응답과 선호 주석, 모델이 생성한 응답 중 reward model이 고른 것, 능력별 합성 데이터 |
| Tülu 3 (2024)[^tulu3] | SFT → DPO → RLVR | SFT 프롬프트 939,344개, DPO 선호쌍 271,409개(8B), RLVR은 수학·정밀한 지시 따르기처럼 정답을 검증할 수 있는 프롬프트 |
| Olmo 3 Think (2025)[^olmo3] | SFT → DPO → RLVR | SFT 프롬프트 약 227만 개(사고 과정이 포함된 응답), DPO 선호쌍 15만 개(7B), RLVR은 수학·코드·지시 따르기·일반 대화 |
| Qwen3 (2025)[^qwen3] | Long-CoT cold start(SFT) → reasoning RL → thinking mode fusion(SFT) → general RL | 검증 가능한 수학·코드 문제와 긴 사고 과정 응답, 20개 이상 과제의 규칙·모델 기반 보상 |

네 recipe 모두 SFT 단계를 포함하며, 선호 학습이나 RL과 결합하거나 라운드로 반복한다. Llama 3처럼 reward model 학습이 먼저 오는 경우도 SFT 데이터의 일부를 그 reward model로 고르기 때문이다. 이 노트는 SFT 단계만 본다. 뒤 단계로 갈수록 "어떤 응답이 더 좋은가"를 모델 자신이 생성한 응답 위에서 배우게 되는데, 그 전환이 왜 필요한지는 §5에서 정리한다.

한 가지 주의할 점이 있다. 표의 출발점인 base model은 서로 같은 상태가 아니다. Qwen3는 pre-training의 두 번째 단계에서 STEM(science, technology, engineering, mathematics)·코드·추론 데이터의 비중을 높인 약 5T 토큰을 추가로 학습했고,[^qwen3] Olmo 3는 mid-training 100B 토큰에 수학·코드 문제뿐 아니라 지시 데이터와 사고 과정(thinking trace)까지 넣어 post-training의 기반을 미리 닦는다.[^olmo3] 그래서 post-training 뒤의 점수 차이를 SFT나 RL만의 효과로 읽으면 안 된다. Mid-training 자체는 [2주차 Pre-training 노트 §3-3](/lecture/2026f-advanced-deep-learning/02c-pre-training/)의 데이터 혼합 변경과 같은 원리이므로 여기서 다시 다루지 않는다.

## 2. SFT의 목적함수

### 2-1. Base model과 지시 따르기

[1주차 BERT vs GPT 노트 §3-2](/lecture/2026f-advanced-deep-learning/01b-bert-vs-gpt/)에서 본 것처럼, GPT-3 이후로는 가중치를 바꾸지 않고 프롬프트에 예시를 넣어 과제를 지시하는 in-context learning이 널리 쓰였다. 그런데 이 방식에는 두 가지 불편이 있다. 사용자가 매번 예시를 써 넣어야 하고, 예시가 없는 zero-shot 지시에는 base model이 지시 자체를 이어 쓰거나 엉뚱한 형식으로 답하기 쉽다. Base model은 웹 문서의 다음 토큰을 예측하도록 학습했으므로, "다음 질문에 답하라"는 문장 뒤에 올 확률이 높은 것은 답이 아니라 또 다른 질문일 수 있다.

SFT는 이 문제를 데이터로 푼다. 지시(instruction)와 그에 대한 응답(response)의 쌍을 모아, 지시가 주어졌을 때 응답을 생성하도록 가중치를 갱신한다. 지시가 대화 형식이면 여러 턴의 user·assistant 메시지가 된다. 학습 목표는 여전히 NTP이며, 달라지는 것은 **어떤 텍스트를 넣고, 그중 어느 토큰의 예측을 채점하는가**다.

### 2-2. Chat template

지시와 응답을 하나의 토큰열로 만들려면 누가 말하는 부분인지 표시해야 한다. 이 형식이 **chat template**이다. 모델마다 다르며, Hugging Face Transformers는 tokenizer에 저장된 Jinja 템플릿을 `apply_chat_template`으로 적용한다.[^hf-chat] Llama 3의 형식을 보자. 역할 이름을 `<|start_header_id|>`와 `<|end_header_id|>`로 감싸고, 메시지 끝을 `<|eot_id|>`(end of turn)로 표시한다.[^llama-format]

```
<|begin_of_text|><|start_header_id|>user<|end_header_id|>

What is France's capital?<|eot_id|><|start_header_id|>assistant<|end_header_id|>

```

추론할 때는 프롬프트가 assistant 헤더로 끝나야 모델이 응답을 생성한다. Transformers의 `add_generation_prompt=True`가 이 헤더를 붙이는 옵션이다.[^hf-chat] 학습할 때는 응답까지 붙인 전체 토큰열을 넣으므로 이 옵션을 끈다. 학습 토큰열과 추론 프롬프트는 응답의 유무만 다를 뿐, 역할 표시·경계 토큰·줄바꿈 같은 직렬화 규칙이 같아야 한다. 학습 때와 다른 형식으로 프롬프트를 주면 성능이 크게 떨어진다.[^hf-chat]

### 2-3. Loss mask

[2주차 Pre-training 노트 §2-3](/lecture/2026f-advanced-deep-learning/02c-pre-training/)의 NTP 목적함수를 그대로 가져온다.

$$
\mathcal{L}=-\frac{1}{\sum_i m_i}\sum_i m_i\log p_\theta(t_i\mid t_{<i})
$$

Pre-training에서는 문서의 거의 모든 토큰에 $m_i=1$을 주었다. SFT에서는 흔히 **assistant 응답 토큰에만** $m_i=1$을 주고 지시 토큰은 0으로 둔다. Llama 3 보고서는 SFT에서 프롬프트 토큰의 손실을 mask한다고 명시하고,[^llama] Hugging Face TRL의 `SFTTrainer`는 prompt-completion 데이터에서 completion 토큰만 채점하는 `completion_only_loss`를 기본값으로 하며 대화 데이터에는 `assistant_only_loss` 옵션을 둔다.[^trl-sft] 전체 토큰열을 채점하는 선택도 가능하고 TRL도 이를 지원하지만, 그러면 모델은 사용자의 질문을 생성하는 법도 함께 배운다. 이 노트와 뒤 노트에서는 응답 토큰만 채점하는 설정을 기본으로 삼는다. 지시 토큰은 손실에서 빠질 뿐 입력에서는 빠지지 않는다. 응답의 각 토큰은 앞선 지시 전체를 조건으로 예측된다.

<Callout type="example">
**대화 한 턴의 loss mask.** 아래는 교육용으로 단순화한 토큰열이다. 실제 tokenizer는 단어를 더 잘게 나누고 헤더도 여러 토큰이지만, 어느 위치가 채점되는지는 같다. 입력과 정답은 한 칸 어긋나 있다. BOS(beginning of sequence)와 EOT(end of turn)는 특수 토큰이다.

| 위치 | 입력 토큰 | 정답 토큰 | $m_i$ | 채점 여부 |
|---|---|---|---|---|
| 0 | BOS | `[user]` | 0 | 지시 부분 |
| 1 | `[user]` | 부산의 | 0 | 지시 부분 |
| 2 | 부산의 | 항구 | 0 | 지시 부분 |
| 3 | 항구 | 이름은? | 0 | 지시 부분 |
| 4 | 이름은? | EOT | 0 | 지시 부분 |
| 5 | EOT | `[assistant]` | 0 | 헤더 |
| 6 | `[assistant]` | 부산항 | 1 | 응답 |
| 7 | 부산항 | 입니다 | 1 | 응답 |
| 8 | 입니다 | . | 1 | 응답 |
| 9 | . | EOT | 1 | 응답의 끝 |

모델이 네 정답에 준 확률이 0.5, 0.8, 0.9, 0.6이었다고 하자. 토큰별 손실은 $-\log$ 값으로 0.693, 0.223, 0.105, 0.511이다. 채점하는 토큰이 4개이므로 $\mathcal{L}=(0.693+0.223+0.105+0.511)/4=0.383$이다. 위치 0–5의 예측은 계산되지만 손실에 들어가지 않는다. 마지막 EOT를 채점하는 이유는 모델이 "여기서 멈춘다"를 배워야 하기 때문이다. 이 토큰을 mask하면 응답을 끝내는 시점을 직접 학습하는 신호가 빠진다.
</Callout>

### 2-4. 배치 안의 평균

위 식의 분모 $\sum_i m_i$는 배치 전체의 유효 토큰 수여야 한다. 2주차에서 "손실의 합과 유효 정답 수를 각각 합친 뒤 나눈다"고 한 이유가 SFT에서 실제 문제가 되었다. 샘플마다 응답 길이가 크게 다르기 때문이다. 위 예의 4토큰 응답과 200토큰 응답을 한 배치에 넣었다고 하자. 샘플별로 평균한 뒤 두 값을 다시 평균하면 4토큰 응답의 토큰 하나가 200토큰 응답의 토큰 하나보다 50배 큰 가중치를 받는다. 배치 전체의 토큰 수로 한 번에 나누면 모든 토큰의 가중치가 같다. Gradient accumulation이나 여러 장치에 나눈 학습에서는 이 두 방식이 은연중에 뒤바뀌기 쉽다.

Tülu 3는 Transformers 라이브러리의 기본 손실 집계가 padding과 gradient accumulation을 고려하지 않아 다른 환경에서 학습한 모델과 성능 차이가 났다고 보고했다. 해결책은 평균 대신 <strong>합(sum loss)</strong>을 쓰는 것이었다. 분모를 없애면 모든 토큰이 같은 가중치를 받는 대신 learning rate를 그에 맞게 조정해야 하며, Tülu 3는 8B 모델에 sum loss와 learning rate $5\times10^{-6}$, 2 epoch를 최종 설정으로 택했다(70B는 $2\times10^{-6}$).[^tulu3] 손실을 어떻게 집계하는가는 구현 세부처럼 보이지만, 실제로는 **긴 응답과 짧은 응답 중 어느 쪽을 더 배울 것인가**를 정하는 선택이다.

### 2-5. 학습 설정

SFT는 pre-training보다 훨씬 작은 learning rate로, 데이터를 몇 번만 반복해서 돈다. Llama 3는 가장 큰 모델에 $10^{-5}$로 8.5K–9K 스텝을,[^llama] Olmo 3 Think 7B는 $5\times10^{-5}$로 2 epoch, 약 45B 토큰을 학습했다.[^olmo3] 45B 토큰은 같은 모델의 pre-training 5.9T 토큰의 1% 미만이다. 위 사례들의 epoch 수는 2이지만 예외가 있다. InstructGPT의 SFT는 16 epoch를 돌았는데, validation loss는 1 epoch 뒤부터 과적합했음에도 reward model 점수와 사람의 선호는 계속 좋아졌다.[^instructgpt] Validation loss가 낮아지는 것과 사람이 좋아하는 응답을 내는 것은 같은 축이 아니다. 이 어긋남은 §4의 평가와 [04d](/lecture/2026f-advanced-deep-learning/04d-reward-hacking/)의 주제로 이어진다.<Sidenote>어떤 파라미터를 갱신할지도 선택이다. 모든 가중치를 갱신하는 full fine-tuning 대신 LoRA처럼 작은 저차원 행렬만 학습하는 방법을 쓰면 optimizer 상태와 gradient의 메모리가 크게 줄고, 이는 [2주차 Training engineering 노트](/lecture/2026f-advanced-deep-learning/02e-training-engineering/)의 메모리 계산과 연결된다. 서베이 §III이 두 방식을 함께 정리한다.[^survey] 이 노트의 논의는 갱신 방식과 무관하게 성립한다.</Sidenote>

## 3. 지시 데이터의 계보

목적함수가 단순하므로 SFT의 발전은 주로 데이터에서 일어났다. 무엇을 지시로 삼고 누가 응답을 쓰는지가 바뀌어 왔다. 계보는 다음과 같다. 기존 NLP(natural language processing) 데이터셋을 지시문으로 감싼 방식(§3-1)은 열린 요청을 덮지 못했고, 사람이 응답을 직접 쓰는 방식(§3-2)은 그 문제를 풀었지만 비용이 컸다. 비용 문제에서 두 갈래가 나온다. 하나는 모델로 데이터를 생성해 양을 늘리는 방향(§3-3), 다른 하나는 소량을 엄격히 골라 품질을 높이는 방향(§3-4)이다. 최근의 recipe는 두 갈래를 능력별 혼합으로 합친다(§3-5).

### 3-1. FLAN과 T0의 과제 지시문

출발점은 이미 있는 NLP 데이터셋이다. 2021년 Google의 FLAN은 62개 데이터셋을 자연어 지시문 템플릿으로 감싸 137B 모델을 fine-tuning했다. 예를 들어 감성 분류 데이터셋은 "이 영화평은 긍정인가 부정인가?" 같은 지시문으로 바뀐다. 학습에 쓰지 않은 과제에서 zero-shot 성능이 base model보다 크게 올랐고, 25개 과제 중 20개에서 175B GPT-3의 zero-shot 성능을 넘었다.[^flan] 같은 시기 T0는 여러 사람이 쓴 다양한 프롬프트 템플릿으로 같은 접근을 encoder-decoder 모델에 적용했다.[^t0] 두 연구가 보인 것은 **지시문의 형식을 배우면 보지 않은 과제로도 일반화된다**는 점이다.

Google은 이어서 과제 수를 1,836개로 늘리고 CoT 데이터를 섞은 Flan-PaLM으로 규모의 효과를 쟀다.[^flan-palm] 모델 크기와 과제 수 모두에서 성능이 올랐고, 정규화 평균의 절대 증가량은 작은 모델에서 더 컸다. 수치는 §4-2에서 본다.

### 3-2. InstructGPT의 사람 시연

기존 데이터셋을 지시문으로 감싸면 과제가 분류·질의응답 같은 정형 과제에 치우친다. 사용자가 실제로 묻는 것은 "이메일을 정중하게 고쳐 줘" 같은 열린 요청이다. OpenAI의 InstructGPT는 API(application programming interface)에 들어온 프롬프트를 바탕으로 <strong>사람이 직접 쓴 응답(demonstration)</strong>을 모아 GPT-3를 SFT했다.[^instructgpt] 이 논문의 전체 파이프라인은 SFT, reward model, 강화학습의 세 단계이고 뒤의 두 단계는 [04b](/lecture/2026f-advanced-deep-learning/04b-rlhf/)에서 다룬다. 여기서 볼 것은 첫 단계의 효과다. 175B 모델의 사람 평가에서 SFT 모델의 출력은 few-shot 프롬프트를 준 GPT-3의 출력보다 선호되었고, 프롬프트만 준 GPT-3와 원래 GPT-3의 차이보다 SFT와 프롬프트만 준 GPT-3의 차이가 컸다(원논문 Figure 1).[^instructgpt] 논문의 대표 결과인 "1.3B 모델이 175B GPT-3보다 선호되었다"는 SFT가 아니라 RLHF까지 마친 모델의 결과이므로 여기서 SFT의 근거로 쓰지 않는다.

사람이 응답을 쓰는 방식의 문제는 비용이다. 응답을 하나하나 써야 하고, 다양한 주제를 고르게 덮으려면 많은 작성자가 필요하다.

### 3-3. Self-Instruct와 Alpaca의 합성 지시

첫째 갈래는 이 비용 문제를 모델로 푼다. Self-Instruct는 사람이 쓴 175개의 시드 과제에서 출발해, 모델이 새 지시문을 만들고 그 지시문에 대한 입력과 응답도 만든 뒤, 기존 것과 너무 비슷한 지시문을 걸러 내는 과정을 반복한다. 이렇게 만든 52K 지시 데이터로 GPT-3를 fine-tuning하자 Super-NaturalInstructions 평가에서 원래 모델보다 33%p 올랐고, 전문가가 새로 쓴 지시에 대한 사람 평가에서는 사람 데이터로 학습한 InstructGPT-001과의 차이가 5%p였다.[^self-instruct] Stanford의 Alpaca는 이 방법을 단순화한 파이프라인을 text-davinci-003으로 실행해 52K 시연을 500달러 미만으로 만들고 LLaMA 7B를 fine-tuning했다.[^alpaca]

모델이 만든 데이터에는 반대 방향의 문제가 있다. 지시문이 서로 비슷해지고 응답의 오류가 그대로 학습된다. 학생 모델이 teacher의 표면적 문체만 배우는 것 아니냐는 우려도 있는데, 이 문제는 [05f Distillation](/lecture/2026f-advanced-deep-learning/05f-distillation/)에서 다시 다룬다.

### 3-4. LIMA의 소량 고품질 데이터

둘째 갈래는 양을 늘리는 대신 고른다. Meta의 연구진은 Stack Exchange·wikiHow 등에서 고르고 일부는 직접 쓴 **1,000개**의 프롬프트·응답으로 65B LLaMA를 SFT했다. 사람 평가에서 LIMA의 응답은 GPT-4의 응답과 같거나 더 낫다고 판정된 비율이 43%였고, Bard에 대해서는 58%, DaVinci003에 대해서는 65%였다. 52K 예시로 학습한 Alpaca 65B보다도 선호되었다.[^lima] 저자들은 이 결과를 **superficial alignment hypothesis**로 설명한다. 모델의 지식과 능력은 거의 전부 pre-training에서 익히고, alignment는 pre-training에서 익힌 여러 응답 방식 중 사용자와 대화할 때 맞는 방식을 고르도록 유도할 뿐이라는 가설이다.[^lima] 같은 논문의 ablation은 프롬프트의 다양성과 응답의 품질을 높이면 성능이 오르지만, 같은 출처의 데이터를 양만 늘리면 성능이 정체한다고 보고한다.[^lima]

이 가설은 §4의 수치를 읽는 열쇠다. SFT 뒤 벤치마크 점수가 크게 오르더라도, 그것이 새 지식을 배운 결과인지 이미 있는 능력을 답 형식으로 꺼내게 된 결과인지 구분해야 한다. 다만 LIMA의 평가는 대화 품질에 대한 사람의 선호였다. 수학이나 코드처럼 정답이 있는 과제에서 소량 SFT가 얼마나 통하는지는 이 논문이 답하지 않는다.

### 3-5. Tülu 3와 Olmo 3의 능력별 혼합

2024년 이후의 공개 recipe는 두 갈래를 합친다. 사람이 쓴 데이터, 기존 과제, 모델이 만든 데이터를 **능력별로 나누어** 섞고, 각 부분이 어느 벤치마크를 올리는지 ablation으로 확인한다. Tülu 3의 SFT 프롬프트 939,344개는 다음과 같이 구성된다(원논문 Table 7의 전체 항목).[^tulu3]

| 범주 | 데이터와 프롬프트 수 |
|---|---|
| 일반 대화 | WildChat(GPT-4 부분집합) 100,000, OpenAssistant 7,132, No Robots 9,500, Tülu 3 Hardcoded 240 |
| 지식 회상 | FLAN v2 89,982, SciRIFF 10,000, TableGPT 5,000 |
| 수학·추론 | Persona MATH 149,960, Persona GSM 49,980, Persona Algebra 20,000, OpenMathInstruct 2 50,000, NuminaMath-TIR 64,312 |
| 코딩 | Evol CodeAlpaca 107,276, Persona Python 34,999 |
| 안전 | CoCoNot 10,983, WildJailbreak 50,000, WildGuardMix 50,000 |
| 다국어 | Aya 100,000 |
| 정밀한 지시 따르기 | Persona IF 29,980 |

"Persona"가 붙은 데이터는 Persona Hub의 방식으로 만든 합성 데이터다. 웹에서 추출한 10억 개의 인물 설명(persona)을 프롬프트에 넣어 같은 과제라도 서로 다른 관점의 문제를 생성하게 하는 방법으로, §3-3에서 본 합성 데이터의 다양성 문제를 겨냥한다.[^persona] WildChat은 실제 사용자와 챗봇의 대화 기록이며 Tülu 3는 그중 GPT-4가 응답한 부분집합을 쓰고, FLAN v2는 §3-1의 계보를 잇는 정형 과제 모음이다.

데이터 범주와 능력의 대응은 Olmo 3의 SFT ablation에서 볼 수 있다. 내부의 OLMo 2 long-context checkpoint에 기본 혼합만 SFT한 경우와 거기에 범주 하나를 더한 경우를 비교한 실험이다(원논문 Table 18).[^olmo3] 정밀한 지시 따르기 데이터(Persona IF)를 더하자 IFEval이 35.7에서 70.4로 올랐고 MMLU도 52.4에서 64.1로 올랐지만, 코드 벤치마크 CHE는 35.4에서 25.0으로 내려갔다. 데이터 범주를 더하면 겨냥한 능력이 오르지만 다른 능력과 상충할 수 있으므로, 최종 혼합은 이런 ablation을 여러 범주에 대해 돌린 뒤 정한다. Olmo 3 Think의 SFT 데이터는 약 227만 개 프롬프트로 Tülu 3의 두 배가 넘는데, 대부분이 수학·코드 문제에 대한 긴 사고 과정 응답이다(원논문 Table 17).[^olmo3] 응답의 길이가 수천 토큰이라 7B 모델의 SFT를 2 epoch 돌리면 45B 토큰을 학습한다. 이 "사고 과정을 담은 SFT"는 §5-3에서 다시 본다.

## 4. SFT의 효과와 단계별 비교

### 4-1. 평가 지표와 조건

수치를 보기 전에 벤치마크가 무엇을 재는지 정리한다. 뒤 노트에서도 같은 벤치마크가 반복해서 나온다.

| 벤치마크 | 재는 것 | 채점 방식 |
|---|---|---|
| MMLU[^mmlu] | 57개 과목의 객관식 지식 | 정답 선택지 일치. 예시 수(0-shot, 5-shot)와 CoT 여부에 따라 값이 달라진다 |
| BBH | BIG-Bench에서 고른 어려운 추론 과제 23개 | 정답 일치. Direct는 답만, CoT는 풀이를 쓰게 한 뒤 답을 채점 |
| MGSM | GSM8K 문제를 10개 언어로 번역한 다국어 수학 | 최종 숫자 답의 일치 |
| IFEval[^ifeval] | "300단어 이하로", "쉼표를 쓰지 말 것" 같은 검증 가능한 지시 25종 | 프로그램으로 조건 충족 여부를 판정. 원논문은 strict·loose와 prompt·instruction 단위의 네 지표를 두며, 아래 Tülu 3 표의 prompt loose는 프롬프트의 모든 지시를 충족했는지를 표현 차이에 관대하게 판정한 비율이다 |
| GSM8K[^gsm8k] | 초등 수준 수학 문장제 | 최종 숫자 답의 일치 |
| MATH[^math] | 경시 수준 수학 | 최종 답의 일치 |
| AlpacaEval 2 LC[^alpacaeval-lc] | 열린 지시에 대한 생성 응답의 품질 | GPT-4 계열 judge가 기준 모델 응답과 비교해 승률을 매기고, 응답 길이의 효과를 회귀로 보정(length-controlled, LC) |
| ToxiGen | 유해 발화를 유도하는 프롬프트 | 생성 응답 중 유해하다고 분류된 비율. 낮을수록 좋다 |
| TruthfulQA | 흔한 오해를 유도하는 질문 | 사실에 맞는 답의 비율 |

같은 이름이라도 shot 수, CoT 여부, 답 추출 규칙이 다르면 값을 비교할 수 없다. 아래 표들은 각각 원논문의 한 표 안에서 조건을 맞춘 비교이며, 표 사이의 값은 비교하지 않는다.

### 4-2. Base model과 SFT model의 비교

**Flan-PaLM.** 같은 PaLM 모델을 1,836개 과제로 SFT하기 전후의 점수다(원논문 Table 3). 평가는 MMLU 5-shot, BBH 3-shot, MGSM 8-shot CoT의 few-shot exact match이고, Norm. avg.는 MMLU·BBH의 Direct·CoT, TyDiQA, MGSM 여섯 점수를 무작위 추측 같은 과제별 하한을 기준으로 정규화한 뒤 평균한 값이다.[^flan-palm]

| 모델 | 조건 | MMLU-Direct | BBH-Direct | MGSM | Norm. avg. |
|---|---|---|---|---|---|
| PaLM 8B | Fine-tuning 없음 | 24.3 | 30.8 | 3.4 | 6.4 |
| PaLM 8B | 1,836 과제 SFT | 49.3 | 36.4 | 8.2 | 21.9 |
| PaLM 62B | Fine-tuning 없음 | 55.1 | 37.4 | 18.2 | 28.4 |
| PaLM 62B | 1,836 과제 SFT | 59.6 | 47.5 | 28.5 | 38.8 |
| PaLM 540B | Fine-tuning 없음 | 71.3 | 49.1 | 45.9 | 49.1 |
| PaLM 540B | 1,836 과제 SFT | 73.2 | 58.8 | 61.3 | 58.5 |

8B에서 MMLU가 24.3에서 49.3으로 두 배가 되었다. 24.3은 4지선다의 무작위 추측(25)과 같은 수준이다. 이 표만으로 그 원인을 가를 수는 없지만, 8B base model이 57개 과목의 지식을 전혀 갖지 못했다기보다 객관식 형식으로 답을 내는 법을 몰랐다고 읽는 편이 §3-4의 가설과 맞는다. 540B에서는 MMLU 상승이 2점 미만인데 다국어 수학(MGSM)은 45.9에서 61.3으로 올랐다. 이 상승은 fine-tuning 데이터 전체를 바꾼 결과이므로, CoT 데이터가 얼마나 기여했는지는 원논문 §4가 CoT 데이터를 넣은 경우와 뺀 경우를 따로 비교한 실험에서 봐야 한다.[^flan-palm]

**OLMo.** Allen AI의 OLMo 7B를 Tülu 2의 SFT 데이터로 SFT하고 이어서 UltraFeedback으로 DPO를 적용한 결과다(원논문 Table 4. 부록 Table 8은 +SFT+DPO의 MMLU를 46.1로 적고 있어 원논문 안에서 0.1 차이가 있다).[^olmo] MMLU는 0-shot 조건이다.

| 모델 | MMLU 0-shot | AlpacaEval | ToxiGen (낮을수록 좋음) | TruthfulQA |
|---|---|---|---|---|
| OLMo 7B (base) | 28.3 | – | 81.4 | 31.6 |
| +SFT | 47.3 | 57.0 | 14.4 | 41.2 |
| +SFT +DPO | 46.2 | 69.3 | 1.7 | 52.0 |

SFT 한 단계로 MMLU 0-shot이 19점, 유해 발화 비율이 81.4%에서 14.4%로 바뀌었다. 그 뒤의 DPO는 MMLU를 오히려 1.1점 내리고 AlpacaEval과 TruthfulQA를 올렸다. 단계마다 모든 지표가 함께 오르지는 않는다.

### 4-3. SFT 뒤의 단계가 더하는 것

SFT의 효과를 보는 다른 방법은 뒤 단계와 비교하는 것이다. Tülu 3 8B의 세 checkpoint와 같은 base model에서 출발한 Llama 3.1 8B Instruct를 나란히 놓으면 다음과 같다(원논문 Table 6). 평균은 원논문 전체 평가 항목의 평균이고, 아래 행은 그중 일부다.[^tulu3]

| 벤치마크 | Tülu 3 8B SFT | +DPO | +RLVR (최종) | Llama 3.1 8B Instruct |
|---|---|---|---|---|
| 평균 (전체 항목) | 60.6 | 64.7 | 65.1 | 62.9 |
| MMLU (0-shot, CoT) | 65.9 | 68.7 | 68.2 | 71.2 |
| IFEval (prompt loose) | 72.8 | 81.1 | 82.4 | 80.6 |
| GSM8K (8-shot, CoT) | 76.2 | 84.3 | 87.6 | 83.4 |
| MATH (4-shot, CoT) | 31.5 | 42.0 | 43.7 | 42.5 |
| AlpacaEval 2 (LC 승률) | 12.4 | 33.5 | 34.5 | 24.2 |
| 안전 (6개 과제 평균) | 93.1 | 87.2 | 85.5 | 75.2 |

SFT 단계는 이미 안전 점수가 가장 높고 IFEval도 72.8에 이르지만, AlpacaEval 승률은 12.4로 DPO 뒤의 33.5와 차이가 크다. 이 recipe에서는 열린 대화 응답의 선호 승률이 시연 모방보다 선호 학습에서 크게 올랐다. 수학(GSM8K, MATH)은 DPO에서 크게 오르고 RLVR에서 더 오른다. Olmo 3 Think 7B의 최종 checkpoint들에서도 IFEval은 SFT 77.9, DPO 75.9, RLVR 88.2로 단계마다 오르내렸고(원논문 Table 24), SFT 뒤에 RLVR을 1,000 스텝만 돌린 ablation에서는 DPO를 거친 뒤 RLVR을 한 쪽의 평균이 가장 높았다(원논문 Table 22).[^olmo3]

정리하면 이 recipe들에서 SFT는 base model을 지시에 답하는 모델로 바꾸고, 뒤 단계는 그 위에서 선호 승률과 수학 점수를 더 올린다. 남은 간격이 무엇인지 보자.

## 5. SFT의 한계와 남는 역할

### 5-1. 시연 데이터의 감독 범위

일반적인 SFT 데이터는 프롬프트마다 선택된 응답을 준다. 같은 프롬프트에 응답 여러 개를 둘 수는 있지만, 어느 응답이 다른 응답보다 얼마나 나은지를 직접 감독하지는 않는다. 모델은 시연에 높은 확률을 주도록 배우고 그 과정에서 다른 응답의 확률도 바뀌지만, 시연보다 조금 나쁜 응답과 훨씬 나쁜 응답을 구분하라는 신호는 없다. 예를 들어 같은 질문에 대한 두 응답 중 하나가 정확하지만 무뚝뚝하고 다른 하나가 친절하지만 틀렸을 때, 사람이 원하는 순서를 배우려면 두 응답을 **비교**한 데이터가 필요하다. 이것이 [04b RLHF](/lecture/2026f-advanced-deep-learning/04b-rlhf/)의 출발점이다.

### 5-2. 학습 문맥과 생성 문맥의 차이

SFT는 teacher forcing으로 학습한다. 응답의 각 토큰을 예측할 때 조건이 되는 앞부분은 모델이 생성한 것이 아니라 데이터에 적힌 시연이다. 추론 때는 모델이 자기 출력을 조건으로 다음 토큰을 만들므로, 한 번 시연과 다른 방향으로 가면 학습 때 보지 못한 문맥에 놓일 수 있다. 시연을 쓴 사람이나 모델의 문체와 현재 모델의 문체가 다를수록 이 차이는 커진다.

이 차이를 뒤 노트에서는 **어느 정책이 학습 데이터를 생성했는가**로 정리한다. 학습되는 모델과 다른 정책(사람, 다른 모델, 자신의 과거 checkpoint)이 만든 데이터로 학습하면 off-policy, 지금 학습 중인 정책이 방금 생성한 데이터로 학습하면 on-policy다. 시연 데이터의 SFT는 off-policy의 대표적인 경우다. 정의와 그 결과는 [04c DPO](/lecture/2026f-advanced-deep-learning/04c-dpo/)에서 다루고, [05f Distillation](/lecture/2026f-advanced-deep-learning/05f-distillation/)에서 이 문제를 직접 겨냥한 방법을 본다.

### 5-3. 사고 과정을 담은 SFT의 자리

이 한계에도 SFT의 자리는 남는다. 추론 모델의 recipe에서 SFT는 RL 전에 모델에 **긴 사고 과정의 형식**을 가르치는 cold start 역할을 맡는다. Qwen3는 검증 가능한 수학·코드 문제를 골라 QwQ-32B가 생성한 사고 과정 응답을 걸러 첫 단계 SFT 데이터로 썼고,[^qwen3] Olmo 3 Think의 SFT 데이터는 §3-5에서 본 것처럼 대부분 그런 응답이다. 흥미로운 결과는 사고 과정을 쓰지 않는 Instruct 모델에서도 나온다. Olmo 3 Instruct 7B의 중간 checkpoint를 사고 과정 SFT를 먼저 거친 뒤 학습하자, 거치지 않은 경우보다 평균 3.3점, MATH에서 5.6점 높았다(원논문 Table 29).[^olmo3] 최종 모델이 사고 과정을 출력하지 않아도, 그것을 한 번 배운 가중치가 더 좋은 출발점이 된다는 관찰이다.

다만 SFT 뒤에 무엇을 거치는가도 최종 성능을 바꾼다. Olmo 3는 SFT 뒤에 바로 RLVR을 한 경우(평균 71.9)보다 DPO를 거친 뒤 RLVR을 한 경우(74.1)가 높았다(원논문 Table 22).[^olmo3] SFT는 뒤 단계의 **초기화**이고, 초기화의 좋고 나쁨은 뒤 단계를 돌려 봐야 안다. 이 관점은 [05a RLVR](/lecture/2026f-advanced-deep-learning/05a-rlvr/)에서 DeepSeek-R1의 cold start를 볼 때 다시 쓴다.
