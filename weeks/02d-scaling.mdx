**모델을 더 크게 만들고, 더 많은 데이터와 계산량을 사용하면 성능도 계속 좋아질까? 얼마나 더 좋아질지 미리 알 수 있을까?** 규모와 성능 사이의 관계를 살펴본다.[^survey] 먼저 규모를 키울 때 loss가 줄어드는 경향을 보고, 그 관계를 이용한 계산 예산 배분으로 넘어간다.

## 1. Scaling laws

어떤 모델을 학습해 성능을 측정했다고 하자. 모델 크기를 두 배로 늘리면 얼마나 나아질까? 학습 데이터를 두 배로 늘리면 어떨까? 계산량을 열 배 투입할 가치가 있을까? 작은 규모에서 얻은 개선이 더 큰 규모에서도 이어지는지, 아니면 어느 지점부터 다른 제약에 막히는지가 궁금해진다.

Scaling law는 이런 질문에 답하기 위해 **모델·데이터·계산 규모와 성능 사이의 관계를 실험으로 측정하고 수식으로 표현**한다. 이 노트에서는 먼저 성능을 평가 데이터의 평균 next-token prediction loss로 측정한다. Loss가 얼마나 줄어드는지와, 질의응답·추론 같은 개별 과제의 점수가 얼마나 오르는지는 구분해서 살펴봐야 한다.

작은 실험에서 얻은 관계가 더 큰 실험에서도 맞는다면, 아직 실행하지 않은 규모의 성능을 예측할 근거가 생긴다. 여기서 law는 주어진 실험 조건에서 관찰하고 맞춘 경험적 관계다. 규모를 무한히 키우면 성능도 계속 좋아진다는 보장이나, 데이터 분포와 모델 구조가 바뀌어도 같은 계수가 유지된다는 자연법칙은 아니다.

### 1-1. 모델·데이터·계산량

| 기호 | 뜻 |
|---|---|
| $N$ | 모델의 파라미터 수 |
| $D$ | 학습 중 소비한 토큰 수 |
| $C$ | 학습에 사용한 총 계산량 |
| $\mathcal{L}$ | 평가 데이터에서 계산한 평균 next-token prediction loss |

$N$은 가중치 행렬의 각 원소처럼 학습으로 조정하는 수의 개수다. 예를 들어 $4\times3$ 가중치 행렬에는 파라미터가 12개 있다. 모델 전체에서 이런 파라미터를 합한 값으로 모델 크기를 나타낸다.

$D$는 고유한 텍스트 양과 같지 않을 수 있다. 같은 데이터를 반복해서 읽어도 소비한 토큰 수는 늘어난다. 또한 tokenizer가 바뀌면 같은 문서의 토큰 수가 달라지므로 서로 다른 실험의 $D$를 해석할 때 조건을 확인해야 한다.

$C$는 학습 중 수행하는 부동소수점 덧셈·곱셈 등의 연산을 세어 나타낸다. 이 연산 횟수를 FLOPs(floating-point operations)라고 하며, 곱셈 한 번과 덧셈 한 번을 수행하면 2 FLOPs로 센다.<Sidenote>FLOP/s 또는 FLOPS(floating-point operations per second)는 초당 연산 처리량이다. 같은 연산량도 하드웨어·통신·활용률에 따라 걸리는 시간이 달라진다.</Sidenote>

Loss를 비교할 때는 tokenizer·평가 텍스트·제공 문맥·채점 위치를 맞춘다. 아래에서는 이러한 조건과 모델 계열을 고정하고 $N,D$를 바꾼다고 생각하자.

Dense Transformer의 학습 FLOPs를 대략적으로 추산할 때 다음 근사(approximation)를 사용한다.[^chinchilla]

$$
C\approx6ND
$$

이 식은 주요 가중치 행렬의 곱셈을 중심으로 한 근사다. 긴 시퀀스의 attention 계산, embedding 취급, activation 재계산 등까지 정확히 포함한 실행 비용은 아니다. 여기서 dense는 각 토큰이 각 층의 주요 가중치 행렬을 모두 사용하는 구조를 뜻한다. MoE(mixture of experts)처럼 토큰마다 일부 expert만 선택하는 구조에서는 전체 파라미터 수를 그대로 $N$에 넣을 수 없다.

**한 토큰에 대해 계산해 보자.** 계수 6은 행렬곱의 forward와 backward 비용에서 나온다. 한 선형층에서 토큰 벡터 $x\in\mathbb R^{1\times d_{\mathrm{in}}}$에 가중치 $W\in\mathbb R^{d_{\mathrm{in}}\times d_{\mathrm{out}}}$를 곱해 $y=xW$를 만든다고 하자. 이 행렬의 파라미터 수는 $N_W=d_{\mathrm{in}}d_{\mathrm{out}}$다.

<Figure src={linearLayer.src} alt="왼쪽 입력 x의 성분 4개와 오른쪽 출력 y의 성분 3개를 가중치 12개가 모두 연결한다. 강조된 w21은 x2와 y1을 잇는다. Forward는 오른쪽으로 계산하고, 입력 gradient는 출력 gradient로부터 왼쪽으로 전달한다." caption="각 원은 한 토큰 벡터의 성분이고, 연결선 하나는 W의 원소 하나다. ℓ은 학습 loss다. 강조한 연결의 gradient 기여는 입력 x₂와 출력 y₁에 대한 loss의 편미분을 곱해 구한다." source="본문의 선형층 y=xW를 직접 도식화. 입력 4차원, 출력 3차원, bias 생략." />

출력 성분 하나를 계산하려면 곱셈 $d_{\mathrm{in}}$번과 덧셈 $d_{\mathrm{in}}-1$번이 필요하다. 따라서 bias를 더하지 않는 $y=xW$에서는 출력 성분 하나당 정확히 $2d_{\mathrm{in}}-1$ FLOPs이고, 전체 출력의 forward 비용은 $d_{\mathrm{out}}(2d_{\mathrm{in}}-1)$ FLOPs다. $d_{\mathrm{in}}$이 크면 $2d_{\mathrm{in}}$에 비해 1이 작으므로, 이를 $2d_{\mathrm{in}}d_{\mathrm{out}}=2N_W$로 근사한다.

<Figure src={chainRule.src} alt="CS231n의 f=(x+y)z 계산 그래프. 덧셈 노드와 곱셈 노드에 초록색 forward 값과 빨간색 gradient가 표시되어 있다." caption="초록색은 forward 값, 빨간색은 최종 출력 f에 대한 각 변수의 gradient다. 이 예제의 x, y, z는 모두 스칼라다." source="Andrej Karpathy · Stanford CS231n, Backpropagation · MIT License · 원본 SVG 발췌, 배경·여백 조정. 숫자·색상·연결 구조 유지." />

[그림 원문](https://cs231n.github.io/optimization-2/#backprop) · [MIT 라이선스](https://github.com/cs231n/cs231n.github.io/blob/master/LICENSE)

그림에서는 $q=x+y$, $f=qz$다. 오른쪽에서 $\frac{\partial f}{\partial q}=z=-4$를 구한 뒤, 덧셈 노드의 $\frac{\partial q}{\partial x}=1$을 곱하면 $\frac{\partial f}{\partial x}=-4$가 된다. 각 연산에서 전달받은 gradient에 그 연산의 미분을 곱하는 것이 chain rule이다. 같은 원리를 선형층의 입력과 가중치에 적용해 보자.

Backward에서는 **출력 $y$가 loss에 미치는 영향**을 출발점으로, **입력 $x$와 가중치 $W$가 loss에 미치는 영향**을 각각 계산한다. 학습 loss를 $\ell$이라고 쓰면, 이후 층에서 전달받는 값은 $\frac{\partial\ell}{\partial y}$다. 출력 $y$의 각 성분이 조금 바뀔 때 loss가 어느 방향으로 얼마나 변하는지를 나타낸다.

먼저 입력 $x$에 대한 gradient $\frac{\partial\ell}{\partial x}$를 구한다. 출력은 $y=xW$이므로, 입력 $x$의 변화가 출력 $y$에 미치는 영향은 가중치 $W$로 정해진다. 여기에 출력 $y$가 loss에 미치는 영향을 chain rule로 연결하면 다음과 같다.

$$
\frac{\partial\ell}{\partial x}
=\frac{\partial\ell}{\partial y}W^\top
$$

이 값은 앞선 층으로 전달해 역전파를 이어 가는 데 사용한다. $\frac{\partial\ell}{\partial y}$와 $W^\top$의 행렬곱 비용은 forward와 마찬가지로 약 $2N_W$ FLOPs다.

다음으로 가중치 $W$에 대한 gradient $\frac{\partial\ell}{\partial W}$를 구한다. 가중치 $W$의 변화가 출력 $y$에 미치는 영향은 입력 $x$로 정해지므로, 입력 $x$와 출력에 대한 gradient $\frac{\partial\ell}{\partial y}$를 이용한다. 이 토큰이 가중치 gradient에 기여하는 값은 다음과 같다.

$$
x^\top\frac{\partial\ell}{\partial y}
$$

각 가중치마다 입력 성분과 출력에 대한 편미분 값을 한 번 곱하고, 여러 토큰에서 얻은 기여를 누적해 $\frac{\partial\ell}{\partial W}$를 구한다. 곱셈과 누적 덧셈을 함께 세면 토큰당 약 $2N_W$ FLOPs다. 이렇게 모은 가중치 gradient는 $W$를 업데이트하는 데 사용한다.

따라서 한 토큰에 대한 이 층의 비용은 forward $2N_W$, 입력 $x$의 gradient 계산 $2N_W$, 가중치 $W$의 gradient 계산과 누적 $2N_W$를 합쳐 약 $6N_W$다. 이를 모델의 주요 가중치 행렬 전체에 합하면 토큰당 약 $6N$이고, 학습 중 소비하는 전체 $D$개 토큰에 걸쳐 합산하면 **학습 FLOPs는 $C\approx6ND$**가 된다.

| 계산 | 의미 | 토큰당 근사 FLOPs |
|---|---|---|
| Forward: 출력 계산 | 입력 $x$에 가중치 $W$를 곱해 출력 $y$ 계산 | $2N_W$ |
| Backward: 입력 gradient | 학습 loss를 이 층의 입력 $x$로 미분한 값. 앞선 층으로 전달해 역전파를 이어 간다. | $2N_W$ |
| Backward: 가중치 gradient | 학습 loss를 가중치 $W$로 미분한 값. 가중치 업데이트에 사용한다. | $2N_W$ |
| 합계 | 한 토큰의 forward와 backward | $6N_W$ |

여기서 입력 $x$는 embedding이나 앞선 층에서 전달받은 연속적인 벡터다.

<Callout type="example">
입력 4차원, 출력 3차원의 작은 선형층은 가중치가 12개다. 출력 세 개를 구할 때 각각 4번 곱하고 3번 더하므로 정확한 forward 연산 수는 21회다. 큰 행렬에서는 덧셈 횟수를 곱셈 횟수와 같게 근사해 $2\times12=24$회로 센다. 같은 방식으로 backward까지 약 72회로 잡는다. 이 계산을 모델의 주요 가중치 행렬에 합산하고, 소비한 $D$개 토큰에 걸쳐 누적한 값이 $6ND$다.
</Callout>

### 1-2. Power law와 loss

Power law는 규모를 일정 배수로 늘릴 때 어떤 양이 일정 비율로 변하는 관계다. 예를 들어 모델 크기 $N$에 따른 loss 감소 항이 $N^{-0.5}$에 비례한다면, $N$을 네 배로 늘릴 때 그 항은 절반이 된다.

학습 데이터 조건을 고정하고, 모델 크기만 늘리는 교육용 모형을 생각하자. $N_{\mathrm B}$는 billion 단위의 파라미터 수다.

$$
\widehat{\mathcal L}=2+N_{\mathrm B}^{-0.5}
$$

모델을 1B→4B→16B로 키우면 loss는 3→2.5→2.25가 된다. 바닥 2를 뺀 감소 항은 1→0.5→0.25로 줄어든다. 규모를 같은 배수로 늘려도 얻는 절대 loss 감소는 점점 작아진다.

이 관계는 로그 축에서 읽기 쉽다. 일반적으로 $\widehat{\mathcal L}=F+AN^{-\alpha}$라면

$$
\log(\widehat{\mathcal L}-F)=\log A-\alpha\log N
$$

이다. 가로축과 세로축을 각각 $\log N$, $\log(\widehat{\mathcal L}-F)$로 놓으면 기울기 $-\alpha$의 직선이 된다. 전체 loss에는 바닥 항 $F$가 남으므로, 직선 관계를 보려면 이 항을 빼고 읽는다.

### 1-3. 실험에 맞춘 loss 모형

먼저 여러 크기의 모델을 여러 학습 토큰 수로 훈련하고, 각 실험의 $(N,D,\mathcal L)$을 기록한다. 이 점들에서 규모가 커질수록 loss가 어떻게 줄어드는지 관찰한 뒤, 그 경향을 설명할 수식을 정하고 계수를 추정한다. 이렇게 관측값에 수식을 맞추는 과정을 **fitting**이라고 한다. 추정에 사용하지 않은 실험에서도 맞는지 확인해야 큰 규모의 예측에 쓸 근거가 생긴다.

**Kaplan et al. (2020).** 충분한 데이터로 수렴시킨 모델에서는 $\mathcal L(N)\propto N^{-\alpha_N}$, 충분히 큰 모델을 제한된 데이터로 학습하고 평가 loss에 따라 조기 종료한 경우에는 $\mathcal L(D)\propto D^{-\alpha_D}$를 관찰했다. 한 자원의 영향을 볼 때 다른 자원이 병목이 되지 않도록 한 실험이다.[^kaplan]

두 제약을 함께 표현한 원논문의 식 (1.5)는 다음과 같다. 여기서만 $D_{\mathrm{set}}$으로 표기를 바꾸어 **데이터셋 크기**임을 드러낸다.

$$
\widehat{\mathcal L}_{\mathrm K}(N,D_{\mathrm{set}})
=\left[\left(\frac{N_c}{N}\right)^{\frac{\alpha_N}{\alpha_D}}
+\frac{D_c}{D_{\mathrm{set}}}\right]^{\alpha_D}
$$

$N_c,D_c$는 척도 상수다. 데이터셋이 충분히 크면 모델 크기에 따른 $(N_c/N)^{\alpha_N}$ 항이, 모델이 충분히 크면 데이터셋 크기에 따른 $(D_c/D_{\mathrm{set}})^{\alpha_D}$ 항이 남는다. Kaplan의 $N$은 embedding을 제외한 파라미터 수다. 원논문 Table 2의 공동 fitting은 $\alpha_N=0.076$, $\alpha_D=0.103$을 보고한다.[^kaplan]

**Hoffmann et al. (2022), Chinchilla.** 모델 크기와 **학습 토큰 수**를 함께 바꾼 실험에 다음 가산 모형을 맞춘다. 이는 Kaplan의 괄호 전체에 지수를 취한 식과 다른 함수다.[^chinchilla]

$$
\widehat{\mathcal{L}}(N,D)=E+\frac{A}{N^\alpha}+\frac{B}{D^\beta}
$$

$A,B,\alpha,\beta$는 실험에 맞춰 추정하는 양수다. $E$는 모델과 데이터를 함께 늘릴 때 이 모형이 예측하는 점근적 loss다. $D$를 고정하면 $F=E+B/D^\beta$가 되어 앞 절의 power law와 연결된다. 앞 그림은 $N,D$를 billion 단위로 넣고 $E=A=B=1$, $\alpha=\beta=0.5$, $D=1$로 놓은 예제에 해당한다.

$N$을 늘리면 첫 번째 감소 항이 작아지고, $D$를 늘리면 두 번째 감소 항이 작아진다. 둘 중 하나만 키우면 다른 항이 남는다. 예산이 고정되어 있다면 둘을 마음대로 동시에 늘릴 수 없으므로 낮은 loss를 주는 조합을 찾아야 한다.

## 2. Compute-optimal training

규모와 loss의 관계를 알면 다음 질문으로 이어진다. **같은 계산 예산에서 가장 낮은 loss를 얻으려면 모델 크기와 학습 토큰 수를 어떻게 배분해야 할까?** 모델을 키우는 것과 더 오래 학습하는 것 사이의 선택이다.

### 2-1. 같은 계산량에서의 비교

$C=6\times10^{18}$ FLOPs를 배정한 가상 실험을 생각하자.

| 후보 | 모델 크기 $N$ | 학습 토큰 수 $D$ | 근사 계산량 $6ND$ |
|---|---|---|---|
| A | 0.5B | 2B | $6\times10^{18}$ |
| B | 1B | 1B | $6\times10^{18}$ |
| C | 2B | 0.5B | $6\times10^{18}$ |

계산량은 같지만 어느 후보의 loss가 낮은지는 이 표만으로 알 수 없다. 앞에서 얻은 loss 모형을 이용해 후보를 비교해 보자. 이것이 isoFLOP, 즉 같은 계산량 안에서의 비교다.

<Callout type="example">
교육용으로 $E=1$, $A=B=1$, $\alpha=\beta=0.5$라고 두고 $N,D$를 각각 billion 단위로 넣자. 앞 표의 A는 $1+1/\sqrt{0.5}+1/\sqrt{2}\approx3.121$, B는 3.000, C는 3.121이다. 이 가상 계수에서는 균형 잡힌 B가 낮다. 실제 모델의 loss나 최적 비율을 보고한 수치는 아니다.
</Callout>

<Figure src={isoFlop.src} alt="고정 예산에서 가상 loss가 모델 크기 1B에서 최소가 되는 U자 곡선. 모델이 작으면 모델 항이, 크면 부족한 데이터 항이 loss를 높인다." caption="같은 계산량의 A·B·C를 곡선 위에서 비교한다. 가로축은 로그 척도이고, 오른쪽으로 갈수록 데이터량은 줄어든다." source="이 노트의 가상 수식으로 직접 계산. N과 D는 billion 단위, ND=1." />

<Details summary="Hoffmann 모형에서 고정 예산의 최적 N과 D 유도">

여기서는 $C\approx6ND$를 제약식 $C=6ND$로 놓는다. $N,D$는 실제 개수 단위다. 그림처럼 billion 단위를 쓰면 $C=6\times10^{18}N_{\mathrm B}D_{\mathrm B}$로 바꾸고, loss 식의 계수도 그 단위에 맞춰야 한다. $D=C/(6N)$을 대입하면

$$
\widehat{\mathcal{L}}(N)=E+AN^{-\alpha}+B(6N/C)^\beta
$$

이다. $N$에 대해 미분해 0으로 놓으면

$$
\alpha AN^{-\alpha}=\beta B(6N/C)^\beta
$$

를 얻는다. 따라서 최적점은 두 loss 항이 같은 곳이 아니라 **지수를 곱한 두 항이 같은 곳**이다. $\alpha=\beta$일 때에만 두 항이 같다. 정리하면

$$
N_*=G(C/6)^a,\qquad D_*=G^{-1}(C/6)^b
$$

$$
G=\left(\frac{\alpha A}{\beta B}\right)^{1/(\alpha+\beta)},\qquad
a=\frac{\beta}{\alpha+\beta},\qquad b=\frac{\alpha}{\alpha+\beta}
$$

이다. $a+b=1$이므로 $6N_*D_*=C$를 만족한다. 두 감소 지수가 같으면 $a=b=1/2$가 되어, 예산을 네 배 늘릴 때 모델 크기와 토큰 수를 각각 두 배 늘린다. 양수인 두 항이 $\log N$에 대해 엄밀히 볼록하므로 위 정지점은 유일한 최솟값이다.

</Details>

### 2-2. Chinchilla

Chinchilla는 “더 큰 모델”만 비교하는 대신, 같은 계산량에서 모델 크기와 학습 토큰 수를 함께 바꾸었다. 대표 비교에서 Gopher는 280B 파라미터와 300B 토큰, Chinchilla는 70B 파라미터와 1.4T 토큰을 사용했다. Chinchilla는 비슷한 학습 계산 예산에서 여러 평가를 개선했다.[^chinchilla]

이 수치에 $6ND$를 적용하면 각각 약 $5.04\times10^{23}$, $5.88\times10^{23}$ FLOPs다. 논문은 attention 등 모델 구조에 따른 연산을 포함한 Appendix F의 계산법을 사용한다. $6ND$는 규모별 비용을 빠르게 비교하는 근사이므로, 이 값만으로 두 실행의 정확한 계산량을 맞추지는 않는다.[^chinchilla]

이 비교가 주는 질문은 “내 모델이 너무 작은가?”에 더해 <strong>“내 모델 크기에 비해 충분히 학습했는가?”</strong>다. 해당 연구의 결론을 흔히 약 20 tokens/parameter로 요약하지만, 모든 데이터·모델·예산의 보편적인 비율로 적용할 수는 없다.

먼저 두 논문의 예산 배분 결과를 구별하자. 아래는 Hoffmann 논문의 Table 2에 정리된 $N_*\propto C^a$, $D_*\propto C^b$의 지수다.[^chinchilla]

| 연구·추정 방법 | 모델 크기 지수 $a$ | 토큰 수 지수 $b$ |
|---|---|---|
| Kaplan (2020): 계산 효율적인 학습 경계 | 0.73 | 0.27 |
| Hoffmann (2022): 학습 곡선들의 최저 경계 | 0.50 | 0.50 |
| Hoffmann (2022): isoFLOP 곡선의 최저점 | 0.49 | 0.51 |
| Hoffmann (2022): 가산 loss 모형 fitting | 0.46 | 0.54 |

Kaplan은 학습 도중의 loss와 batch size·학습 step을 함께 분석하고, batch size 효율을 보정한 계산량 $C_{\min}$으로 예산 배분을 추정했다.[^kaplan]

Hoffmann의 첫 방법은 여러 학습 곡선에서 예산별 최저 loss를 찾고, 둘째는 계산 예산을 고정한 별도 실행들을 비교한다. 셋째는 앞 절의 가산 모형을 직접 맞춘다. 세 방법은 모두 모델과 데이터를 비슷한 비율로 늘리는 방향을 제안한다. 예산이 10배가 될 때 Kaplan의 보고값은 $N$ 약 5.4배·$D$ 약 1.9배, Hoffmann의 첫 방법은 각각 약 3.2배에 해당한다.

실제 Chinchilla의 비율은 $1.4\mathrm T/70\mathrm B=20$이다. 가산 모형의 최적 비율은 $D_*/N_*=G^{-2}(C/6)^{b-a}$로, fitting 계수와 계산 예산에 따라 정해진다.

[원논문의 Figure 3와 §3.2](https://arxiv.org/html/2203.15556v1#S3.SS2)를 열고 가상 U자 곡선과 비교해 보자. 논문은 이 접근에서 9개 계산 예산을 정하고, 각 예산마다 여러 모델 크기를 학습했다. 그림은 다음 순서로 읽으면 된다.

1. **왼쪽 패널의 곡선 하나를 고른다.** 가로축은 모델 파라미터 수, 세로축은 최종 학습 loss다. 같은 곡선 위에서는 계산량이 고정되어 있으므로 오른쪽으로 갈수록 $N$은 늘고 $D$는 줄어든다. 각 점은 서로 다른 학습 실행의 결과이며, 한 모델이 학습 중 커지는 과정이 아니다.
2. **곡선의 최저점을 찾는다.** 측정한 점들에 곡선을 맞춰 그 예산에서 loss가 가장 낮아지는 모델 크기 $N_*$를 추정한다. 너무 작은 모델과, 주어진 예산으로 충분히 학습하지 못한 큰 모델 사이에 최적점이 나타난다.
3. **다른 예산의 최저점과 비교한다.** 예산이 커질 때 최적 모델 크기와 학습 토큰 수도 어떻게 커지는지 본다. 가운데·오른쪽 패널은 이 최저점들을 모아 $C$에 따른 $N_*,D_*$의 관계를 추정한 것이다.

논문은 전체 말뭉치보다 적은 토큰으로 학습하는 조건에서, 평활화한 학습 loss를 test loss의 불편 추정값으로 사용한다. 이것이 앞서 정의한 평가 loss와 그림의 학습 loss를 연결하는 가정이다. 학습 데이터를 여러 번 반복하는 경우에는 별도의 검증 데이터로 일반화 성능을 확인해야 한다.[^chinchilla]

관측 범위 밖으로 예측을 확장하는 것을 **외삽**(extrapolation)이라고 한다. Chinchilla는 작은 실험에서 얻은 예측을 더 큰 모델의 학습과 downstream 평가로 확인한 사례다.

### 2-3. 데이터 반복과 제약

Pre-training에서 데이터 풀의 크기와 학습에서 소비한 토큰 수를 구분했다. 예를 들어 다음 두 실행은 같은 모델을 학습한다면 $6ND$로 계산한 연산량이 같다.

| 구성 | 고유 데이터량 | 평균 반복 횟수 | 소비 토큰 수 $D$ |
|---|---|---|---|
| 새로운 문서를 한 번씩 읽기 | 100B | 1회 | 100B |
| 같은 문서를 반복해서 읽기 | 10B | 10회 | 100B |

그렇다고 두 실행의 최종 loss까지 같다고 예측할 수는 없다. 반복해서 읽으면 이미 본 문맥을 더 학습할 수 있지만, 새로운 문맥의 다양성이 같은 속도로 늘지는 않는다. **연산량을 세는 $D$와 성능을 예측할 때의 데이터 조건을 함께 봐야 한다.**

Muennighoff 등의 *Scaling Data-Constrained Language Models*는 고유 데이터량과 반복 횟수를 구분해 실험했다. 해당 실험에서는 몇 차례 반복이 유용했지만, 반복을 계속 늘릴 때 추가 계산의 이득은 줄었다. 따라서 새로운 데이터로 얻은 scaling 관계에 반복 토큰 수만 대입해 같은 개선을 기대하기는 어렵다.[^data-constrained] [원논문의 Figure 1](https://arxiv.org/html/2305.16264v3#S0.F1)은 반복에 따른 loss 감소와 자원 배분을 함께 보여준다.

한국어·전문 영역처럼 확보할 수 있는 문서가 제한적이라면, 모델 크기와 총 학습 토큰 수에 더해 고유 데이터량·반복 노출·혼합 비율을 기록한다. 데이터 품질이나 혼합을 바꾸었을 때에도 기존 fitting 계수가 그대로 적용되는지는 작은 비교 실험으로 확인해야 한다.

### 2-4. 추론을 포함한 비용

같은 품질을 가진 두 모델이 있다고 가정하자. 하나는 크고 학습을 짧게 했고, 다른 하나는 작지만 더 오래 학습했다. 작은 모델의 학습 비용이 더 들었더라도 앞으로 많은 요청을 처리한다면 배포 과정의 비용을 줄일 수 있다.

$$
C_{\text{lifetime}}=C_{\text{train}}+Q\,C_{\text{request}}
$$

$Q$는 예상 요청 수다. 이 식은 의사결정의 범위를 보여주기 위한 단순 모형이며, 실제 요청 비용은 입력·출력 길이와 batching, 하드웨어 등에 따라 달라진다. LLaMA 논문은 주어진 학습 예산에서만 최적인 모델과 추론을 고려한 모델 설계를 구분한다.[^llama1]

<Callout type="example">
같은 목표 품질에서 모델 A는 학습 비용 100, 요청당 비용 0.01이고, B는 학습 비용 150, 요청당 비용 0.005라고 가정하자. $100+0.01Q=150+0.005Q$이므로 손익분기점(break-even point)은 10,000회다. 금액이나 실제 모델 측정값이 아닌 가상 비용 단위이며, 장기 사용량이 학습 선택을 바꿀 수 있음을 보여준다.
</Callout>

“Compute-optimal보다 오래 학습했다”는 표현은 곧 낭비했다는 뜻이 아니다. 어떤 비용을 목적함수에 넣었는지 먼저 물어야 한다.

### 2-5. 예측의 검증

서베이 *(Mis)Fitting*은 학습 설정, 관측할 실험점, fitting 방식의 차이가 예측과 최적 비율을 바꿀 수 있음을 검토한다.[^survey] 우리 연구의 계획으로 바꾸면 다음 순서가 된다.

1. **비교 조건을 고정한다.** 데이터 분포·tokenizer·평가 텍스트·모델 계열을 명시한다.
2. **여러 크기와 학습 길이를 실험한다.** 한 모델의 중간 checkpoint만으로 모든 규모를 대표하지 않는다.
3. **추정에 쓰지 않은 실험으로 확인한다.** 관측 범위 안에서 곡선이 잘 맞는 것과 외삽이 맞는 것은 다르다.
4. **예측 오차를 예산에 반영한다.** 점추정(point estimate) 하나만 보고 대규모 학습을 결정하기보다 설정 변화에 대한 민감도를 본다.

Pre-training에서 본 learning rate schedule도 이 비교에 영향을 준다. 긴 학습용 schedule의 중간 checkpoint는, 그 시점에 학습을 마치도록 learning rate를 낮춘 별도 실행과 다르다. Chinchilla는 학습 토큰 수에 맞춰 cosine schedule의 길이를 정했다. 같은 $(N,D)$라도 최적화 설정이 다르면 loss와 추정한 최적점이 달라질 수 있다.[^chinchilla]

## 3. Emergent abilities

### 3-1. 관측된 능력의 출현

Pre-training에서 평균 NTP loss와 downstream 과제 정확도를 함께 보았다. 여기서도 두 지표를 구분한다. **평균 loss가 조금씩 낮아질 때, 특정 문제를 푸는 성공률도 같은 모양으로 좋아질까?** Wei 등은 작은 모델의 결과만으로 단순 외삽하기 어려운 능력의 출현을 emergent ability라는 관점에서 정리했다.[^emergence]

[그림 원문과 캡션](https://arxiv.org/html/2206.07682v2#S3.F2) · [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)

먼저 **(A) 산술**을 보자. 작은 모델들의 정확도는 0에 가깝고, 더 큰 학습 계산량을 쓴 모델에서 높아진다. **(G) Multi-task NLU**는 MMLU(massive multitask language understanding) 평가다. 작은 모델들의 점수가 무작위 선택 기준선 부근에 모여 있다가 큰 모델에서 상승한다. 두 경우 모두 작은 모델 몇 개만 봤다면 이후의 개선 폭을 예상하기 어려웠을 것이다.

1주차에서 본 **few-shot prompting**으로 평가한 결과이므로, 점수 상승은 평가 예시로 가중치를 갱신한 효과와 구분한다. 또 가로축은 파라미터 수 자체가 아닌 **학습 FLOPs**다. 곡선의 색·기호마다 모델 계열이 다르고 학습 데이터와 설정도 다를 수 있으므로, 하나의 보편적인 임계 모델 크기를 읽어 내는 그림으로 쓰지는 않는다.

하지만 그래프의 급격한 변화만으로 내부 능력이 불연속적으로 생겼다고 결론 내릴 수는 없다. Schaeffer 등은 평가 지표를 바꾸면 일부 급격한 출현이 부드러운 변화로 보일 수 있음을 분석했다.[^mirage]

### 3-2. 평가 지표와 측정 해상도

가상의 생성·평가 과정에서 길이가 5토큰인 답변을 만든다고 하자. 각 위치에 생성한 토큰이 정답과 일치할 확률을 $p$로 놓고, 다섯 위치의 성공 사건이 독립이라고 가정한다. 여기서 $p$는 생성 결과의 성공 확률이다. 앞서 NTP loss를 계산할 때 사용한, 정답 토큰에 부여한 모델 확률과는 구별한다. 전체가 맞아야 1점인 완전 일치(exact match) 점수의 기댓값(expected value)은 $p^5$다.

| 토큰별 정답 확률 $p$ | 전체 5토큰이 맞을 확률 $p^5$ |
|---|---|
| 0.4 | 1.02% |
| 0.6 | 7.78% |
| 0.8 | 32.77% |
| 0.9 | 59.05% |

토큰별 성능은 조금씩 좋아져도 전체 정답률은 뒤쪽에서 더 가파르게 보인다. 평가 문항이 적거나 모델 크기를 몇 개만 측정하면 낮은 구간은 모두 0점으로 관측될 수도 있다. 실제 언어의 토큰 오류는 독립이 아니므로, 이 표는 메커니즘의 가능성을 보여주는 단순 예제다.

측정 해상도의 영향도 계산해 보자. $p=0.4$일 때 답 전체의 성공률은 약 0.01024다. 독립적인 평가 문항 20개만 쓰면 성공 횟수의 기댓값은 약 0.205개이고, 전부 실패할 확률은 $(1-0.01024)^{20}\approx81.4\%$다. 실제 성공률이 조금씩 개선되어도 작은 평가에서는 계속 0점으로 보일 수 있는 이유다.

이 논쟁에서 구분할 것은 **능력의 개선**, **그 개선이 급격한가**, **작은 실험으로 예측할 수 있는가**다. 지표 효과를 지적하는 것이 모델의 유용한 능력 향상을 부정하는 것은 아니다. 반대로 성공률 곡선 하나만으로 새로운 메커니즘의 출현을 입증한 것도 아니다.

실제 지표 비교는 [Schaeffer 등의 Figure 3](https://arxiv.org/html/2304.15004v2#S3.F3)에서 볼 수 있다. 위쪽은 산술 응답 전체의 정답 여부를 평가하고, 아래쪽은 정답에 도달하기 위해 토큰을 얼마나 고쳐야 하는지 보는 token edit distance로 평가한다. 같은 모델 계열의 출력도 채점 방식에 따라 개선 곡선이 달라진다.[^mirage] 앞의 $p^5$는 이 가능성을 이해하는 작은 예제이며, 모든 과제의 emergence를 설명했다는 뜻은 아니다.

계산 예산과 목표 품질을 바탕으로 $N,D$를 정했다면, 다음 문제는 그 학습을 실제 GPU에서 수행하는 것이다. Training engineering에서는 가중치·gradient·optimizer 상태를 저장하고 계산과 통신을 분산하는 방법을 살펴본다. 여기서 센 연산량이 학습 시간으로 어떻게 이어지는지도 그 실행 방식에 달려 있다.
