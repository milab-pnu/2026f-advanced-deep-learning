Latent diffusion은 autoencoder가 압축한 이미지 표현인 latent 공간에서 noise를 추가하고 제거한다.
Denoiser는 현재 noisy latent와 시간, 조건을 받아 생성에 필요한 예측을 만든다.[^survey]
이 denoiser를 꼭 U-Net으로 만들 필요는 없다.
Diffusion Transformer(DiT)는 latent를 patch token으로 바꾸고 Transformer로 처리한다.[^dit]
DiT는 diffusion의 학습 방식과 반복 sampling은 그대로 두고, denoiser의 backbone만 Transformer로 바꾼다.

## 1. U-Net에서 Transformer로

U-Net은 convolution으로 공간 해상도를 낮췄다 높이는 계층 구조와 skip connection을 쓰고, attention은 일부 해상도에만 끼운다.
DiT는 latent를 일정한 크기의 조각으로 나누어 token으로 바꾼다.
이 token열은 해상도를 바꾸지 않은 채 같은 구조의 Transformer block을 반복해 지나며, self-attention으로 서로 정보를 교환한다.

두 구조 모두 noisy 입력, 시간 정보, 조건을 받아 sampler에 전달할 출력을 만든다.
Sampler가 denoiser를 여러 번 호출해야 한다는 diffusion의 비용도 두 구조에 똑같이 남는다.
그런데도 구조를 바꾸려 한 이유는 규모에 있다.
Transformer는 언어와 이미지 인식에서 표준 구조가 되었고, 이미지 인식에서는 ViT가 convolution network보다 규모를 키울 때 더 효과적이었다.
반면 diffusion의 denoiser는 처음 도입된 U-Net의 큰 설계를 그대로 이어 오고 있었다.[^dit]
그래서 DiT 원논문이 묻는 핵심 질문은 Transformer의 크기와 token 수를 늘리면 이미지 생성 품질이 어떻게 달라지는가이다.

## 2. Latent를 token으로

### 2-1. Patchify

이미지 autoencoder가 $256\times256$ 이미지를 높이와 너비가 각각 32이고 채널이 4인 latent로 바꾼다고 하자.
Latent diffusion의 forward 과정은 이 latent에 noise를 더해 $z_t$를 만든다.
DiT는 $z_t$를 한 변이 $p$인 patch로 나눈다.
높이 $H$, 너비 $W$가 $p$로 나누어떨어지면 token 수는 다음과 같다.

$$
N=\frac{H}{p}\frac{W}{p}.
$$

예를 들어 $32\times32\times4$ latent에 $2\times2$ patch를 쓰면, patch 하나는 $2\times2\times4=16$개의 값을 갖는다.
전체 patch는 $16\times16=256$개다.
DiT는 모든 patch에 같은 학습 가능한 선형 투영을 적용해, 16차원 patch를 hidden dimension $D$인 벡터로 바꾼다.
그 결과 Transformer에 들어가는 배열의 크기는 $N\times D$다.

이미지 원본을 patch로 나누는 ViT와 달리 여기서는 **이미 압축된 noisy latent**를 patch로 나눈다.
DiT는 각 token에 위치 정보를 더해, 그 token이 원래 격자의 어디에 있었는지 알려 준다.
원논문은 고정된 2차원 sinusoidal position embedding을 사용한다.

### 2-2. Patch 크기와 비용

같은 $32\times32$ latent에서 $p=4$이면 token은 64개이고 $p=2$이면 256개다.
Patch가 작을수록 token 하나가 나타내는 영역이 작아져, 모델이 세밀한 정보를 다룰 여지가 생긴다.
대신 attention이 계산해야 할 token 쌍도 많아진다.
일반적인 dense self-attention의 token 간 점수 행렬은 $N\times N$이다.
앞의 256-token 예에서는 attention head마다 $256\times256$개의 점수가 생긴다.
Token 수를 4배로 늘리면 그 행렬의 원소 수는 16배가 된다.
다만 전체 모델의 계산량까지 16배가 되지는 않는다.
선형 투영과 MLP(multi-layer perceptron, 각 token에 적용하는 신경망)의 비용은 token 수에 비례해 4배로 늘기 때문이다.

## 3. DiT block의 조건 주입

DiT block은 표준 Transformer block처럼 self-attention과 MLP를 residual connection으로 잇는다.
DiT가 바꾼 것은 시간과 class 조건을 block에 넣는 방식이다.

오른쪽의 흐린 두 block은 원논문이 대안으로 비교한 방식이고, 이어지는 설명은 adaLN-Zero block을 기준으로 한다.

### 3-1. Adaptive layer normalization

DiT의 입력은 token만이 아니다.
모델은 현재 $t$에 해당하는 timestep embedding과 생성할 class의 embedding을 조건으로 받는다.
원논문의 기본 실험은 text prompt가 아니라 ImageNet의 class 조건 생성이다.
Timestep embedding은 현재 noise 수준을 알려 주고, class embedding은 만들 이미지의 범주를 알려 준다.
원논문의 구현은 timestep을 여러 주파수의 sinusoidal 값으로 표현한 뒤 작은 MLP에 통과시킨다.
Class label은 embedding table에서 같은 차원의 벡터로 바꾼다.
모델은 두 벡터를 더해 조건 벡터 $c$를 만든다.
그래서 같은 `개` class라도 시간 단계가 바뀌면 $c$가 달라지고, 같은 시간이라도 class가 바뀌면 $c$가 달라진다.[^dit]

Layer normalization은 token의 hidden 차원에 걸친 값을 정규화한다.
DiT의 adaptive layer normalization(adaLN)은 조건 벡터 $c$를 이용해 정규화 결과의 크기와 이동량을 조절한다.
조건 벡터에서 만든 두 벡터를 $\gamma(c)$와 $\beta(c)$라 하면 adaLN은 다음과 같다.

$$
\operatorname{adaLN}(h,c)=\bigl(1+\gamma(c)\bigr)\odot\operatorname{LN}(h)+\beta(c).
$$

$h$는 token의 hidden vector, $\odot$는 원소별 곱이다.
이 표기에서 $\gamma=0$, $\beta=0$이면 정규화 결과가 그대로 전달된다.
adaLN은 조건에 따라 각 hidden 차원을 얼마나 키우고 옮길지 바꾼다.
그래서 같은 token도 시간과 class에 따라 다르게 처리된다.
여기의 $\beta$는 diffusion noise schedule의 $\beta_t$와 다른 값이다.

### 3-2. AdaLN-Zero와 residual gate

원논문이 주로 쓰는 adaLN-Zero는 attention과 MLP 앞에 각각 조건으로 만든 scale과 shift를 적용한다.
그리고 각 연산의 출력을 residual 경로에 더하기 전에 별도의 gate를 곱한다.
각 block의 조건 처리층은 $c$에서 attention용 shift·scale·gate와 MLP용 shift·scale·gate를 만든다.
각 벡터의 길이가 hidden dimension $D$이므로 이 여섯 벡터를 합친 출력의 길이는 $6D$다.
조건 벡터는 모든 위치에 똑같이 주어지지만, 위치마다 hidden 값이 다르므로 결과도 위치마다 다르다.
경로 하나만 간단히 쓰면 다음과 같다.

$$
h'=h+g(c)\odot F\bigl(\operatorname{adaLN}(h,c)\bigr).
$$

$F$는 attention 또는 MLP이고 $g(c)$는 조건에서 만든 차원별 gate다.
두 경로를 순서대로 쓰면 첫 번째가 self-attention, 두 번째가 MLP다.
두 경로는 정규화와 gate에 서로 다른 조건부 벡터를 쓴다.

$$
h_1=h+g_{\mathrm{attn}}(c)\odot\operatorname{Attn}(\operatorname{adaLN}_{\mathrm{attn}}(h,c)).
$$

$$
h_2=h_1+g_{\mathrm{mlp}}(c)\odot\operatorname{MLP}(\operatorname{adaLN}_{\mathrm{mlp}}(h_1,c)).
$$

다음 block은 $h_2$를 입력받아 같은 종류의 처리를 별도의 학습된 parameter로 반복한다.

DiT의 공식 구현은 조건 처리층의 마지막 선형층을 0으로 초기화한다.
그래서 처음에는 $\gamma(c)$, $\beta(c)$, $g(c)$가 모두 0이고, gate $g(c)$가 0이므로 각 block은 입력을 그대로 전달한다.
예를 들어 어떤 차원에서 입력이 2이고 $F$의 출력이 0.4라면 gate가 0일 때 출력은 2, gate가 0.5일 때 출력은 2.2다.
Block의 gate가 0이면 그 block의 residual branch 내부로 전달되는 gradient는 처음에 0이다.
DiT 구현은 최종 출력층도 0으로 초기화한다.
그래서 학습 초기에는 출력층이 먼저 갱신되고, 그다음 gate와 block 내부로 gradient가 전파된다.
이 초기화는 block의 학습을 막지 않고, 모델이 입력을 그대로 전달하는 상태에서 출발해 residual 경로를 점차 쓰게 한다.[^dit]

## 4. Unpatchify와 출력

마지막 Transformer block의 출력은 여전히 $N$개의 벡터다.
DiT는 조건으로 scale과 shift를 정하는 layer normalization을 한 번 더 적용한다.
그다음 각 벡터를 선형 변환해 해당 patch 위치의 출력 값으로 만들고, 이를 격자 순서대로 다시 이어 붙인다.
이를 unpatchify라고 한다.
앞의 $32\times32$, $p=2$ 예에서는 256개 출력 patch를 다시 $32\times32$ 격자로 조립한다.
원논문 모델은 noise와 함께 분산도 예측하므로, 출력 채널 수는 입력의 두 배다.
입력 latent가 4채널이면 모델은 patch마다 $2\times2\times8=32$개의 값을 예측하고, 이를 이어 $32\times32\times8$ 배열로 만든다.

이 출력은 완성된 이미지가 아니라 latent 위의 예측이다.
Sampler가 이 예측으로 noise가 조금 더 적은 latent를 만들고, 다음 시간 단계에서 같은 DiT를 다시 호출한다.
반복이 끝난 latent는 autoencoder의 decoder가 이미지로 바꾼다.

## 5. 계산량과 생성 품질

크기를 키우면 품질이 어떻게 되는지 보려면 품질을 잴 지표가 필요하다.
DiT 원논문은 생성 이미지 평가에 흔히 쓰는 FID(Fréchet Inception Distance)를 쓴다.[^fid]
FID는 실제 이미지 묶음과 생성 이미지 묶음을 모두 ImageNet으로 학습한 Inception-v3 분류 network에 통과시켜 특징 벡터를 얻는다.
그리고 각 묶음의 특징 분포를 평균과 공분산으로 요약해, 두 분포가 얼마나 떨어져 있는지를 거리로 잰다.
생성 이미지의 특징 통계가 실제 이미지와 비슷할수록 FID가 작아지므로, **FID는 낮을수록 좋다.**
이미지 한 장씩 채점하지 않고 두 묶음의 통계를 비교하므로, 생성 이미지를 많이 뽑아 계산한다.
DiT 원논문은 생성 이미지 5만 장으로 계산한 값(FID-50K)을 보고한다.

Patch 크기를 줄이면 token이 늘어 계산량은 크게 늘지만, 모든 patch가 같은 weight를 공유하므로 parameter 수는 거의 그대로다.
그래서 원논문은 모델의 크기를 parameter 수가 아니라 forward 한 번에 드는 연산량인 Gflops(10억 번 단위의 부동소수점 연산 수)로 잰다.
원논문은 depth와 width가 다른 네 구성(S, B, L, XL)과 세 patch 크기(8, 4, 2)를 조합해 DiT 12개를 같은 조건으로 학습했다.
이름의 숫자가 patch 크기다.
예를 들어 DiT-XL/2는 가장 큰 XL 구성에 $p=2$를 쓴 모델이다.
결과는 일관적이었다.
모델을 키워도, patch를 줄여 token을 늘려도 Gflops가 늘었고, Gflops가 클수록 FID가 낮았다.[^dit]

<Callout type="example">
다음은 원논문이 보고한 값 일부다.
모두 ImageNet $256\times256$에서 40만 step 학습한 뒤, classifier-free guidance(CFG) 없이 잰 FID-50K다.

| 모델 | Parameter | Gflops | FID-50K |
|---|---|---|---|
| DiT-XL/8 | 676M | 7.4 | 106.41 |
| DiT-XL/4 | 675M | 29.1 | 43.01 |
| DiT-XL/2 | 675M | 118.6 | 19.47 |
| DiT-S/2 | 33M | 6.1 | 68.40 |
| DiT-B/4 | 130M | 5.6 | 68.38 |

XL 세 모델은 parameter 수가 거의 같지만, patch를 줄여 Gflops가 늘수록 FID가 106에서 19로 내려간다.
반대로 DiT-S/2와 DiT-B/4는 parameter 수가 약 4배 차이 나도 Gflops가 비슷하고 FID도 거의 같다.
이 실험에서 품질을 가른 것은 parameter 수보다 계산량이었다.
</Callout>

이 분석에서 가장 Gflops가 큰 DiT-XL/2를 700만 step까지 학습하자, ImageNet $256\times256$ class 조건 생성에서 FID-50K가 CFG 없이 9.62, CFG를 쓰면 2.27이었다.[^dit]
이 값은 그때까지 가장 좋던 diffusion 모델인 LDM(latent 공간의 U-Net)이 CFG를 써서 얻은 3.60보다 낮다.
DiT-XL/2의 연산량은 118.6 Gflops로 LDM과 비슷하고, pixel 공간에서 동작하는 U-Net(ADM)의 1120 Gflops보다 훨씬 작다.
앞에서 던진 질문에 원논문이 내놓은 답은 이렇다.
Transformer denoiser는 Gflops가 클수록 FID가 꾸준히 낮아졌고, 충분히 키운 모델은 비슷한 계산량의 U-Net 기반 모델보다 좋은 FID를 냈다.

## 6. 텍스트 조건과 영상 확장

### 6-1. 텍스트와 이미지 token의 결합

원래 DiT는 class label 하나를 조건 벡터로 받는다.
텍스트 prompt처럼 여러 token으로 된 조건을 넣으려면 조건을 주는 방식을 다시 정해야 한다.
Stable Diffusion 3 연구의 multimodal diffusion transformer(MMDiT)는 이미지와 텍스트 표현에 별도의 가중치를 사용하면서 두 종류의 token이 attention을 통해 정보를 교환하도록 설계한다.[^sd3]
더 구체적으로 이미지 token과 텍스트 token은 각자의 가중치로 query, key, value를 만든다.
그다음 모델은 두 종류의 query·key·value를 sequence 방향으로 이어 붙여 joint attention을 계산한다.
그래서 이미지 token은 텍스트 token을, 텍스트 token은 이미지 token을 참고할 수 있다.
모델은 attention 결과를 다시 modality별로 나누어 각자의 후속 변환으로 처리한다.
이미지 query가 텍스트 key와 value만 읽는 기본 cross-attention과 달리, 여기서는 정보가 양방향으로 오간다.
Stable Diffusion 3는 학습 방식도 바꿨다.
Noise와 데이터를 직선 경로로 잇고 모델이 그 경로를 따라가는 이동 방향을 예측하게 하는 rectified flow로 학습한다.
Transformer라는 구조 선택과 rectified flow라는 경로·학습 선택은 서로 다른 축이다.

### 6-2. Spacetime patch와 Sora

영상에는 가로·세로뿐 아니라 시간축이 있다.
이미지 patch가 공간의 조각이라면, spacetime patch는 시간과 공간에 걸친 latent의 조각이다.
모델은 이 조각 하나를 token 하나로 표현한다.
한 장면의 여러 시점이 함께 처리되므로 생성 모델은 프레임 사이의 움직임과 일관성도 다루어야 한다.
영상 latent의 모양과 patch 크기에 따라 token 수와 계산량이 크게 달라진다.

OpenAI는 Sora를 이미지와 영상 latent의 spacetime patch를 처리하는 diffusion transformer로 설명한다.[^sora]
보고서는 patch와 예측 대상의 개요만 설명하고, block 구성이나 조건을 넣는 방식은 공개하지 않는다.

### 6-3. Text-to-video와 image-to-video

Text-to-video는 텍스트로 장면과 움직임을 지정하고 영상을 생성하는 task다.
예를 들어 “눈 내리는 숲을 카메라가 천천히 지나간다”라는 요청에는 숲의 모습과 시간에 따른 변화가 함께 담긴다.
모델은 영상 latent의 noise에서 출발해 텍스트 조건에 맞는 시공간 표현을 만들고, decoder는 이를 프레임들로 변환한다.
이때 diffusion의 denoising 단계는 영상 속 시간과 별개여서, 각 단계는 모든 프레임을 함께 조금씩 갱신한다.

Text + image → video에서는 입력 이미지가 장면의 구체적인 모습을 제공하고, 텍스트가 원하는 움직임이나 변화를 지정한다.
같은 요청에 숲 사진을 함께 주면, 사용자는 숲의 생김새를 글로 모두 설명하지 않아도 된다.
모델은 정지 이미지에 없는 움직임과 새로 드러나는 영역을 생성해야 하므로, 입력 이미지만으로 결과 영상이 하나로 결정되지는 않는다.

2024년 Sora 보고서는 같은 모델로 텍스트만으로 영상을 만드는 예와 이미지·prompt를 함께 주어 정지 이미지를 움직이게 만드는 예를 모두 보여 준다.[^sora]
