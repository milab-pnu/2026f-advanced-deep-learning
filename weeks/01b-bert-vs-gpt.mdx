앞 노트에서 조립한 Transformer 블록은 그대로 두고, **어떤 mask 로 어떤 목적함수를
학습하느냐**만 바꾸면 성격이 사뭇 다른 두 계열이 나온다. 2018–2020년의 BERT[^bert]
와 GPT[^gpt1][^gpt2][^gpt3] 가 그것이다. 이 노트는 둘의 차이를
정리하고, 왜 생성형 LLM(large language model) 이 **decoder-only** 로 수렴했는지[^wang22] 를 본다. 다음
노트부터는 decoder-only 만 다룬다.

## 1. 같은 블록, 다른 mask

Transformer 블록의 self-attention 은 $Q K^\top$ 행렬의 어느 성분을 살리고 어느 성분을
$-\infty$ 로 덮느냐에 따라 두 가지로 갈린다.

- **양방향(bidirectional) attention** — mask 없음. 위치 $i$ 가 문장의 **모든** 위치를
  본다. 앞뒤 문맥을 다 쓰므로 각 토큰의 표현이 풍부하지만, "다음 토큰"을 정의할 수 없다
  (이미 다 봤으므로). → **encoder**, 이해(understanding)용.
- **인과(causal) attention** — causal mask. 위치 $i$ 는 $j \le i$ 만 본다. 위치 $i$ 의
  표현은 "지금까지 본 것"만 담으므로 그 자리에서 다음 토큰 $x_{i+1}$ 을 예측하는 것이
  잘 정의된다. → **decoder**, 생성(generation)용.

그래서 **BERT 를 쌓는다** = 매 층에서 각 토큰이 좌·우 문맥을 함께 흡수해 표현이 점점
정교해지고, 마지막에 그 표현 위에 분류기 같은 얇은 층을 얹는다. **GPT 를 쌓는다** =
매 층에서 각 토큰이 왼쪽 문맥만 반영한 표현을 만들고, 마지막 위치의 표현이 곧 "다음에
올 토큰"의 예측이 된다 — 그걸 이어 붙이면 생성이다. 층을 아무리 쌓아도 이 성격은
그대로다.

## 2. BERT — 양방향 encoder

BERT(Bidirectional Encoder Representations from Transformers)[^bert] 는 §1a 의 블록을
mask 없이 쌓은 **encoder** 스택이다(BERT-base: 12층, $d_{\text{model}} = 768$, 12 head,
110M 파라미터). 각 위치가 문장 전체를 보므로 표현은 풍부하지만, 그 대가로 "다음 토큰"
이라는 학습 목표를 쓸 수 없다 — 예측해야 할 토큰까지 이미 입력에서 봐 버리기 때문이다.
그래서 BERT 는 다른 학습 과제를 만든다.

### Masked Language Modeling (MLM)

**빈칸 채우기**다. 문장에서 토큰의 약 15%를 가리고, 모델에게 **가려진 자리에 원래
있던 토큰**을 양쪽 문맥으로 맞히게 한다.

```
입력:   고양이가 [???] 위에 앉았다
정답:   방석
```

위치 $i$ 를 맞히려면 $i$ 의 왼쪽("고양이가")과 오른쪽("위에 앉았다")을 모두 봐야 하므로,
학습이 끝나면 모든 토큰의 표현에 양방향 문맥이 담긴다. 이것이 BERT 표현이
"bidirectional" 인 이유다.

가리는 방법에는 사연이 있다. 매번 특수 토큰 `[MASK]` 로만 바꾸면, 모델은 `[MASK]` 가
보이는 자리에서만 예측을 준비하게 된다. 그런데 정작 downstream 과제(분류·태깅 등)의
입력에는 `[MASK]` 가 없다 — 학습 때만 보던 표식이 실전에서 사라지는 불일치다. 이를
줄이려고, 고른 15% 를 이렇게 나눠 처리한다.

- **80%** — `[MASK]` 로 바꾼다. 기본 케이스.
- **10%** — 엉뚱한 임의 토큰으로 바꾼다. 모델은 "이 자리 단어가 문맥에 안 맞는다"를
  알아채고 원래 토큰을 복원해야 한다.
- **10%** — 그대로 둔다. 겉보기엔 멀쩡한 이 자리도 모델은 (원본인지 아닌지 모른 채)
  예측을 내야 한다.

뒤 두 경우 덕분에 모델은 `[MASK]` 표식에만 의존하지 못하고 **모든 위치를 늘 문맥으로
따져 보는** 습관을 들인다.

### Next Sentence Prediction (NSP)

BERT 는 MLM 과 함께 두 번째 과제도 학습했다. 문장 두 개 A, B 를 이어 붙여 넣고 "B 가
원문에서 실제로 A 다음에 오던 문장인가?"를 예·아니오로 맞히게 한다. 질의응답·자연어
추론처럼 문장 쌍 관계가 중요한 과제를 겨냥한 장치였지만, 이후 연구(RoBERTa[^roberta])
에서 효과가 미미하고 빼는 편이 낫다고 밝혀졌다.

### 사전학습이 끝나면

BERT 는 이제 어떤 문장이든 넣으면 토큰마다 양방향 문맥 표현을 내놓는다. 입력을 넣을
때 문장 맨 앞에 `[CLS]`, 문장 경계에 `[SEP]` 토큰을 두는데, 학습된 `[CLS]` 자리의
벡터를 문장 전체의 요약으로 쓴다. 여기에 **얇은 과제용 층 하나**를 얹고 과제 데이터로
조금 더 학습하면(fine-tuning) 감성 분석·자연어 추론·개체명 인식 등이 된다.
2018–2020년의 표준 절차가 "BERT 를 받아와 각 과제에 fine-tune" 이었다.

BERT 계열이 지금도 쓰이는 자리는 **분류, 검색용 임베딩(retrieval), 리랭킹** 처럼 입력을
한 번에 이해하기만 하면 되고 생성이 필요 없는 곳이다. 이런 용도는 생성형 LLM 시대에도
encoder 가 효율적이다(양방향 + 단 한 번의 forward).

## 3. GPT — 인과적 decoder

GPT(Generative Pre-Training)[^gpt1] 는 Transformer **decoder** 스택에서
encoder–decoder attention(cross-attention)을 뺀 것이다(GPT-1: 12층, 117M) — 참조할
encoder 가 없으니 masked self-attention 과 FFN 만 남는다. causal mask 하에 **오직
next-token prediction** 만 학습한다:

$$
\mathcal{L} = -\sum_{i} \log p_\theta\big( x_i \mid x_{<i} \big)
$$

한 문장으로 위치마다 loss 가 나오고(teacher forcing, 앞 노트 6절), 학습이 끝나면 같은
모델로 토큰을 하나씩 뽑아 문장을 **생성**할 수 있다.

GPT 라인의 궤적이 이 노트의 핵심이다.

- **GPT-1**[^gpt1] (2018) — generative pre-training + 과제별 discriminative
  fine-tuning. 아직 BERT 와 같은 "불러와서 fine-tune" 틀.
- **GPT-2**[^gpt2] (2019, 1.5B) — 더 크게, 더 많은 데이터(WebText). fine-tuning
  없이 **zero-shot** 으로 여러 과제를 수행. "언어모델은 비지도 멀티태스크 학습기".
- **GPT-3**[^gpt3] (2020, 175B) — **in-context learning**. 파라미터를 안 바꾸고,
  프롬프트에 예시 몇 개를 넣는 것(few-shot)만으로 과제를 수행. 이때부터 "모델을 과제에
  맞추는" 대신 "프롬프트로 과제를 지시하는" 틀로 넘어간다.<Sidenote>in-context learning 처럼 스케일이 커지며 두드러지는 능력을 초기엔 **emergent ability** — 작은 모델엔 없다가 큰 모델에서 갑자기 나타나는 능력 — 라 불렀다.[^wei22] 이후 이 "급격한 출현"의 상당 부분은 불연속적 평가지표가 만든 착시이며, 잘 최적화된 소형 모델도 유사한 능력을 보인다는 반론이 자리잡았다.[^mirage]</Sidenote>

<Callout type="intuition">
BERT 와 GPT-1 은 "사전학습 + fine-tuning" 이라는 같은 게임을 했다. 판을 바꾼 것은
GPT-2 → GPT-3 의 **스케일 + zero/few-shot**: 하나의 고정된 모델이 프롬프트만으로 수많은
과제를 처리한다. fine-tuning 데이터셋도, 과제별 모델도 필요 없어진다.
</Callout>

## 4. 그 사이의 선택지 — encoder–decoder 와 prefix LM

### 두 스택을 다 쓰는 encoder–decoder

세 번째 길은 원래 Transformer 처럼 스택을 **둘** 두는 것이다.

- **encoder** 가 입력 문장을 양방향으로 읽어 각 토큰의 표현을 만든다(BERT 처럼).
- **decoder** 가 출력을 왼쪽에서 오른쪽으로 생성하되(GPT 처럼), 매 스텝 encoder 가 만든
  입력 표현도 함께 참조한다. 이 "출력 쪽이 입력 쪽을 들여다보는" attention 이 1a 노트
  6절의 **encoder–decoder attention**(= cross-attention)이다.

입력을 다 소화한 뒤 출력을 쓰기 시작하는 구조라, **입력과 출력이 뚜렷이 나뉘는**
번역·요약에 잘 맞는다("이 문장(입력)을 이 문장(출력)으로 바꿔라").

대표가 **T5**[^t5] 다. T5 는 모든 과제를 "문자열 하나를 받아 문자열 하나를 내놓는다"로
통일한다 — 번역도, 감성 분류도(출력이 `"positive"` 라는 단어), 요약도 같은 틀이다.
사전학습은 **span corruption**: 입력에서 짧은 토큰 구간 몇 개를 통째로 지우고 각 자리를
자리표시 토큰(sentinel, `<X>`·`<Y>` …) 하나로 대체한 뒤, decoder 가 지워진 구간들만
순서대로 복원하게 한다.

```
원문:   Thank you for inviting me to your party last week .
입력:   Thank you <X> me to your party <Y> week .
정답:   <X> for inviting <Y> last <Z>
```

(`<Z>` 는 "여기서 끝"이라는 종료 표시다.) BERT 의 빈칸 채우기와 비슷하지만, 빈칸이
여러 토큰짜리 구간이고 복원을 decoder 가 생성으로 한다는 점이 다르다.

**BART**[^bart] 는 같은 encoder–decoder 이되 입력을 더 다양하게 망가뜨린다 — 토큰을
지우고, 문장 순서를 섞고, 구간을 마스킹한 문장을 넣어 decoder 가 **원문 전체**를
되살리게 한다(denoising autoencoder, 잡음 섞은 입력에서 원본을 복원하는 모델).

encoder–decoder 의 대가는 구조가 복잡하다는 것이다(스택 둘 + cross-attention). 또 하나의
모델로 "프롬프트에 그냥 이어 쓰기"를 시키기에는 입력/출력 경계가 걸리적거린다.

### 스택 하나로 근사하는 prefix LM

**Prefix LM** 은 스택을 하나만 두는 절충안이다. decoder-only 처럼 단일 스택이지만,
attention mask 를 입력 구간과 생성 구간으로 나눈다 — 프롬프트(prefix)에 해당하는 앞부분은
서로 앞뒤를 다 보게(양방향), 그 뒤 생성하는 부분은 왼쪽만 보게(causal). encoder–decoder
의 "입력은 양방향으로 읽는다"를 스택 하나 안에서 흉내 낸 셈이다. mask 가 전부 causal 은
아니라는 뜻에서 **non-causal decoder** 라고도 부른다(GLM 등이 채택).

정리하면 후보는 세 형태다 — **causal decoder-only**, **prefix LM(non-causal decoder)**,
**encoder–decoder**. §5 에서 볼 Wang 등(2022)[^wang22] 의 비교가 바로 이 셋을 같은
조건에서 나란히 놓은 것이다. 세 구조와 각각의 attention mask 를 그림으로 보려면 T5
논문 §3.2 의 Figure 3–4 가 깔끔하다.[^t5]

## 5. 왜 생성형 LLM 은 decoder-only 로 수렴했나

2020년 이후 범용 생성 모델은 거의 전부 causal decoder-only 다(GPT-3/4, Llama, Mistral,
Qwen, Gemma …). 이유를 정리하면:

1. **구조가 가장 단순하다.** 스택 하나, attention 한 종류(masked self), cross-attention
   없음. 스케일링·최적화·서빙 스택을 이 한 형태에 집중할 수 있다.
2. **사전학습이 밀도 높다.** causal LM(language model) 은 길이 $n$ 시퀀스에서 위치 $n$ 개
   전부에 loss 를 준다. BERT-MLM 은 15% 만 예측하므로 같은 데이터에서 학습 신호가 적다.
3. **사전학습과 사용 방식이 일치한다.** "다음 토큰 예측"으로 배우고 "다음 토큰 생성"으로
   쓴다. 이해·생성·대화·추론이 모두 같은 인터페이스(이어 쓰기)로 표현된다.
4. **zero/few-shot 일반화가 가장 좋다.** Wang 등(2022)[^wang22] 은 동일 조건에서
   아키텍처×목적함수를 비교해, **순수 자기지도 사전학습만 했을 때는 causal decoder-only +
   autoregressive LM 이 zero-shot 일반화가 가장 강함**을 보였다(멀티태스크 fine-tuning 을
   추가하면 non-causal + MLM 이 앞서지만, 범용 기반 모델의 기본기는 전자).
5. **in-context learning 과 궁합.** 프롬프트에 예시를 이어 붙이면 그대로 "이어 쓰기"
   문제가 된다 — 별도 입력/출력 분리가 필요 없다.
6. **KV(key–value) cache 로 생성이 효율적이다.** causal 구조라서 이미 계산한 key/value 를
   캐시해 토큰당 비용을 낮출 수 있다.

<Callout type="warning">
"decoder-only 가 항상 최선"은 아니다. 고정 입력을 반복 참조하는 번역·요약 전용이라면
encoder–decoder 가 여전히 효율적이고, 분류·검색이라면 encoder 가 낫다. decoder-only 가
이긴 것은 **하나의 모델로 최대한 많은 것을 하려는** 범용 생성 시나리오다.
</Callout>

## 6. 정리

| | BERT (encoder) | GPT (decoder-only) | T5 (encoder–decoder) |
|---|---|---|---|
| attention | 양방향 | causal | encoder 양방향 + decoder causal |
| 사전학습 목적 | MLM (+NSP) | next-token prediction | span corruption |
| 학습 신호 밀도 | 토큰의 ~15% | 토큰의 100% | 가려진 span |
| 잘 맞는 일 | 분류, 검색 임베딩, 리랭킹 | 범용 생성·대화·추론, in-context learning | 번역·요약 등 입력→출력 과제 |
| 사용 방식 | 과제별 fine-tuning | 프롬프트(zero/few-shot) | text-to-text fine-tuning |
| 대표 | BERT, RoBERTa, DeBERTa | GPT-3/4, Llama, Mistral, Qwen | T5, BART, FLAN-T5 |

- Transformer 블록은 공유하고, **mask + 목적함수**가 계열을 가른다.
- BERT = 양방향 이해, GPT = 인과적 생성, encoder–decoder(및 prefix LM) = 입력/출력이 나뉘는 과제.
- 범용 생성 LLM 은 **단순성 · 사전학습 밀도 · 사용 일치 · zero/few-shot · KV cache**
  때문에 causal decoder-only 로 수렴했다.

돌며, Llama 3 8B 로 각 부분의 크기를 확인한다.
