앞 노트에서 조립한 Transformer 블록은 그대로 두고, **어떤 mask 로 어떤 목적함수를
학습하느냐**만 바꾸면 성격이 전혀 다른 두 계열이 나온다. 2018–2020년의 BERT[^bert]
와 GPT[^gpt1][^gpt2][^gpt3] 가 그것이다. 이 노트는 둘의 차이를
정리하고, 왜 생성형 LLM 이 **decoder-only** 로 수렴했는지[^wang22] 를 본다. 다음
노트부터는 decoder-only 만 다룬다.

## 1. 같은 블록, 다른 mask

Transformer 블록의 self-attention 은 $Q K^\top$ 행렬의 어느 성분을 살리고 어느 성분을
$-\infty$ 로 덮느냐에 따라 두 가지로 갈린다.

- **양방향(bidirectional) attention** — mask 없음. 위치 $i$ 가 문장의 **모든** 위치를
  본다. 앞뒤 문맥을 다 쓰므로 각 토큰의 표현이 풍부하지만, "다음 토큰"을 정의할 수 없다
  (이미 다 봤으므로). → **encoder**, 이해(understanding)용.
- **인과(causal) attention** — causal mask. 위치 $i$ 는 $j \le i$ 만 본다. 위치 $i$ 의
  표현은 "지금까지 본 것"만 담으므로 그 자리에서 다음 토큰 $x_{i+1}$ 을 예측하는 것이
  잘 정의된다. → **decoder**, 생성(generation)용.

## 2. BERT — 양방향 encoder

BERT(Bidirectional Encoder Representations from Transformers)[^bert] 는 Transformer
**encoder** 스택이다(BERT-base: 12층, $d_{\text{model}} = 768$, 12 head, 110M 파라미터).
mask 가 없으므로 다음 토큰 예측은 못 한다. 대신 두 개의 자기지도 목적함수로 학습한다.

**Masked Language Modeling (MLM).** 입력 토큰의 15%를 골라, 그중 80%는 `[MASK]` 로,
10%는 임의 토큰으로 바꾸고, 10%는 그대로 둔다. 모델은 **가려진 자리의 원래 토큰**을
앞뒤 문맥으로 복원한다. 위치 $i$ 를 맞출 때 $i$ 의 좌우를 모두 보므로 양방향 표현이
학습된다.

<Sidenote>`[MASK]` 는 fine-tuning·추론 때는 안 나온다. 10% 를 임의 토큰, 10% 를 원본으로 두는 것은 이 train/test 불일치를 줄이려는 장치다.</Sidenote>

**Next Sentence Prediction (NSP).** 두 문장 A, B 를 이어 붙이고 B 가 A 의 실제 다음
문장인지 이진 분류한다. 이후 연구(RoBERTa[^roberta])에서 NSP 는 별 도움이 안 되고
오히려 빼는 게 낫다는 게 밝혀졌다.

**입력 형식과 사용법.** 문장 앞에 `[CLS]`, 문장 사이·끝에 `[SEP]` 를 넣는다. 학습 후
`[CLS]` 위치의 최종 벡터를 문장 전체의 요약으로 보고, 그 위에 얇은 분류 head 를 얹어
**과제별로 fine-tuning** 한다(감성 분석, 자연어 추론, 개체명 인식 등). 2018–2020년의
지배적 패러다임 = "BERT 를 불러와 각 과제에 fine-tune".

BERT 계열이 지금도 쓰이는 자리: **분류, 검색용 임베딩(retrieval), 리랭킹** 처럼 입력을
한 번에 이해하면 되고 생성이 필요 없는 곳. 생성형 LLM 시대에도 이 용도는 encoder 가
효율적이다(양방향 + 한 번의 forward).

## 3. GPT — 인과적 decoder

GPT(Generative Pre-Training)[^gpt1] 는 Transformer **decoder** 스택에서
cross-attention 을 뺀 것이다(GPT-1: 12층, 117M). causal mask 하에 **오직 next-token
prediction** 만 학습한다:

$$
\mathcal{L} = -\sum_{i} \log p_\theta\big( x_i \mid x_{<i} \big)
$$

한 문장으로 위치마다 loss 가 나오고(teacher forcing, 앞 노트 6절), 학습이 끝나면 같은
모델로 토큰을 하나씩 뽑아 문장을 **생성**할 수 있다.

GPT 라인의 궤적이 이 노트의 핵심이다.

- **GPT-1**[^gpt1] (2018) — generative pre-training + 과제별 discriminative
  fine-tuning. 아직 BERT 와 같은 "불러와서 fine-tune" 틀.
- **GPT-2**[^gpt2] (2019, 1.5B) — 더 크게, 더 많은 데이터(WebText). fine-tuning
  없이 **zero-shot** 으로 여러 과제를 수행. "언어모델은 비지도 멀티태스크 학습기".
- **GPT-3**[^gpt3] (2020, 175B) — **in-context learning**. 파라미터를 안 바꾸고,
  프롬프트에 예시 몇 개를 넣는 것(few-shot)만으로 과제를 수행. 이때부터 "모델을 과제에
  맞추는" 대신 "프롬프트로 과제를 지시하는" 틀로 넘어간다.

<Callout type="intuition">
BERT 와 GPT-1 은 "사전학습 + fine-tuning" 이라는 같은 게임을 했다. 판을 바꾼 것은
GPT-2 → GPT-3 의 **스케일 + zero/few-shot**: 하나의 고정된 모델이 프롬프트만으로 수많은
과제를 처리한다. fine-tuning 데이터셋도, 과제별 모델도 필요 없어진다.
</Callout>

## 4. Encoder–decoder 도 있다 — T5, BART

세 번째 선택지는 원래 Transformer 처럼 **encoder + decoder** 를 다 쓰는 것이다.

- **T5**[^t5] — 모든 NLP 과제를 "text-in → text-out" 으로 통일. 사전학습은
  **span corruption**: 입력에서 연속된 토큰 구간을 하나의 sentinel 로 가리고, decoder 가
  그 구간을 복원. encoder 는 양방향으로 입력을 읽고 decoder 가 인과적으로 출력을 생성.
- **BART** — encoder 에 다양한 noise(토큰 삭제, 순서 섞기 등)를 준 문장을 넣고 decoder 가
  원문을 복원하는 denoising autoencoder.

encoder–decoder 는 **입력과 출력이 뚜렷이 나뉘는** 과제(번역, 요약)에서 강하다. 입력을
양방향으로 충분히 인코딩한 뒤 출력을 생성하기 때문이다. 대가는 구조가 복잡하고(두 스택 +
cross-attention), 하나의 모델로 "그냥 이어 쓰기"를 하기엔 어색하다는 것.

## 5. 왜 생성형 LLM 은 decoder-only 로 수렴했나

2020년 이후 범용 생성 모델은 거의 전부 causal decoder-only 다(GPT-3/4, Llama, Mistral,
Qwen, Gemma …). 이유를 정리하면:

1. **구조가 가장 단순하다.** 스택 하나, attention 한 종류(masked self), cross-attention
   없음. 스케일링·최적화·서빙 스택을 이 한 형태에 집중할 수 있다.
2. **사전학습이 밀도 높다.** causal LM 은 길이 $n$ 시퀀스에서 위치 $n$ 개 전부에 loss 를
   준다. BERT-MLM 은 15% 만 예측하므로 같은 데이터에서 학습 신호가 적다.
3. **사전학습과 사용 방식이 일치한다.** "다음 토큰 예측"으로 배우고 "다음 토큰 생성"으로
   쓴다. 이해·생성·대화·추론이 모두 같은 인터페이스(이어 쓰기)로 표현된다.
4. **zero/few-shot 일반화가 가장 좋다.** Wang 등(2022)[^wang22] 은 동일 조건에서
   아키텍처×목적함수를 비교해, **순수 자기지도 사전학습만 했을 때는 causal decoder-only +
   autoregressive LM 이 zero-shot 일반화가 가장 강함**을 보였다(멀티태스크 fine-tuning 을
   추가하면 non-causal + MLM 이 앞서지만, 범용 기반 모델의 기본기는 전자).
5. **in-context learning 과 궁합.** 프롬프트에 예시를 이어 붙이면 그대로 "이어 쓰기"
   문제가 된다 — 별도 입력/출력 분리가 필요 없다.
6. **KV cache 로 생성이 효율적이다.** causal 구조라서 이미 계산한 key/value 를 캐시해
   토큰당 비용을 낮출 수 있다(네 번째 노트).

<Callout type="warning">
"decoder-only 가 항상 최선"은 아니다. 고정 입력을 반복 참조하는 번역·요약 전용이라면
encoder–decoder 가 여전히 효율적이고, 분류·검색이라면 encoder 가 낫다. decoder-only 가
이긴 것은 **하나의 모델로 최대한 많은 것을 하려는** 범용 생성 시나리오다.
</Callout>

## 6. 정리

| | BERT (encoder) | GPT (decoder-only) | T5 (encoder–decoder) |
|---|---|---|---|
| attention | 양방향 | causal | encoder 양방향 + decoder causal |
| 사전학습 목적 | MLM (+NSP) | next-token prediction | span corruption |
| 학습 신호 밀도 | 토큰의 ~15% | 토큰의 100% | 가려진 span |
| 잘 맞는 일 | 분류, 검색 임베딩, 리랭킹 | 범용 생성·대화·추론, in-context learning | 번역·요약 등 입력→출력 과제 |
| 사용 방식 | 과제별 fine-tuning | 프롬프트(zero/few-shot) | text-to-text fine-tuning |
| 대표 | BERT, RoBERTa, DeBERTa | GPT-3/4, Llama, Mistral, Qwen | T5, BART, FLAN-T5 |

- Transformer 블록은 공유하고, **mask + 목적함수**가 계열을 가른다.
- BERT = 양방향 이해, GPT = 인과적 생성, encoder–decoder = 입력/출력 분리 과제.
- 범용 생성 LLM 은 **단순성 · 사전학습 밀도 · 사용 일치 · zero/few-shot · KV cache**
  때문에 causal decoder-only 로 수렴했다.

다음 노트는 이 decoder-only 모델을 **tokenizer 입력부터 sampling 출력까지** 한 바퀴
돌며, Llama 3 8B 로 각 부분의 크기를 확인한다.
