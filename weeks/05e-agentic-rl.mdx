지금까지의 RL(reinforcement learning)은 프롬프트 하나에 응답 하나를 내는 문제였다. 04b의 PPO(proximal policy optimization)도, 05c의 GRPO(group relative policy optimization)도 응답이 끝나면 에피소드가 끝나고 과제의 보상이 한 번 온다. 실제 과제의 많은 부분은 그렇지 않다. 검색해서 읽고 다시 검색하고, 코드를 실행해 오류를 보고 고치고, 사용자와 여러 턴을 주고받는다. 모델의 출력이 환경을 바꾸고 환경의 응답이 다음 입력이 되는 이런 상호작용 궤적을 보상으로 학습하는 것을 **agentic RL**이라고 부른다. 상호작용의 형식(ReAct)과 도구 호출 텍스트의 자기 지도 학습(Toolformer)은 그에 앞선 단계다. 이 노트는 단일 응답 RL이 도구 호출과 다중 턴 궤적으로 확장될 때 무엇이 달라지는지를 따라간다. 데이터의 형태, 손실을 거는 위치, 보상이 오는 시점, 그리고 05d의 생성 비용이 모두 바뀐다.

전체 지도는 Zhang 등이 2025년에 정리하고 2026년 TMLR에 실린 agentic RL 서베이[^survey]로 잡는다. §2가 단일 응답 RL과 agentic RL을 MDP(Markov decision process)의 형식으로 대비하고, §3이 능력별(계획, 도구 사용, 기억, 자기 개선, 추론, 지각) 분류를, §4가 과제별 분류를, §5가 환경과 프레임워크를 정리한다. 이 노트는 §2의 형식과 §3.2의 도구 사용에 집중한다.

## 1. 단일 응답에서 궤적으로

### 1-1. 형식의 차이

서베이 §2는 선호 기반 강화 fine-tuning(preference-based reinforcement fine-tuning, PBRFT)으로 대표되는 지금까지의 post-training RL을, 응답 전체를 행동 하나로 묶은 **퇴화한 MDP**로 형식화한다.[^survey] 상태는 프롬프트 하나이고, 그 행동 뒤에 종료 상태로 한 번 전이하며, 보상은 한 번 온다(04b §3-2처럼 토큰을 행동으로 보면 토큰 단위 MDP가 되지만 환경의 개입은 없다). 서베이는 agentic RL을 부분 관측 MDP(partially observable MDP, POMDP)로 모델링한다. 환경에는 정책이 다 볼 수 없는 상태(파일 시스템, 검색 엔진의 색인, 사용자의 의도)가 있고, 정책이 행동(텍스트, 도구 호출)을 내면 환경이 관측(검색 결과, 실행 출력, 사용자 답)을 돌려준다. 서베이의 식은 정책이 현재 관측을 보고 행동한다고 쓰지만, LLM(large language model) agent에서는 지금까지의 행동과 관측이 모두 문맥에 이어 붙으므로 사실상 그 이력 전체가 다음 행동의 입력이 된다. 보상은 여러 시점에 올 수 있고 최종 성공은 여러 턴 뒤에 정해진다.

| | 단일 응답 RL (04b–05c) | Agentic RL |
|---|---|---|
| 환경 상태 | 프롬프트 | 프롬프트와 정책이 다 보지 못하는 세계 상태 |
| 정책의 입력 | 프롬프트 | 프롬프트 + 지금까지의 행동과 관측의 이력 |
| 행동 | 응답 전체 (토큰열) | 한 턴의 텍스트 또는 도구 호출 |
| 전이 | 종료 상태로 한 번 | 행동에 따라 환경 상태가 바뀌고, 정책은 그에 대한 관측을 받음 |
| 보상 | 응답 끝에 한 번 | 최종 결과, 또는 턴마다 |
| 궤적 길이 | 응답 하나 | 턴 여러 개, 길면 수만 토큰 |

### 1-2. 학습에서 달라지는 세 가지

이 형식 변화가 04b–05c의 학습 절차에 미치는 영향은 셋이다.

**손실을 거는 위치.** 궤적에는 정책이 생성하지 않은 토큰이 섞여 있다. 검색 결과와 실행 출력은 환경이 넣은 것이므로, 정책의 log 확률을 올리거나 내리는 대상이 아니다. Search-R1은 검색으로 가져온 토큰을 손실에서 mask했고, mask를 적용했을 때 성능 향상이 더 크고 학습이 더 안정적이었다고 보고했다.[^searchr1] 04a §2-3의 loss mask가 지시 토큰을 제외한 것과 같은 논리이고, 대상이 관측 토큰으로 바뀐 것이다. 04a에서처럼 mask는 손실에서 빼는 것이지 입력에서 빼는 것이 아니다. 관측 토큰은 문맥에 남아 뒤의 정책 토큰을 예측하는 조건이 되고, 확률비와 log 확률은 정책이 생성한 토큰에서만 계산한다.

**보상의 귀속.** 최종 보상 하나를 여러 턴에 어떻게 나누는가가 credit assignment 문제다. 가장 단순한 방법은 04b §3-2의 return처럼 최종 보상을 모든 턴에 그대로 주는 것이고, 턴마다 별도 보상(도구 호출 형식, 중간 결과)을 더하면 05a §2-4의 process 보상이 된다.

**생성 비용.** 궤적 하나를 만들려면 정책 생성과 환경 실행이 번갈아야 한다. 도구 실행(검색, 코드 실행)의 지연이 생성에 더해지고, 궤적 길이의 분산이 커진다. 05d의 비동기 설계가 여기서 더 절실해지고, 비싸게 만든 궤적 중 상당수가 학습 신호를 주지 않는다는 문제도 커진다(§3-2).

<Callout type="example">
**두 턴 궤적의 mask와 return.** "소설 『채식주의자』의 작가가 노벨 문학상을 받은 해는?"이라는 질문에 Search-R1 형식(§2-3)으로 답하는 교육용 궤적을 보자. 학습에 들어가는 토큰열은 세 구간으로 나뉜다.

| 구간 | 내용 | 생성 주체 | Loss mask |
|---|---|---|---|
| 턴 1 | `<think>`작가를 먼저 확인하고 수상 연도를 찾는다`</think><search>`채식주의자 작가 노벨 문학상`</search>` | 정책 | 1 |
| 관측 | `<information>`한강은 2024년 노벨 문학상을 받았다. …`</information>` | 환경(검색 엔진) | 0 |
| 턴 2 | `<think>`작가는 한강이고 수상 연도는 2024년이다`</think><answer>`2024`</answer>` | 정책 | 1 |

관측 구간은 mask가 0이지만 턴 2의 토큰을 계산할 때 문맥으로 들어간다. 정책 갱신의 확률비와 log 확률은 mask가 1인 두 구간의 토큰에서만 계산한다. 최종 답이 맞아 보상 1을 받았고 중간 보상은 없다면, 할인 없이 계산한 각 턴의 return은 둘 다 1이다. 여기에 "검색어가 형식을 지켰는가"에 대한 process 보상 0.1을 턴 1에 더하면 턴 1의 return은 1.1, 턴 2는 1이 된다. 최종 보상을 두 턴에 임의로 반씩 나누지는 않는다. 각 턴은 자기 뒤에 온 보상의 합을 받는다. 실제 갱신 방향은 이 return에서 value model이나 그룹 baseline을 뺀 advantage가 정한다. GRPO처럼 그룹 baseline을 쓰는데 같은 문제의 다른 궤적들도 모두 1을 받았다면, 05c §1-2처럼 advantage가 0이 되어 policy 항의 신호가 사라진다(KL 항의 gradient는 남는다).
</Callout>

## 2. 도구 사용의 계보

도구 사용 연구는 두 축으로 나눠 보면 정리된다. 하나는 모델이 도구와 주고받는 **상호작용 형식**이다(ReAct의 few-shot 설정). 다른 하나는 그 형식 안에서 언제 어떤 도구를 부를지를 가르치는 **학습 신호와 학습 단위**이며, Toolformer의 자기 지도 학습에서 결과로 보상하는 RL로 발전했다. RL은 다시 학습 단위에 따라 두 갈래로 나뉜다. 표의 "겨냥한 한계"는 각 방법을 앞의 방법과 견주어 이 노트가 정리한 것이며, 원논문이 그 방법을 직접 계승했다는 뜻은 아니다.

| 방법 | 축 | 겨냥한 한계 | 학습 신호 | 학습 단위 |
|---|---|---|---|---|
| ReAct | 상호작용 형식 | (출발점) 추론만 하는 프롬프팅과 행동만 하는 방식이 따로 다뤄짐 | 없음(few-shot 프롬프트) | 없음 |
| Toolformer | 학습 신호·단위 | ReAct식 프롬프팅은 매번 예시가 필요하고 호출 시점을 학습하지 않음 | 다음 토큰 예측 | 도구 호출이 끼워진 텍스트 |
| Search-R1 | 학습 신호·단위 (RL, 궤적 갈래) | 시연·자기 지도 데이터에 없는 호출 시점·조합은 배우기 어려움 | 최종 답의 정확 일치 | 검색 실행을 포함한 다중 턴 궤적 |
| ToolRL | 학습 신호·단위 (RL, 단계 갈래) | Search-R1과 같은 한계를 단일 단계 호출과 보상 설계로 다룸 | 형식 + 호출의 세분화된 정확성 | 이력이 주어진 다음 호출 한 단계 |
| ARPO | 학습 신호·단위 (RL, 궤적 갈래) | Search-R1식 궤적 단위 보상은 어느 턴이 좋았는지 구분 못함 | 정확성·형식 + 다중 도구 사용 보너스 | 분기로 공통 prefix를 공유하는 궤적 묶음 |

두 RL 갈래 중 ARPO는 Search-R1과 같은 궤적 갈래에서 credit assignment를 다듬은 발전이다.

### 2-1. ReAct의 상호작용 형식

도구 사용의 출발점은 학습이 아니라 프롬프트였다. Yao 등의 ReAct는 모델이 "생각(thought)"과 "행동(action)"을 번갈아 쓰고 행동의 결과인 "관측(observation)"을 받아 다음 생각을 잇게 하는 형식을 few-shot 예시로 유도했다.[^react] 질의응답과 사실 확인에서 위키백과 검색을, 상호작용 과제에서 환경 명령을 행동으로 썼다. 원논문은 같은 형식으로 fine-tuning한 실험도 함께 보고했지만 중심은 프롬프팅이다. 이 형식은 이후 agent에서 널리 쓰이게 되었지만, 이 프롬프팅 설정에서는 매번 예시를 넣어야 하고 예시에 없는 상황에서 언제 도구를 부를지 모델이 알기 어렵다.

### 2-2. Toolformer의 자기 지도 학습

Schick 등의 Toolformer는 도구 호출을 모델에 **학습**시켰다.[^toolformer] 계산기, 검색, 번역 같은 API(application programming interface)를 어디에 끼워 넣으면 다음 토큰 예측이 좋아지는지를 모델 자신이 표집·검증해 학습 데이터를 만들고, 그 데이터로 언어 모델을 자기 지도 방식으로 fine-tuning했다. 사람이 쓴 예시는 API마다 몇 개뿐이다. 도구 호출이 든 텍스트로 fine-tuning한다는 점에서, 이후의 공개 recipe가 도구 호출이 포함된 대화 데이터를 04a §2의 SFT(supervised fine-tuning)에 넣는 것과 같은 갈래다. Olmo 3 Instruct의 SFT 데이터에는 도구 사용 프롬프트가 약 23만 개 들어 있다(원논문 Table 30).[^olmo3] 시연 데이터에는 04a §5-2에서 본 학습 문맥과 생성 문맥의 차이가 그대로 남는다. 시연에 없는 도구 조합이나 실패 뒤의 복구는 모델이 스스로 그런 상황을 만나 보며 배워야 한다는 것이 이후 RL 연구의 출발점이다.

### 2-3. Search-R1의 다중 턴 rollout

05a의 검증 가능한 보상이 여기서 다시 쓰인다. Jin 등의 Search-R1은 모델이 `<think>`, `<search>`, `<answer>` 태그로 추론·검색·답을 번갈아 내게 하고, 검색 엔진이 `<information>` 태그로 결과를 돌려주며, 보상은 최종 답의 정확 일치뿐이다. 프롬프트는 지식이 부족하면 검색을 부를 수 있다고만 알려 주고, 언제 무엇을 검색할지의 시연은 주지 않았다. 정책 생성과 검색 실행이 번갈아 이어지는 궤적 전체가 하나의 rollout이고, §1-2의 mask를 이 rollout의 검색 결과 토큰에 적용한다.

결과는 일곱 개 질의응답 데이터셋의 정확 일치 평균으로 보고되었다. Instruct 모델에 검색 증강 생성(retrieval-augmented generation, RAG)을 붙인 기준선이 7B 0.304, 3B 0.270이었고, base model에서 PPO로 학습한 Search-R1은 7B 0.431, 3B 0.303이었다(원논문 Table 2). 같은 초기 모델의 전후 비교는 아니며, 표의 값으로 계산한 상대 차이는 약 42%와 12%다. 원논문이 요약한 향상률은 위치마다 표기가 일치하지 않아(arXiv 초록 페이지는 41%와 20%, v5 PDF의 초록과 §4.4는 24%와 20%), 여기서는 Table 2의 두 행을 밝혀 직접 계산했다.[^searchr1]

### 2-4. ToolRL의 단계별 보상

Qian 등의 ToolRL은 같은 문제를 다른 학습 단위로 다룬다. 다중 턴 궤적을 "지금까지의 대화 이력이 주어졌을 때 다음 도구 호출"이라는 단일 단계 사례로 분해해 프롬프트에 이력을 넣고, 보상 설계에 집중했다. 도구 호출의 형식 보상에 더해, 정답 호출과 비교해 도구 이름·인자 이름·인자 값이 각각 맞는지를 나누어 점수를 주는 세분화된 정확성 보상을 두었다. Qwen2.5-Instruct(1.5B, 3B, 7B)와 Llama-3.2-3B-Instruct에서 출발해 GRPO로 학습했다.[^toolrl]

원논문 초록은 여러 도구 사용·질의응답 벤치마크에 걸쳐 출발 모델보다 17%, SFT 모델보다 15% 향상이라고 요약하지만 이 값의 집계 방식은 밝히지 않는다. 표의 한 예로 BFCL V3 전체 정확도(Table 1)에서 Qwen2.5-7B-Instruct는 출발 모델 41.97%에서 Instruct 모델에서 바로 시작한 GRPO 58.38%로 올랐고, 도구 SFT 뒤에 GRPO를 한 모델(SFT400+GRPO)은 39.25%였다. 원논문은 추가 도구 SFT 뒤에 RL을 하는 것보다 Instruct 모델에서 바로 RL을 시작하는 편이 그 실험에서 나았고, 긴 추론이 도구 호출 성능을 자동으로 높이지는 않았으며, 보상을 세분화하면 학습이 안정적이었다고 보고한다.[^toolrl] 마지막 관찰은 04d의 "검증기가 무엇을 확인하는가"의 다른 면이다. 도구 호출에서는 무엇을 확인해야 하는지가 비교적 분명하다.

### 2-5. ARPO의 분기 rollout

Search-R1처럼 궤적 단위로 보상을 주는 GRPO를 그대로 쓰면 궤적 안의 어느 턴이 좋았는지 구분하지 못한다. Dong 등의 ARPO(agentic reinforced policy optimization)는 도구 결과가 돌아온 직후 10–50토큰에서 정책의 entropy가 급격히 오른다는 관측에서 출발했다.[^arpo] 원논문의 예비 실험으로 보면, 새 정보를 받은 직후가 초기 추론보다 불확실한 지점이라는 뜻이다.

ARPO의 rollout(entropy 기반 적응 rollout)은 다음 순서로 진행된다(원논문 §3.1).

1. 질문마다 전체 rollout 예산 $M$ 중 $N$개는 처음부터 끝까지 궤적을 생성하고, 나머지 $M-N$개는 분기용으로 남긴다. 각 궤적의 처음 $k$개 토큰의 entropy를 기준값으로 기록한다.
2. 도구 결과가 돌아올 때마다 그 뒤 $k$개 토큰을 생성해 entropy를 다시 재고, 기준값 대비 변화량을 구한다.
3. 변화량이 클수록 커지는 분기 확률이 임계값을 넘으면 그 지점에서 후속 $Z$개를 새로 생성하고, 아니면 현재 궤적을 그대로 이어 간다.

이렇게 얻은 궤적들은 분기 지점 앞의 토큰(공통 prefix)을 공유한다. 보상의 정규화는 05c와 같이 같은 질문의 전체 rollout 그룹에서 하고, 정책 갱신에서 공통 prefix를 어떻게 다룰지가 advantage attribution이다(원논문 §3.2). 기본 설정(soft)은 GRPO 손실을 그대로 쓴다. 공통 prefix의 토큰은 분기 수만큼의 궤적에 같은 문맥과 같은 확률비로 들어가므로, 그 토큰의 갱신에는 분기들의 advantage가 합쳐져 기여하고, 갈라진 뒤의 토큰은 각 분기의 advantage만 받는다. 별도 장치 없이도 공통 부분과 갈라진 부분이 서로 다른 신호를 받는 셈이다. 다만 GRPO 손실의 궤적 길이 정규화와 clipping이 함께 작용하므로, 공통 토큰이 받는 신호가 advantage의 단순 합이나 hard 설정의 평균과 정확히 같지는 않다. 보상은 Search-R1의 정확 일치 하나가 아니라, 답의 정확성과 형식 보상에 더해 정답을 올바른 형식으로 내면서 검색과 Python 실행을 함께 쓴 궤적에 0.1을 더 주는 다중 도구 사용 보상으로 이루어진다(원논문 §3.2, 식 8).

<Details summary="Hard 설정의 계산 예">

Hard 설정은 이 구분을 advantage 수준에서 명시한다. 공통 prefix의 토큰에는 그 prefix를 공유하는 분기들의 advantage 평균을, 갈라진 뒤의 토큰에는 각 분기의 advantage를 준다. 한 prefix에서 갈라진 두 후속의 advantage가 $+0.8$과 $-0.4$이면 공통 토큰은 $+0.2$, 갈라진 뒤의 토큰은 각각 $+0.8$과 $-0.4$를 받는다. 원논문은 soft 설정이 학습 중 보상이 더 높고 안정적이어서 기본값으로 썼다.

</Details>

수학·지식 질의응답·심층 검색의 13개 벤치마크에서 ARPO는 궤적 단위 RL 알고리즘보다 평균 성능이 높았다고 보고되었다(개별 벤치마크에서는 비슷하거나 낮은 경우도 있다).[^arpo] 효율은 따로 측정했다. Qwen2.5-7B에서 GRPO와 학습 중 도구 호출 수를 비교한 결과, ARPO가 전체 정확도는 더 높으면서 도구 호출은 절반만 썼다(원논문 §4.6, Figure 7). 원논문 초록은 이를 "도구 사용 예산의 절반"으로 요약하지만, 직접 측정한 근거는 이 한 모델의 비교이고 학습 시간을 잰 것도 아니다.

## 3. 환경과 데이터

### 3-1. 환경을 만드는 문제

단일 응답 RL의 데이터는 문제와 정답이었다. Agentic RL의 데이터는 **환경**이다. 도구가 실제로든 시뮬레이터 안에서든 실행되어야 하고, 과제마다 성공 조건이 있어야 하며, 궤적이 길어 사람이 만들기 어렵다. Kimi K2는 이 문제를 합성으로 풀었다. GitHub의 MCP(model context protocol) 도구 3천여 개에 합성 도구 2만여 개를 더해 도구 저장소를 만들고, 서로 다른 시스템 프롬프트와 도구 조합으로 수천 개의 agent를 정의한 뒤, 각 agent에 성공 기준(rubric)이 달린 과제를 주고, 사용자 역할의 LLM과 상태를 유지하는 도구 시뮬레이터 사이에서 다중 턴 궤적을 생성해 LLM 판정자가 rubric으로 걸렀다.[^kimik2] 이 궤적은 SFT 데이터가 되고, 그 뒤의 RL은 검증 가능한 보상과 rubric 기반 자기 비평 보상을 함께 쓴다.[^kimik2] 시뮬레이터가 실제 환경과 다르면 시뮬레이터에 맞춘 행동을 배운다는 위험은 04d의 대리 지표 문제와 같다.

### 3-2. 평가의 민감성과 rollout 낭비

Liu 등은 2026년에 도구 호출 agent를 평가와 학습 두 쪽에서 점검했다.[^liu2026] 평가 쪽에서는 무작위 시드, 시스템 프롬프트, 다중 턴 template의 구성, 이전 턴의 이력과 추론을 다음 턴에 어떻게 넘기는지 같은 문서화되지 않은 작은 선택이 보고 점수를 크게 바꾸며, 다중 턴 설정에서는 표준화 없이 leaderboard 순위를 믿기 어렵다고 보고했다. 환경이 개입하는 만큼 단일 응답 벤치마크보다 변동 요인이 많다. 논문이나 자기 실험의 agent 점수를 비교할 때는 이 설정들이 같은지부터 확인해야 한다.

학습 쪽의 관찰은 §1-2 예시의 마지막 문장과 이어진다. 한 프롬프트의 rollout이 모두 같은 보상을 받으면 그룹 advantage가 0이 되어 policy 항의 학습 신호가 없다. 도구 호출 RL에서는 이런 프롬프트의 비율이 예상보다 높았다.

원논문은 단일 턴(Qwen2.5-3B-Instruct)과 다중 턴(Qwen3-4B) 두 설정 모두에서 유효 프롬프트가 20% 안팎이라고 보고했다(Figure 4). 05c §2-2의 dynamic sampling은 이런 그룹을 버리고 다시 뽑아 배치를 채우지만, 05d §2-2에서 보았듯 그만큼 생성이 더 필요하고, Liu 등은 이 방식이 오히려 학습 시간을 크게 늘렸다고 관찰했다(원논문 §5). 대신 이들은 생성 **전에** 거르는 방법을 제안했다. 최근 몇 epoch 동안 모든 rollout이 정답이었던 프롬프트는 한동안 계속 정답일 가능성이 높다는 관찰에 근거해, 그런 프롬프트를 rollout을 만들기 전에 건너뛴다(§4.1). 어느 프롬프트가 무효인지는 학습 중에 바뀌므로 학습 전에 한 번 거르는 것으로는 부족하다는 점도 함께 지적했다. 여기에 정책 갱신 단계의 계산을 줄이는 rollout down-sampling(§4.2)을 더해, 같은 성능에 도달하는 시간이 단일 턴에서 1.7배, 다중 턴에서 2.6배 빨랐다(§4.3, Figure 7).

## 4. 정리와 다음 노트

Agentic RL은 04b–05c의 틀을 버리지 않는다. 정책 갱신은 같은 policy gradient이고 보상은 05a의 검증기와 04b·04d의 판정자에서 온다. 바뀐 것은 궤적에 환경의 토큰이 섞이고, 보상이 여러 턴 뒤에 오며, 생성이 환경 실행과 얽힌다는 점이다. 그래서 손실 mask, credit assignment, 환경 합성, rollout 효율이 새 문제가 된다. 서베이 §3의 나머지 능력(계획, 기억, 자기 개선)과 §4의 과제(코드, GUI(graphical user interface), 체화 agent(embodied agent))는 이 노트의 범위 밖이며, 14주차의 world model과 VLA(vision-language-action) 모델에서 다시 만난다.

5주차의 마지막 질문이 남는다. 이렇게 RL로 만든 큰 모델의 능력을 작은 모델에 어떻게 옮기는가. 05f가 그 답을 04c §3-1의 on-policy 관점에서 찾는다.
