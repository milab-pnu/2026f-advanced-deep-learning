“오늘 부산의 날씨는”이라는 문자열이 어떻게 다음 토큰의 확률로 바뀔까? LLM(large language model)의 구조와 학습을 정리한 Zhao 등의 서베이[^survey]를 바탕으로, Llama 3 하나의 입력부터 출력까지 따라간다. 여기서 잡을 큰 흐름은 **텍스트의 수치화 → 문맥 반영 → 다음 토큰 선택**이다.

## 1. 한 토큰의 생성 과정

“오늘 부산의 날씨는” 뒤를 이어 쓰게 한다고 하자. 모델은 먼저 텍스트를 정수 ID 열로 바꾸고, 각 ID에 대응하는 벡터에 문맥을 반영한다. 마지막에는 가능한 다음 토큰마다 점수를 계산한다. **모델이 점수를 만드는 과정과, 그 점수로 토큰을 고르는 과정**을 함께 거쳐야 문장이 이어진다.

아래 그림은 한 번의 생성 과정을 보여준다. 토큰 분할·ID·벡터·logits는 교육용 가상 값이며, Llama의 실제 실행 결과는 아니다. `␠`는 공백을 나타낸다.

## 2. 모델 계산과 학습

### 2-1. Token ID와 embedding

Tokenizer는 어휘 집합(vocabulary)과 분할 규칙을 이용해 문자열을 정수 ID 열로 바꾼다. 도입 예문에서는 `[17, 42, 9, 83, 11]`이다. 임베딩(embedding)은 그 ID에 대응하는 실수 벡터를 제공한다. ID 42는 테이블의 행 번호일 뿐, ID 17보다 의미가 크거나 강하다는 뜻이 아니다.

이 노트의 기준 모델은 <strong>Llama 3 8B base(2024년 4월 공개)</strong>다. Vocabulary 크기는 $V=128{,}256$, 벡터 차원은 $d=4{,}096$이다. 모델 규모는 Llama 3 보고서의 Table 3과 공식 구현을 따른다.[^llama][^implementation]

$$
E\in\mathbb{R}^{V\times d},\qquad x_i=E_{t_i},\qquad X\in\mathbb{R}^{n\times d}
$$

$n$은 입력 토큰 수다. 예문의 다섯 ID로 다섯 행을 조회하면 $5\times4096$ 행렬 $X$가 된다. 같은 ID는 처음에 같은 embedding을 받지만, decoder를 통과한 뒤에는 앞선 문맥에 따라 다른 표현을 갖게 된다.

여기서는 tokenizer가 정해져 있다고 둔다. Vocabulary와 병합 규칙의 학습, 어휘 크기의 선택, 처음 보는 문자열의 처리는 [다음 Tokenizer 노트](/lecture/2026f-advanced-deep-learning/02b-tokenizer/)에서 다룬다.

이후 그림과 수식에서는 배치(batch) 차원을 생략한다. 여러 입력을 한 번에 처리할 때에는 대부분의 텐서 앞에 batch 크기 $B$가 붙는다.

### 2-2. Llama 3 8B 구조

임베딩 행렬은 32개의 decoder 블록을 차례로 통과한다. 각 블록의 구조는 같지만 가중치는 별개다. 블록을 지나는 동안 $n\times d$라는 모양은 유지되고, 마지막 LM(language model) head에서 각 토큰의 벡터가 vocabulary 전체의 점수로 바뀐다.

### 2-3. 문맥과 벡터 변환

Decoder 블록 안에서는 attention과 FFN(feed-forward network)이 서로 다른 일을 한다. **Attention은 위치 사이의 정보를 섞고, FFN은 각 위치의 벡터를 변환한다.** Causal mask 때문에 각 위치는 자신과 앞선 위치만 참조한다. 예문의 마지막 “는”은 앞의 “오늘 부산의 날씨”를 반영할 수 있지만, 첫 “오늘”은 뒤쪽 토큰을 보지 못한다.

Llama는 각 연산 전에 RMSNorm(root mean square normalization)으로 벡터의 크기를 정규화한다. 연산 결과를 원래 입력에 더하는 경로가 잔차 연결(residual connection)이다. 블록 하나의 입력을 $X$, 중간 결과를 $A$, 출력을 $Y$라고 하면 다음과 같다.[^implementation]

$$
A=X+\operatorname{Attn}(\operatorname{RMSNorm}(X))
$$

$$
Y=A+\operatorname{FFN}(\operatorname{RMSNorm}(A))
$$

더하는 두 행렬의 모양이 같아야 하므로 attention과 FFN은 각각 $n\times d$ 형태로 결과를 돌려준다. 전체 구조도에 표시한 부품들은 이 두 연산을 구체화한다.

- **GQA(grouped-query attention):** 여러 query head가 key–value head를 공유한다. Llama 3 8B에서는 query head 4개가 한 쌍의 key–value head를 공유한다.
- **RoPE(rotary position embedding):** 각 층의 query와 key에 위치에 따른 회전을 적용해 위치 관계를 반영한다.
- **SwiGLU(Swish-gated linear unit):** FFN의 두 입력 투영 중 한 경로에 활성화 함수를 적용하고, 다른 경로와 원소별로 곱한 뒤 출력 차원으로 투영한다.

여기서는 각 부품의 역할까지 이해하면 된다. RoPE·GQA·SwiGLU의 세부 연산은 3주차에서 다룬다.

### 2-4. Logits와 확률

마지막 decoder 출력에 최종 RMSNorm을 적용한 결과를 $H$라고 하자. LM head는 hidden dimension $d$를 vocabulary dimension $V$로 바꾸는 선형 변환이다.

$$
H\in\mathbb{R}^{n\times d},\qquad
W_{LM}\in\mathbb{R}^{d\times V},\qquad
Z=HW_{LM}\in\mathbb{R}^{n\times V}
$$

$Z$의 $i$번째 행은 입력의 $i$번째 토큰까지 읽었을 때 **그다음 토큰**의 점수다. 이 점수를 logits라고 한다. 현재 입력 뒤를 잇는 데에는 마지막 행 $z=Z_n$을 사용한다. 수식의 행 번호는 1부터 세며, 구현에서는 보통 0부터 센다.

Softmax는 logits를 합이 1인 확률 분포로 바꾼다.

$$
p(v\mid t_{1:n})=\frac{\exp(z_v)}{\sum_{u=1}^{V}\exp(z_u)}
$$

도입 그림의 세 후보 예에서는 $[2,1,0]$이 약 $[0.665,0.245,0.090]$이 된다. 실제 모델에서는 vocabulary 전체에 대해 계산한다. 이 분포를 얻는 것까지가 한 번의 예측이고, 어떤 토큰을 선택할지는 다음 단계에서 정한다.

입력 embedding과 LM head는 모양이 전치(transpose) 관계여서 가중치를 공유하는 weight tying도 가능하다. 기준 모델인 Llama 3는 그림처럼 별도 가중치를 쓴다.[^implementation]

### 2-5. 다음 토큰 학습

학습에서는 데이터에 있는 실제 앞선 토큰을 조건으로 주고 다음 토큰의 확률을 높인다. 이를 teacher forcing이라고 한다. §2-4의 각 행을 하나씩 다음 토큰 정답과 비교하면, 유효한 예측 위치에 대한 cross-entropy loss를 계산할 수 있다.

$$
\mathcal{L}_{\mathrm{NTP}}=-\frac{1}{N}\sum_{i=1}^{N}\log p_\theta(t_{i+1}\mid t_{1:i})
$$

여기서 $N$은 채점하는 위치 수이며 padding 등 제외할 위치는 세지 않는다. 예를 들어 정답 토큰이 `␠맑`이라면, 그 토큰에 준 확률이 높을수록 해당 위치의 loss는 작아진다. Loss를 역전파하면 embedding·decoder·LM head의 가중치가 갱신된다. 정수 ID와 tokenizer의 병합 규칙을 이 gradient로 바꾸는 것은 아니다.

Causal mask 덕분에 여러 위치를 한 번의 forward에서 계산하면서도 각 위치는 뒤의 정답을 미리 볼 수 없다. 학습 시에는 정답 시퀀스가 이미 있으므로, 앞 위치에서 새 토큰을 뽑을 때까지 기다릴 필요가 없다. 학습 데이터의 구성과 pre-training 절차는 이번 주의 pre-training 노트에서 이어간다.

## 3. 생성과 rollout

### 3-1. Greedy와 sampling

가장 높은 점수의 토큰을 고르는 방식이 greedy decoding이고, 확률에 따라 뽑는 방식이 sampling이다. 도입 예문에서 greedy는 `␠맑`을 고른다. Sampling은 같은 모델 출력에서도 `␠흐`나 `␠비`를 고를 수 있다.

### 3-2. Sampling parameter

Temperature $T>0$는 softmax 전에 logits를 나누어 분포의 집중도를 조절한다.

$$
p_T(v)=\frac{\exp(z_v/T)}{\sum_u\exp(z_u/T)}
$$

$T$가 작을수록 큰 logit에 확률이 집중된다. $T=0$을 이 식에 대입하지는 않는다. 구현에서 temperature 0을 greedy 선택의 의미로 받는 경우가 있다. Top-k는 상위 $k$개, top-p는 누적 확률이 기준에 도달하는 최소 후보 집합을 남기고 확률의 합이 1이 되도록 다시 정규화(renormalization)한다.[^nucleus]

같은 logits $[2,1,0]$에서도 설정에 따라 실제로 뽑는 분포가 달라진다. 아래 값은 도입 그림의 세 후보만 놓고 계산한 예다. 각 행은 별도 설정이며, top-k와 top-p 예시는 $T=1$을 사용한다.

| 설정 | `␠맑` | `␠흐` | `␠비` | 효과 |
|---|---|---|---|---|
| $T=1$ | 66.5% | 24.5% | 9.0% | 원래 softmax 분포 |
| $T=0.5$ | 86.7% | 11.7% | 1.6% | 높은 점수에 더 집중 |
| $T=2$ | 50.6% | 30.7% | 18.6% | 낮은 점수의 후보도 더 자주 선택 |
| Top-k, $k=2$ | 73.1% | 26.9% | 0% | 후보 수를 두 개로 제한 |
| Top-p, $p=0.8$ | 73.1% | 26.9% | 0% | 누적 확률 80%에 도달하려면 앞의 두 후보가 필요 |

Top-k는 후보 수를 고정하지만, top-p는 그 시점의 분포에 따라 남기는 후보 수가 달라진다. Temperature를 높인다고 응답 품질이 반드시 좋아지는 것은 아니다. 더 다양한 토큰을 시도하는 효과와 낮은 확률의 부적절한 토큰을 고를 가능성을 함께 보아야 한다.

생성 API에는 이 밖에도 반복을 억제하는 penalty나 생성 길이·종료 조건을 정하는 parameter가 있다. 이번에는 **분포를 바꾸는 설정**과 **언제 생성을 멈추는지 정하는 설정**을 구분하면 된다. 지원 항목과 여러 설정을 적용하는 순서는 구현마다 다를 수 있다.

### 3-3. 생성 루프


선택한 token ID를 기존 ID 열 뒤에 붙이면 다음 예측의 조건이 된다. 도입 예문은 이후 다음처럼 이어질 수 있다.

```
오늘 부산의 날씨는 맑       → 습니다
오늘 부산의 날씨는 맑습니다 → 종료 토큰
```

이 분할과 출력도 교육용 예시다. 실제 문자열은 ID에 대응하는 바이트 조각을 이어 붙여 복원하며, 한 토큰이 항상 한 단어나 완성된 글자인 것은 아니다.

정해진 종료 토큰이나 길이 제한에 도달하면 생성을 멈춘다. 효율적인 구현에서는 과거 위치의 key와 value를 KV(key–value) cache에 보관해 재사용한다. 캐시는 이전 계산을 반복하는 비용을 줄이며, 새로 선택한 토큰을 조건에 추가한다는 원리는 같다.

### 3-4. RL의 rollout

이후 post-training의 강화학습(reinforcement learning, RL)에서는 모델을 <strong>다음 토큰을 선택하는 정책(policy)</strong>으로 본다. 프롬프트와 지금까지 생성한 토큰이 현재 문맥이고, 다음 토큰을 고르는 것이 행동(action)에 해당한다. 이 정책으로 토큰을 차례로 생성해 응답을 얻는 과정이 rollout이다. 여기서는 도구 호출 없이 텍스트 응답 하나를 생성하는 경우를 생각한다.

Rollout은 §3-3의 생성 루프를 학습에 사용할 경험을 모으는 데 쓰는 것이다. 예를 들어 InstructGPT의 RL 단계에서는 현재 정책으로 응답을 생성하고, reward model이 응답을 평가하며, 그 신호를 이용해 정책을 업데이트한다.[^instructgpt]

| 단계 | 하는 일 |
|---|---|
| Rollout | 현재 정책으로 프롬프트에 대한 응답 생성 |
| 평가 | 생성한 응답에 보상(reward) 부여 |
| 업데이트 | 수집한 응답과 보상으로 정책의 가중치 학습 |

**응답을 생성하는 것 자체가 가중치 업데이트는 아니다.** Sampling 설정을 바꾸면 수집되는 응답의 분포가 달라지므로 RL이 학습할 경험도 달라진다. 따라서 rollout에서는 어떤 정책과 sampling 설정으로 데이터를 생성했는지가 중요하다. 보상을 정의하고 업데이트하는 구체적인 방법은 post-training에서 다룬다.

6주차 inference에서는 이 생성 루프를 바탕으로 KV cache·메모리·처리량 등 실행 효율을 살펴본다.
