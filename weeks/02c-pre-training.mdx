Decoder-only LLM은 앞부분을 보고 다음 토큰을 예측하는 방식으로 학습할 수 있다. 그렇다면 **모델을 학습시킬 때 어떤 문서를 사용해야 할까?** 웹 문서·책·코드 중 무엇을 얼마나 섞을지, 문서를 어떤 길이의 학습 샘플로 만들지에 따라 모델이 접하는 문맥이 달라진다. 이 노트에서는 Zhao 등의 LLM 서베이[^survey]를 참고해 pre-training의 데이터 구성과 학습 목표, 학습 설정을 살펴본다.

## 1. LLM 학습 과정

우리가 사용하는 대화 모델(chat model)은 대규모 텍스트 모음인 말뭉치로 학습한 직후의 기본 모델(base model)과 구분할 필요가 있다. 대표적인 개발 흐름은 다음과 같다. **모든 모델이 같은 단계나 순서를 따르는 것은 아니며**, 데이터를 보강하고 평가하면서 여러 번 반복하기도 한다.

| 구분 | 대표적인 데이터 | 학습에서 바꾸려는 것 |
|---|---|---|
| Pre-training | 문서·코드 등 대규모 말뭉치 | 다양한 문맥의 다음 토큰을 예측하는 기반 능력 |
| Post-training: SFT(supervised fine-tuning) | 지시와 응답, 대화 예시 | 원하는 입력 형식에서 적절한 응답을 생성하는 행동 |
| Post-training: 선호도 학습(preference learning) | 응답 선호도, 검증 가능한 보상, 상호작용 결과 | 여러 가능한 응답 중 목적에 더 맞는 행동을 강화 |

위 표는 목적에 따른 큰 구분이다. 실제 개발에서는 각 구간을 더 잘게 나누고, 모델 크기에 따라 서로 다른 경로를 사용하기도 한다. **Qwen3**는 pre-training에서 일반적인 지식을 익힌 뒤 수학·코드 등의 데이터 비중을 높인다. 마지막에는 **긴 문서로 구성한 학습 데이터를 사용하고, 학습 시퀀스 길이를 4,096에서 32,768 토큰으로 늘려** 긴 문맥을 다루도록 추가 학습한다. 이때 토큰의 위치 정보를 반영하는 **RoPE**(rotary position embedding)의 설정도 긴 문맥에 맞게 함께 조정한다.[^qwen3]
Post-training에서는 대형 모델을 여러 단계로 개선하고, 그 모델을 teacher로 활용해 소형 student 모델에 능력을 전달한다. 이를 <strong>distillation(지식 증류)</strong>이라고 한다.[^qwen3]

그림의 위쪽이 이 노트에서 살펴볼 **pre-training**이다. 아래쪽의 RL과 distillation은 post-training의 세부 방법이다. 특히 **on-policy distillation**에서는 student가 직접 생성한 응답의 각 문맥에서 teacher의 다음 토큰 확률 분포를 따라가도록 학습한다. Teacher가 만들어 둔 응답을 학습하는 off-policy 단계와, **누가 학습에 사용할 응답을 생성하는가**에서 차이가 난다.<Sidenote>후속 연구인 *MOPD*는 영역별로 강화학습한 여러 teacher의 능력을 하나의 student에 모으는 multi-teacher on-policy distillation을 다룬다.[^mopd]</Sidenote>

지금은 각 방법을 모두 이해하기보다, **pre-training과 post-training 각각에 여러 단계와 데이터 선택이 들어간다**는 점을 보자.

## 2. Objective function

### 2-1. 세 구조의 사전학습

1주차에서 본 구조와 대표적인 학습 목표를 정리하면 다음과 같다. 구조와 목적함수는 설계상 별개이므로 아래 연결이 가능한 조합의 전부는 아니다.

| 구조 | 문맥을 읽는 방식 | 대표적인 사전학습 objective function |
|---|---|---|
| Encoder-only | 양방향으로 참조 | BERT의 MLM(masked language modeling) |
| Decoder-only | 현재 위치와 이전 위치 참조 | GPT의 NTP(next token prediction) |
| Encoder-decoder | 입력을 양방향으로 읽고 출력은 순차 생성 | T5의 span corruption |

### 2-2. 입력과 정답

이제 decoder-only의 NTP(next-token prediction)에 집중한다. 가상 토큰열 (학습 문서) `[BOS, 부산, 항구, EOS]`를 보자. BOS(beginning of sequence)와 EOS(end of sequence)는 문서 시작·종료를 표시하는 special token이다. 입력을 한 칸 오른쪽의 정답과 짝지으면 다음과 같다.

| 위치 | 입력 토큰 | 참조 가능한 문맥 | 정답 |
|---|---|---|---|
| 0 | BOS | BOS | 부산 |
| 1 | 부산 | BOS, 부산 | 항구 |
| 2 | 항구 | BOS, 부산, 항구 | EOS |

Teacher forcing으로 세 위치를 함께 계산한 뒤에는 **어느 정답을 채점하고, 몇 개의 정답으로 평균할 것인가**를 정한다. 위 예제에서 세 정답을 모두 채점한다면, 세 위치의 loss를 더해 3으로 나눈다.

### 2-3. NTP 목적함수

데이터의 토큰열을 $t_1,\ldots,t_T$라고 하면 각 위치에서 앞선 토큰들을 조건으로 다음 토큰에 확률을 준다.

$$
p_\theta(t_{1:T})=p_\theta(t_1)\prod_{i=2}^{T}p_\theta(t_i\mid t_{<i})
$$

이 식은 <strong>결합확률(joint probability)을 조건부 확률의 곱으로 표현하는 확률의 연쇄법칙(chain rule)</strong>이다. 앞선 토큰에 따라 다음 토큰의 확률이 달라지므로 문맥을 조건으로 남겨 둔다.

위의 `[BOS, 부산, 항구, EOS]` 예시에 적용해 보자.

$$
\begin{aligned}
p_\theta(\mathrm{BOS})\times p_\theta(\text{부산}\mid\mathrm{BOS})\times p_\theta(\text{항구}\mid\mathrm{BOS},\text{부산})\times p_\theta(\mathrm{EOS}\mid\mathrm{BOS},\text{부산},\text{항구})
\end{aligned}
$$

우리는 **관측된 문서(학습 데이터)들을 잘 설명하는 확률 모델을 찾는 것**을 학습 기준으로 삼는다.
여기서 관측한 토큰열 $t_{1:T}$는 고정하고, 가중치 $\theta$를 바꾸어 가며 $p_\theta(t_{1:T})$를 비교한다. 이처럼 **주어진 데이터를 얼마나 잘 설명하는지를 본 값**이 우도(likelihood)다. 이를 크게 만드는 모델 가중치(weight, parameter)를 찾는 방법이 **최대우도추정**(maximum likelihood estimation, MLE)이다.

예를 들어 `BOS, 부산` 다음에 실제로 `항구`가 관측되었다면, 다른 조건이 같을 때 `항구`에 0.1보다 0.4의 확률을 주는 모델이 이 관측을 더 잘 설명한다. 다만 이 한 문장만의 확률을 높이는 것이 목적은 아니다. **전체 학습 문서에 대한 log likelihood의 합을 최대화**해 여러 문맥을 함께 설명하도록 모델 가중치를 조정한다.

최적화에서는 보통 최소화할 loss를 사용하므로 <strong>우도에 음의 로그(negative log likelihood)</strong>를 취한다. 로그는 확률의 크기 순서를 유지하고, 음수 부호는 최대화 문제를 최소화 문제로 바꾼다. 또한 위의 조건부 확률들의 곱이 로그의 합으로 바뀌므로, 결국 각 위치에서 관측된 다음 토큰의 음의 로그 확률을 더하게 된다. 이를 유효한 정답 토큰 수로 평균하면 다음 목적함수를 얻는다.

$$
\mathcal{L}=-\frac{1}{\sum_i m_i}\sum_i m_i\log p_\theta(t_i\mid t_{<i})
$$

$m_i$는 해당 정답 위치를 loss에 포함하면 1, 제외하면 0인 mask다. 이 식은 데이터에 실제로 나타난 토큰에 낮은 확률을 줄수록 큰 벌점을 준다.
여러 문서나 배치를 합칠 때도 **loss의 합과 유효 정답 수를 각각 합친 뒤 나누어야** 한다.

NTP의 정답은 문서 자체에서 얻는다. 사람이 문장마다 별도 라벨을 붙일 필요가 없다는 점이 활용하는 데 유리하다. 반면, 동시에 데이터의 오류·반복·편향도 학습 신호가 될 수 있다는 위험이 있다. 그렇기에 우리는 **데이터의 품질**을 위해 많은 노력을 해야 한다.
## 3. 학습 데이터

실제 모델의 데이터 구성에서 출발해 수집한 문서를 선별하고, 학습할 비율을 정하고, 입력 시퀀스로 만드는 과정을 살펴보자.

### 3-1. 데이터 구성과 분포

먼저 실제 공개 말뭉치를 보자. Allen AI의 **OLMo 2**의 기본 pre-training 데이터인 OLMo Mix 1124는 웹 문서에 코드·논문·수학·백과 자료를 더한 구성이다. 아래는 공식 데이터 카드가 공개한 데이터 풀의 규모다. B는 10억 (1,000,000,000), T는 1조 (1,000,000,000,000) 토큰을 뜻한다.[^olmo2][^olmo-data]

| 데이터 출처 | 주요 내용 | 데이터 풀의 토큰 수 |
|---|---|---|
| DCLM-Baseline | 웹 문서 | 3.70T |
| StarCoder | 코드 | 83.0B |
| peS2o / arXiv | 학술 문서 | 58.6B / 20.8B |
| OpenWebMath / Algebraic Stack | 수학 관련 웹 문서·코드 | 12.2B / 11.8B |
| Wiki | 백과 자료 | 3.66B |

큰 웹 말뭉치가 다양한 문맥을 제공하고, 별도의 출처가 코드·수학·학술 내용을 보강하는 모습을 볼 수 있다. 다만 **데이터 풀에 저장된 양과 학습 중 읽히는 양은 다를 수 있다**(3-3절 참고). 일부 자료를 더 자주 선택하거나 후반에 구성을 바꿀 수 있기 때문이다. OLMo 2도 후반 학습에는 별도의 혼합 비율을 사용한다.[^olmo2]

이 영어 중심 구성을 한국어 모델에 그대로 적용할 수는 없다. 카카오의 **Kanana**는 영어·한국어 웹, 학술 문서, 코드, 백과사전, instruction 자료를 구분해 구성했다. 다만, 한국어 능력을 목표로 한다고 영어 자료의 비중을 무조건 줄일 필요는 없다. Kanana Technical Report는 한국어 데이터 조건을 유지하면서 영어 데이터의 품질을 높였을 때 한국어 benchmark 점수도 개선되었다.[^kanana]

자료를 모을 때는 출처, 수집 시점, 이용 조건, 처리 이력을 함께 기록한다. 그래야 모델의 성능 변화가 어느 데이터 선택과 연결되는지 추적할 수 있다.

### 3-2. 추출·필터링·중복 제거

수집한 웹 페이지에는 본문뿐 아니라 메뉴·광고·반복 문구가 섞여 있다. 코드도 복제본이나 자동 생성 파일을 포함할 수 있다. **FineWeb**은 이런 웹 데이터를 pre-training 말뭉치로 만드는 추출·필터링·중복 제거 선택을 실험으로 비교한 자료다.[^fineweb] 이 절에서는 FineWeb의 관점에 실제 모델 개발 사례를 연결한다.

**본문 추출**은 메뉴와 본문을 구분하고, 표나 코드의 구조를 얼마나 보존할지 정해야 한다. 줄바꿈을 모두 없애면 일반 산문은 읽을 수 있어도 코드의 의미가 달라질 수 있다.

Llama 3는 수학·코드의 구조를 보존하는 추출 방식을 사용하고, 해당 영역에 맞는 필터를 따로 구성했다.[^llama] Qwen3는 Qwen2.5-VL로 PDF 형태 문서에서 텍스트를 추출하고 Qwen2.5로 정제했다.[^qwen3] 같은 내용을 담은 자료라도 HTML, PDF, 소스 파일 중 어떤 형태인지에 따라 추출 방법이 달라진다.

**품질 필터링**은 문서 길이, 반복 비율, 언어 판별 점수나 학습된 분류기 등을 사용할 수 있다. 기준을 강하게 하면 잡음을 줄일 수 있지만, 짧은 질의응답이나 소수 언어의 정상 문서를 제거할 수도 있다. 필터 통과율만 보지 말고 빠진 문서의 표본을 직접 읽어야 한다.

Kanana는 영어와 한국어에 서로 다른 품질 필터를 적용했고, 한국어에는 교육적 품질 분류기를 별도로 만들었다.[^kanana] **SmolLM2**의 Stack-Edu는 코드의 교육적 품질을 기준으로 선별하되 프로그래밍 언어별 분류기를 사용한다. 실제 비교에서 Java는 다른 언어들과 다른 임계값이 유리했다.[^smollm2] 품질 점수는 하나의 보편적인 기준이라기보다, 어떤 자료를 남겨 어떤 능력을 키울지에 관한 선택이다.

<strong>중복 제거(deduplication)</strong>는 같은 문서의 여러 URL, 조금씩 바뀐 복제 페이지, 문서 내부의 긴 반복 구간을 다룬다. 완전 일치(exact duplicate)와 내용이 조금씩 다른 근접 중복(near duplicate)은 다른 문제다. Lee 등의 연구는 중복 제거를 암기된 텍스트 생성 및 train–test 중복과 연결해 분석한다.[^dedup] Llama 3는 URL·문서·줄 수준에서 중복을 제거한다.[^llama] 동일한 예제가 많이 수집되었다고 해서 새로운 학습 내용이 그만큼 늘어난 것은 아니다.

<strong>평가 데이터 오염(benchmark contamination)</strong>은 학습 데이터에 benchmark 문제나 해설이 들어 있는 경우다. 문자열 일치로 찾을 수 있는 중복도 있지만 번역·의역된 유출은 더 어렵다. “검사에서 발견하지 못했다”는 결과만으로 오염이 없다고 단정하지 않는다.

EXAONE 3.5는 평가 자료를 정규화하고 부분 문자열을 대조하는 오염 제거 과정을 공개했다.[^exaone35] 예를 들어 코드 평가 문제와 그 풀이를 학습 데이터에 넣으면, 테스트를 통과한 이유가 새로운 문제 해결 능력인지 익숙한 풀이의 재현인지 구분하기 어려워진다. 일반적인 중복 제거와 평가 자료에 대한 별도 대조가 모두 필요한 이유다.

선별 후 부족한 자료는 모델로 생성하는 <strong>합성 데이터(synthetic data)</strong>로 보완할 수도 있다. Qwen3는 기존 모델들로 교재·질의응답·코드 조각 등을 생성했다.[^qwen3]

### 3-3. 데이터 혼합과 반복 노출

문서가 저장된 비율과 학습에서 선택하는 비율은 다를 수 있다. 여러 출처의 데이터를 섞는 데이터 혼합(data mixing)을 말뭉치의 문서 수 대신 **모델이 소비하는 토큰의 비율**로 설명하면 계산 예산과 연결하기 쉽다.

SmolLM2의 한 학습 단계는 영어 웹 75%, 코드 20%, 수학 5%로 구성된다. 그중 영어 웹 내부에서는 FineWeb-Edu와 DCLM을 60:40으로 섞었다.[^smollm2]
그리고 중복 제거 후 데이터가 5M 토큰인 묶음에 대해, 15M 토큰을 소비하기 위해 평균적으로 약 세 번 반복 노출이 된다.

혼합 비율은 어떻게 선택할까? Llama 3는 학습 중간의 8B 모델에 후보 데이터 30%와 기존 혼합 70%를 넣어 짧은 후반 학습 실험을 했다.[^llama] SmolLM2도 웹 데이터 비율과 코드 데이터 교체를 비교했다.[^smollm2] 처음부터 전체 학습을 반복하기 전에 **후보 구성이 목표 능력을 개선하는지 작은 규모로 확인**하는 것이다.

예를 들어 위 구성을 기준으로, 총 토큰 수와 학습 설정은 유지한 채 영어 문서의 5%p를 한국어 기술 설명 묶음으로 옮긴 후보를 비교할 수 있다. 한국어 문서 이해, 코드의 테스트 통과율, 한국어 설명과 코드의 일치 여부를 각각 살펴본다. 여러 후보를 고르는 데 쓰는 검증 자료와 최종 성능을 보고할 평가 자료도 구분한다.

혼합은 학습 도중에도 바뀔 수 있다. **EXAONE 3.0**은 일반 영역 중심의 6T 토큰 학습 이후 전문 영역의 비중을 높여 2T 토큰을 추가 학습했다.[^exaone3] 우리 예시에서도 후반에 한국어 기술 자료를 더 읽히는 후보를 생각할 수 있다. 다만 반복 노출이 늘고 다른 능력이 약해질 수 있으므로, 한국어·코드뿐 아니라 일반 영역의 평가도 함께 유지해야 한다.

### 3-4. 학습 시퀀스와 문서 경계

선별과 혼합이 끝나면 문서를 실제 모델 입력으로 만들어야 한다. 우리 예시의 한국어 튜토리얼에서는 설명과 해당 코드가 같은 문맥에 남도록 구간을 나누는 것이 도움이 될 수 있다. 반면 서로 무관한 두 튜토리얼을 한 배열에 넣을 때는 문서 사이의 경계를 어떻게 처리할지 정해야 한다.

문서의 길이는 제각각이지만 모델은 한 번에 처리할 수 있는 context 길이가 정해져 있다. 따라서 말뭉치의 문서와 학습에 넣는 시퀀스가 항상 일대일로 대응하지는 않는다. 긴 문서를 여러 구간으로 나누거나, 짧은 문서를 이어 붙여 일정 길이의 시퀀스를 만들 수 있다. Megatron Core의 GPTDataset은 샘플이 문서 경계를 넘으면 여러 문서의 토큰을 이어 가져오고, 입력과 정답을 한 칸 차이로 구성할 수 있다.[^gpt-data]

여기서 **배열에서 이웃한 두 문서를 서로의 문맥으로 사용할 것인지**는 별도로 정해야 한다. EOS는 문서 종료를 표시하는 토큰이지 attention을 자동으로 끄는 명령이 아니다.

DeepSeek-V3는 문서를 묶는 packing을 사용하면서 샘플 간 attention은 차단하지 않는다고 명시한다.[^deepseek3] 반면 문서별 attention을 분리하는 구성도 가능하다. 아래의 두 방식은 실제로 선택해야 하는 학습 설정이다.

| 문서 경계 처리 | 뒤 문서가 읽는 문맥 | 학습 데이터의 의미 |
|---|---|---|
| 이어진 causal stream | 현재 배열에 있는 앞 문서까지 참조 가능 | 문서 경계를 포함한 토큰 흐름을 이어 쓰기 |
| 문서별 attention 분리 | 자기 문서의 앞선 토큰만 참조 | 여러 문서를 같은 배열에 담아도 각 문서를 독립적으로 학습 |

독립적인 문서를 학습하려면 입력·정답도 문서별로 맞춘다. §2-2의 문서를 A로 놓고, 한 토큰 더 긴 문서 B를 함께 담아 보자. 아래는 실제 tokenizer 출력이 아닌 교육용 토큰이다. 위쪽 네 행은 같은 위치의 입력·정답·위치 번호·loss mask이고, 아래 행렬은 그 입력 위치들 사이의 attention 허용 범위다.

<Figure src={packedDocuments.src} alt="문서 A 입력은 BOS·부산·항구, 정답은 부산·항구·EOS다. 문서 B 입력은 BOS·코드·실행·완료, 정답은 코드·실행·완료·EOS다. 위치 번호는 0,1,2,0,1,2,3이고 loss mask는 모두 1이다. A의 마지막 입력 `항구`는 EOS를 예측하고, B의 첫 입력 BOS는 `코드`를 예측한다. 배열을 붙여 저장해도 A의 마지막 정답은 그대로 EOS다. 이 그림은 문서별 attention을 분리하고 위치 번호도 문서마다 다시 시작하는 구성을 택했다.

이어진 causal stream이라면 B의 행에서 A0–A2도 허용한다. 이 차이는 EOS의 존재 자체가 아니라 attention 설정이 만든다. Position ID는 각 입력의 위치 번호로, 이 예제에서는 `[0,1,2,0,1,2,3]`이다. Attention mask와 위치 번호는 별도 설정이며, 위치 번호만 다시 시작해도 다른 문서가 가려지는 것은 아니다.

<Callout type="note">
Attention mask는 **어디를 볼 수 있는가**, loss mask는 **어디의 예측을 채점하는가**를 정한다. 어떤 위치를 loss에서 제외하는 것만으로 서로 다른 문서의 attention이 차단되지는 않는다.
</Callout>

## 4. 학습과 평가

### 4-1. 가중치 갱신

한 배치를 학습하는 순서는 다음과 같다.

```
입력·정답·mask 준비
  → forward로 위치별 logits 계산
  → 유효한 정답 위치의 cross-entropy 평균
  → backward로 gradient 계산
  → optimizer가 가중치 갱신
  → 다음 배치
```

Learning rate는 가중치 갱신의 크기를 조절한다. 가장 단순한 SGD(stochastic gradient descent)는 $\theta\leftarrow\theta-\eta g$로 쓸 수 있다. 가중치 하나가 1.0, gradient가 0.2, learning rate $\eta$가 0.1이라면 새 값은 0.98이다. 실제 모델에서는 이 계산을 수많은 파라미터에 적용한다.

대표적인 optimizer인 AdamW는 현재 gradient 하나만 사용하는 대신, 각 파라미터에 두 상태를 유지한다. 학습 step을 $s$, 그 step의 gradient를 $g_s$라고 하자.[^adamw]

$$
m_s=\beta_1m_{s-1}+(1-\beta_1)g_s,\qquad
v_s=\beta_2v_{s-1}+(1-\beta_2)g_s^2
$$

$\beta_1,\beta_2$는 0 이상 1 미만의 계수로, 클수록 과거 상태를 오래 반영한다. $m_s$는 gradient의 지수이동평균(exponential moving average)이고, $v_s$는 제곱 gradient의 지수이동평균이다. 첫째는 최근 갱신 방향을, 둘째는 최근 gradient 크기의 척도를 담는다. $v_s$는 평균을 뺀 분산 자체는 아니다. 두 상태는 가중치 하나마다 하나씩 있으므로, 파라미터가 8B개면 상태 값은 총 16B개다.

초깃값 0의 영향을 보정한 값을 $\hat m_s,\hat v_s$라고 하면 AdamW의 갱신은 다음처럼 쓸 수 있다. 제곱·나눗셈·제곱근은 원소별 연산이다.

$$
\theta_s=(1-\eta_s\lambda)\theta_{s-1}
-\eta_s\frac{\hat m_s}{\sqrt{\hat v_s}+\epsilon}
$$

$\lambda$는 weight decay 계수, $\epsilon$은 분모의 수치 안정화를 위한 작은 양수다. Weight decay는 가중치를 줄이는 항이고, gradient 기반 항과 분리해 적용한다. 어떤 파라미터에 decay를 적용할지도 설정한다.

<Details summary="Adam의 초기 상태 보정과 숫자 예제">

상태를 0으로 시작하면 초기 평균이 작아지는 효과가 있어 $\hat m_s=m_s/(1-\beta_1^s)$, $\hat v_s=v_s/(1-\beta_2^s)$로 보정한다. 교육용으로 $g_1=0.2$, $\beta_1=0.9$, $\beta_2=0.99$라면 $m_1=0.02$, $v_1=0.0004$, 보정 후에는 $\hat m_1=0.2$, $\hat v_1=0.04$다. $\epsilon$과 weight decay를 생략하면 비율은 $0.2/\sqrt{0.04}=1$이다. Learning rate가 0.01이면 가중치 1.0은 약 0.99가 된다. 이는 계산을 보여주는 예이며 권장 hyperparameter가 아니다.

</Details>

학습 초기에는 learning rate를 낮게 시작해 점차 높이는 **warmup**을 사용하기도 한다. 학습 후반의 **decay**는 갱신 폭을 줄인다. **Gradient clipping**은 gradient norm이 임계값을 넘으면 gradient를 같은 방향으로 축소한다. AdamW처럼 상태를 이용하는 optimizer에서는 이것을 최종 가중치 변화량의 직접적인 상한으로 해석하지 않는다. 세 방법은 역할이 다르므로 하나가 다른 하나를 대신하지 않는다. 실제 recipe를 읽을 때에는 learning rate뿐 아니라 전체 학습 길이, batch 크기, warmup 길이를 함께 확인한다.

예를 들어 gradient가 $(3,4)$라면 norm은 5다. 임계값을 1로 정한 norm clipping은 두 성분에 $1/5$를 곱해 $(0.6,0.8)$로 만든다. Warmup·decay가 **step에 따라 learning rate를 바꾸는 것**이라면, clipping은 **현재 gradient의 크기에 따라 적용하는 것**이다.

학습률 곡선도 숫자로 읽어 보자. 교육용으로 총 1,000번 갱신하고, 처음 100 step에서 0부터 최대 학습률까지 선형으로 올린 뒤 마지막까지 선형으로 내린다고 정할 수 있다. 50 step에서는 최대값의 절반, 100 step에서는 최대값, 550 step에서는 다시 절반이다. 실제 recipe는 cosine decay나 최솟값을 두는 방식도 사용한다. 같은 토큰 수라도 batch 크기가 바뀌면 optimizer step 수가 바뀌므로, warmup을 step과 token 중 어느 단위로 지정했는지 확인한다.

### 4-2. 검증 지표

Training loss가 줄어드는 것만으로는 충분하지 않다. 적어도 서로 다른 질문을 나누어 본다.

| 관측 | 답하려는 질문 |
|---|---|
| Training loss | 학습 데이터의 정답 토큰을 더 잘 맞히는가? |
| Held-out loss | 학습에 넣지 않은 같은 종류의 텍스트에도 일반화하는가? |
| 도메인별 평가 | 한국어·코드 등 목표한 능력이 개선되는가? |
| 생성 결과 표본 | 반복·형식 오류·데이터 암기 같은 문제가 보이는가? |

Perplexity는 평균 NTP loss를 지수화한 값이다. 위의 loss 1.040 예제라면 $\exp(1.040)\approx2.83$이다. 낮을수록 정답에 더 높은 확률을 준다는 의미지만, **서로 다른 tokenizer의 토큰 단위 perplexity는 곧바로 비교하지 않는다**. 토큰 단위와 평가 텍스트, 문맥 길이, mask 조건을 맞춰야 한다.[^perplexity]

매 위치에서 네 후보에 각각 $1/4$의 확률을 주고 정답이 그중 하나라면, loss는 $-\log(1/4)=\log4$, perplexity는 4다. 일반적인 경우에는 정답 확률 역수의 기하평균으로 볼 수 있다. 따라서 2.83이라는 값이 실제로 후보를 2.83개 남겼다는 뜻은 아니다.

평가할 때는 배치별 perplexity를 산술평균하지 않는다. 각 배치의 음의 로그 확률 합과 유효 정답 수를 전체에 걸쳐 합산하고, 그 평균 loss를 마지막에 지수화한다. 긴 평가 문서를 짧은 독립 구간으로 자르면 구간 시작에서 앞 문맥을 잃는다. 겹치는 window를 사용하면 앞 문맥을 더 보존할 수 있지만, 겹친 정답을 중복 채점하지 않도록 mask를 정해야 한다.[^perplexity]

데이터 구성과 검증 방법을 정해도 모델 크기와 학습 기간은 아직 선택해야 한다. 같은 계산 예산으로 큰 모델을 짧게 학습할지, 작은 모델에 더 많은 토큰을 읽힐지가 scaling의 문제다.
