다음 토큰의 정답은 문서 자체에서 얻을 수 있다. 그렇다면 문서를 많이 모으기만 하면 좋은 모델이 될까? Zhao 등의 LLM(large language model) 서베이가 구분하는 데이터 준비·목적함수(objective function)·학습 설정[^survey]을 따라 이 질문을 살펴본다. 중심은 **어떤 텍스트를 어떤 비율로 어떤 학습 샘플에 담는가**다.

## 1. LLM 학습 과정

우리가 사용하는 대화 모델은 대규모 텍스트 모음인 말뭉치(corpus)로 학습한 직후의 모델과 구분할 필요가 있다. 대표적인 개발 흐름은 다음과 같다. 모든 모델이 같은 단계나 순서를 따르는 것은 아니며, 데이터를 보강하고 평가하면서 여러 번 반복하기도 한다.

| 구분 | 대표적인 데이터 | 학습에서 바꾸려는 것 |
|---|---|---|
| Pre-training | 문서·코드 등 대규모 말뭉치 | 다양한 문맥의 다음 토큰을 예측하는 기반 능력 |
| Post-training: SFT(supervised fine-tuning) | 지시와 응답, 대화 예시 | 원하는 입력 형식에서 적절한 응답을 생성하는 행동 |
| Post-training: 선호도 학습(preference learning)·RL(reinforcement learning) | 응답 선호도, 검증 가능한 보상, 상호작용 결과 | 여러 가능한 응답 중 목적에 더 맞는 행동을 강화 |

필요하면 base model에 특정 언어·도메인 데이터를 더 학습하는 **continued pre-training**을 수행한다. 모든 모델에 필수인 별도 단계는 아니다. Post-training 안에서도 SFT와 선호도 학습·RL을 어떤 순서와 조합으로 사용할지는 달라진다.

Pre-training을 마친 **base model**은 텍스트를 이어 쓰는 모델이다. 질문 뒤에 답변을 쓸 수도 있지만, 질문을 반복하거나 시험지의 다음 문제를 이어 쓸 수도 있다. SFT는 원하는 응답 예시를 학습에 사용한다. 둘 다 next-token loss를 사용할 수 있으나 데이터 분포와 loss를 적용하는 구간이 다르다.

위 표는 목적에 따른 큰 구분이다. 실제 개발에서는 각 구간을 더 잘게 나누고, 모델 크기에 따라 서로 다른 경로를 사용한다. **Qwen3**는 pre-training에서 일반적인 지식을 익힌 뒤 수학·코드 등의 데이터 비중을 높이고, 마지막으로 긴 문맥을 다루도록 학습한다. Post-training에서는 대형 모델을 여러 단계로 개선하고, 그 모델을 teacher로 활용해 소형 student 모델에 능력을 전달한다. 이를 **distillation(지식 증류)**이라고 한다.[^qwen3]

그림의 위쪽이 이 노트에서 살펴볼 **pre-training**이다. 아래쪽의 RL과 distillation은 post-training의 세부 방법이다. 특히 **on-policy distillation**에서는 student가 직접 생성한 응답의 각 문맥에서 teacher의 다음 토큰 확률 분포를 따라가도록 학습한다. Teacher가 만들어 둔 응답을 학습하는 off-policy 단계와, **누가 학습에 사용할 응답을 생성하는가**에서 차이가 난다.<Sidenote>후속 연구인 *MOPD*는 영역별로 강화학습한 여러 teacher의 능력을 하나의 student에 모으는 multi-teacher on-policy distillation을 다룬다. Qwen3 보고서의 distillation과 구분되는 확장 사례다.[^mopd]</Sidenote>

지금은 각 방법을 모두 이해하기보다, **pre-training과 post-training 각각에 여러 단계와 데이터 선택이 들어간다**는 점을 보자. Qwen3의 원래 post-training 그림은 [보고서 Figure 1](https://arxiv.org/html/2505.09388v1#S4.F1)에서 확인할 수 있다.

## 2. 학습 목표

### 2-1. 세 구조의 사전학습

1주차에서 본 구조와 대표적인 학습 목표를 정리하면 다음과 같다. 구조와 목적함수는 설계상 별개이므로 아래 연결이 가능한 조합의 전부는 아니다.

| 구조 | 문맥을 읽는 방식 | 대표적인 사전학습 목표 |
|---|---|---|
| Encoder-only | 입력 내부에서 양방향으로 참조 | 가린 토큰 복원: BERT의 MLM(masked language modeling) |
| Decoder-only | 현재 위치와 이전 위치 참조 | 다음 토큰 예측: causal language modeling |
| Encoder–decoder | 입력을 양방향으로 읽고 출력은 순차 생성 | 손상된 입력에서 빠진 부분이나 원문 복원: T5 계열 |

### 2-2. 입력과 정답

가상 토큰열 `[BOS, 부산, 항구, EOS]`를 보자. BOS(beginning of sequence)와 EOS(end of sequence)는 문서 시작·종료를 표시하는 special token이다. 입력을 한 칸 오른쪽의 정답과 짝지으면 다음과 같다.

| 위치 | 입력 토큰 | 참조 가능한 문맥 | 정답 |
|---|---|---|---|
| 0 | BOS | BOS | 부산 |
| 1 | 부산 | BOS, 부산 | 항구 |
| 2 | 항구 | BOS, 부산, 항구 | EOS |

Teacher forcing으로 세 위치를 함께 계산한 뒤에는 **어느 정답을 채점하고, 몇 개의 정답으로 평균할 것인가**를 정한다. 위 예제에서 세 정답을 모두 채점한다면, 세 위치의 loss를 더해 3으로 나눈다. Padding이나 학습에서 제외할 구간이 있을 때의 집계 방법을 수식으로 살펴보자.

### 2-3. NTP 목적함수

이제 decoder-only의 NTP(next-token prediction)에 집중한다. 데이터의 토큰열을 $t_1,\ldots,t_T$라고 하면 각 위치에서 앞선 토큰들을 조건으로 다음 토큰에 확률을 준다.

$$
p_\theta(t_{1:T})=\prod_{i=1}^{T}p_\theta(t_i\mid t_{<i})
$$

첫 토큰의 조건은 문서 시작 토큰 등으로 구현할 수 있다. 최대우도 학습(maximum likelihood estimation)은 관측된 토큰열에 높은 확률을 주는 방향으로 가중치 $\theta$를 바꾼다. 음의 로그를 취하면 곱이 합으로 바뀌어 각 위치를 따로 채점할 수 있다.

$$
\mathcal{L}=-\frac{1}{\sum_i m_i}\sum_i m_i\log p_\theta(t_i\mid t_{<i})
$$

$m_i$는 해당 정답 위치를 loss에 포함하면 1, 제외하면 0인 mask다. 유효한 정답이 적어도 하나 있다고 가정한다. 이 식은 데이터에 실제로 나타난 토큰에 낮은 확률을 줄수록 큰 벌점을 준다.

<Callout type="example">
두 위치의 정답 확률이 각각 0.5와 0.25라면 평균 loss는 $-(\log0.5+\log0.25)/2\approx1.040$이다. 두 번째 정답 확률을 0.5로 올리면 약 0.693으로 줄어든다. 여기서 로그는 자연로그이며 단위는 nat이다.
</Callout>

Padding을 포함하면 분모를 어떻게 정하는지도 중요하다. 길이 4의 배열에 실제 정답 세 개와 padding 하나를 담았다고 하자.

| 정답 | 모델이 정답에 준 확률 | loss mask | 음의 로그 확률 |
|---|---|---|---|
| 부산 | 0.5 | 1 | 약 0.693 |
| 항구 | 0.25 | 1 | 약 1.386 |
| EOS | 0.5 | 1 | 약 0.693 |
| padding | 채점하지 않음 | 0 | 제외 |

평균은 $(0.693+1.386+0.693)/3\approx0.924$다. 배열 길이인 4로 나누면 약 0.693이 되어, 예측은 그대로인데 padding을 넣었다는 이유로 loss가 낮아진다. 여러 문서나 배치를 합칠 때도 **loss의 합과 유효 정답 수를 각각 합친 뒤 나누어야** 한다. Padding은 빈 위치를 채우는 표식이며, 그 위치에 대한 계산 자체를 없애는지는 구현에 따라 다르다.

NTP의 정답은 텍스트 자체에서 얻는다. 사람이 문장마다 별도 라벨을 붙일 필요가 적다는 점이 큰 말뭉치를 활용하는 데 유리하다. 동시에 데이터의 오류·반복·편향도 학습 신호가 될 수 있다. **정답을 자동으로 얻는 것과 데이터가 저절로 좋아지는 것은 다른 문제**다.

## 3. 학습 데이터

### 3-1. 데이터 구성과 분포

우리 연구실에서 한국어와 코드를 잘 다루는 모델을 학습한다고 가정하자. 웹 문서가 가장 많다는 이유로 모두 같은 확률로 읽히면, 목표 능력에 필요한 데이터는 드물게 나타날 수 있다. 먼저 모델의 사용 목적과 평가할 도메인을 정하고, 그에 맞춰 데이터의 구성을 살펴야 한다.

| 데이터 유형 | 얻을 수 있는 신호 | 살펴볼 문제 |
|---|---|---|
| 웹 문서 | 다양한 주제와 언어 표현 | 광고·탐색 메뉴·중복·기계 생성 텍스트 |
| 책·논문·교육 자료 | 긴 설명과 구조화된 지식 | 접근·이용 조건, 추출 품질, 도메인 편중 |
| 코드 | 문법과 구조, 문제 해결 패턴 | 생성 파일·복제 저장소·라이선스·비밀정보 |
| 다국어 문서 | 언어별 표현과 지식 | 언어 식별 오류, 언어별 양과 품질 격차 |
| 합성 데이터(synthetic data) | 부족한 유형의 예시 보강 | 생성 모델의 오류와 반복, 검증 가능성 |

이 표는 데이터셋의 성능 순위가 아니라, 수집할 때 던질 질문이다. 공개적으로 읽을 수 있는 문서와 학습·재배포 조건이 확인된 문서도 구분해야 한다. 데이터 출처, 수집 시점, 필터 설정을 기록하면 나중에 성능 변화의 원인을 추적할 수 있다.

### 3-2. 추출·필터링·중복 제거

다음은 교육용 데이터 처리 흐름이다. 실제 파이프라인에서는 순서를 바꾸거나 여러 단계를 반복한다.

```
수집과 출처 기록
  → 본문 추출·언어 식별
  → 품질·안전·민감정보 필터링
  → 중복 제거·평가 데이터 오염 점검
  → train/validation 분리
  → 데이터 혼합·tokenization·학습 샘플 구성
```

**본문 추출**은 HTML 태그를 지우는 것보다 어렵다. 메뉴와 본문을 구분하고, 표나 코드의 구조를 얼마나 보존할지 정해야 한다. 줄바꿈을 모두 없애면 일반 산문은 읽을 수 있어도 코드의 의미가 달라질 수 있다.

**품질 필터링**은 문서 길이, 반복 비율, 언어 판별 점수나 학습된 분류기 등을 사용할 수 있다. 기준을 강하게 하면 잡음을 줄일 수 있지만, 짧은 질의응답이나 소수 언어의 정상 문서를 제거할 수도 있다. 필터 통과율만 보지 말고 빠진 문서의 표본을 직접 읽어야 한다.

<strong>중복 제거(deduplication)</strong>는 같은 문서의 여러 URL, 조금씩 바뀐 복제 페이지, 문서 내부의 긴 반복 구간을 다룬다. 완전 일치(exact duplicate)와 내용이 조금씩 다른 근접 중복(near duplicate)은 다른 문제다. Lee 등의 연구는 중복 제거를 암기된 텍스트 생성 및 train–test 중복과 연결해 분석한다.[^dedup]

<strong>평가 데이터 오염(benchmark contamination)</strong>은 학습 데이터에 benchmark 문제나 해설이 들어 있는 경우다. 문자열 일치로 찾을 수 있는 중복도 있지만 번역·의역된 유출은 더 어렵다. “검사에서 발견하지 못했다”는 결과만으로 오염이 없다고 단정하지 않는다.

<Callout type="example">
같은 한국어 강의 안내문이 서로 다른 50개 사이트에 복제되어 있다고 하자. URL 단위로 train과 validation을 나누면 양쪽에 같은 본문이 들어갈 수 있다. 먼저 본문 유사성을 기준으로 묶고, 같은 묶음이 양쪽에 흩어지지 않도록 분리하는 방법을 생각할 수 있다. 단순 무작위 분할의 단위가 왜 중요한지 보여주는 예다.
</Callout>

FineWeb은 데이터 처리 선택을 바꾸어 같은 구조의 모델을 학습하고 성능을 비교한다.[^fineweb] 아래는 WARC(Web ARChive)에서 추출한 텍스트에 기본 필터를 적용한 경우와 적용하지 않은 경우의 비교다. 필터를 통과한 문서 수보다 **그 데이터로 학습한 모델의 평가 결과**를 본다는 점에 주목하자.

### 3-3. 데이터 혼합과 반복 노출

문서가 저장된 비율과 학습에서 선택하는 비율은 다를 수 있다. 여러 출처의 데이터를 섞는 데이터 혼합(data mixing)을 말뭉치의 문서 수 대신 **모델이 소비하는 토큰의 비율**로 설명하면 계산 예산과 연결하기 쉽다.

예를 들어 100M 토큰을 읽힐 때 일반 문서 60%, 코드 25%, 한국어 전문 자료 15%를 목표로 삼았다고 하자. 이는 교육용 설정이며 권장 비율이 아니다. 한국어 전문 자료가 5M 토큰뿐이라면 15M 토큰을 소비하기 위해 평균적으로 약 세 번 재사용해야 한다. 비율을 높이는 선택에는 반복 노출이 따라온다.

$$
\text{평균 노출 횟수}\approx
\frac{\text{해당 데이터에서 소비할 토큰 수}}{\text{해당 데이터셋을 한 번 읽을 때의 토큰 수}}
$$

분모는 중복 제거된 해당 데이터셋을 한 번 tokenization했을 때의 길이다. Vocabulary에 있는 서로 다른 token ID의 개수가 아니다. 따라서 데이터량을 보고할 때 **중복 제거 후 데이터량과 학습 중 소비한 총 토큰 수**를 구분한다. 같은 1B 토큰이라는 표현도 새 텍스트 1B를 한 번 읽은 것과 100M을 열 번 읽은 것은 다르다.

혼합 비율은 학습 내내 고정할 수도 있고 후반에 바꿀 수도 있다. 어느 쪽이 나은지는 목표 도메인별 검증 결과를 보아야 한다. 평균 loss가 내려가도 작은 도메인의 성능은 나빠질 수 있으므로, 일반 문서·한국어·코드 평가를 따로 유지하는 것이 이 예제에 적합하다.

### 3-4. 학습 시퀀스와 문서 경계

문서의 길이는 제각각이지만 모델은 한 번에 처리할 수 있는 context 길이가 정해져 있다. 따라서 말뭉치의 문서와 학습에 넣는 시퀀스가 항상 일대일로 대응하지는 않는다. 긴 문서를 여러 구간으로 나누거나, 짧은 문서를 이어 붙여 일정 길이의 시퀀스를 만들 수 있다. Megatron Core의 GPTDataset은 샘플이 문서 경계를 넘으면 여러 문서의 토큰을 이어 가져오고, 입력과 정답을 한 칸 차이로 구성할 수 있다.[^gpt-data]

여기서 **배열에서 이웃한 두 문서를 서로의 문맥으로 사용할 것인지**는 별도로 정해야 한다. EOS는 문서 종료를 표시하는 토큰이지 attention을 자동으로 끄는 명령이 아니다.

| 문서 경계 처리 | 뒤 문서가 읽는 문맥 | 학습 데이터의 의미 |
|---|---|---|
| 이어진 causal stream | 현재 배열에 있는 앞 문서까지 참조 가능 | 문서 경계를 포함한 토큰 흐름을 이어 쓰기 |
| 문서별 attention 분리 | 자기 문서의 앞선 토큰만 참조 | 여러 문서를 같은 배열에 담아도 각 문서를 독립적으로 학습 |

독립적인 문서를 학습하려면 입력·정답도 문서별로 맞춘다. §2-2의 문서를 A로 놓고, 한 토큰 더 긴 문서 B를 함께 담아 보자. 아래는 실제 tokenizer 출력이 아닌 교육용 토큰이다. 위쪽 네 행은 같은 위치의 입력·정답·위치 번호·loss mask이고, 아래 행렬은 그 입력 위치들 사이의 attention 허용 범위다.

<Figure src={packedDocuments.src} alt="문서 A 입력은 BOS·부산·항구, 정답은 부산·항구·EOS다. 문서 B 입력은 BOS·코드·실행·완료, 정답은 코드·실행·완료·EOS다. 위치 번호는 0,1,2,0,1,2,3이고 loss mask는 모두 1이다. A의 마지막 입력 `항구`는 EOS를 예측하고, B의 첫 입력 BOS는 `코드`를 예측한다. 배열을 붙여 저장해도 A의 마지막 정답은 그대로 EOS다. 이 그림은 문서별 attention을 분리하고 위치 번호도 문서마다 다시 시작하는 구성을 택했다.

이어진 causal stream이라면 B의 행에서 A0–A2도 허용한다. 이 차이는 EOS의 존재 자체가 아니라 attention 설정이 만든다. Position ID는 각 입력의 위치 번호로, 이 예제에서는 `[0,1,2,0,1,2,3]`이다. Attention mask와 위치 번호는 별도 설정이며, 위치 번호만 다시 시작해도 다른 문서가 가려지는 것은 아니다.

<Callout type="note">
Attention mask는 **어디를 볼 수 있는가**, loss mask는 **어디의 예측을 채점하는가**를 정한다. 어떤 위치를 loss에서 제외하는 것만으로 서로 다른 문서의 attention이 차단되지는 않는다.
</Callout>

## 4. 학습과 평가

### 4-1. 가중치 갱신

한 배치를 학습하는 순서는 다음과 같다.

```
입력·정답·mask 준비
  → forward로 위치별 logits 계산
  → 유효한 정답 위치의 cross-entropy 평균
  → backward로 gradient 계산
  → optimizer가 가중치 갱신
  → 다음 배치
```

Learning rate는 가중치 갱신의 크기를 조절한다. 가장 단순한 SGD(stochastic gradient descent)는 $\theta\leftarrow\theta-\eta g$로 쓸 수 있다. 가중치 하나가 1.0, gradient가 0.2, learning rate $\eta$가 0.1이라면 새 값은 0.98이다. 실제 모델에서는 이 계산을 수많은 파라미터에 적용한다.

대표적인 optimizer인 AdamW는 현재 gradient 하나만 사용하는 대신, 각 파라미터에 두 상태를 유지한다. 학습 step을 $s$, 그 step의 gradient를 $g_s$라고 하자.[^adamw]

$$
m_s=\beta_1m_{s-1}+(1-\beta_1)g_s,\qquad
v_s=\beta_2v_{s-1}+(1-\beta_2)g_s^2
$$

$\beta_1,\beta_2$는 0 이상 1 미만의 계수로, 클수록 과거 상태를 오래 반영한다. $m_s$는 gradient의 지수이동평균(exponential moving average)이고, $v_s$는 제곱 gradient의 지수이동평균이다. 첫째는 최근 갱신 방향을, 둘째는 최근 gradient 크기의 척도를 담는다. $v_s$는 평균을 뺀 분산 자체는 아니다. 두 상태는 가중치 하나마다 하나씩 있으므로, 파라미터가 8B개면 상태 값은 총 16B개다.

초깃값 0의 영향을 보정한 값을 $\hat m_s,\hat v_s$라고 하면 AdamW의 갱신은 다음처럼 쓸 수 있다. 제곱·나눗셈·제곱근은 원소별 연산이다.

$$
\theta_s=(1-\eta_s\lambda)\theta_{s-1}
-\eta_s\frac{\hat m_s}{\sqrt{\hat v_s}+\epsilon}
$$

$\lambda$는 weight decay 계수, $\epsilon$은 분모의 수치 안정화를 위한 작은 양수다. Weight decay는 가중치를 줄이는 항이고, gradient 기반 항과 분리해 적용한다. 어떤 파라미터에 decay를 적용할지도 설정한다.

<Details summary="Adam의 초기 상태 보정과 숫자 예제">

상태를 0으로 시작하면 초기 평균이 작아지는 효과가 있어 $\hat m_s=m_s/(1-\beta_1^s)$, $\hat v_s=v_s/(1-\beta_2^s)$로 보정한다. 교육용으로 $g_1=0.2$, $\beta_1=0.9$, $\beta_2=0.99$라면 $m_1=0.02$, $v_1=0.0004$, 보정 후에는 $\hat m_1=0.2$, $\hat v_1=0.04$다. $\epsilon$과 weight decay를 생략하면 비율은 $0.2/\sqrt{0.04}=1$이다. Learning rate가 0.01이면 가중치 1.0은 약 0.99가 된다. 이는 계산을 보여주는 예이며 권장 hyperparameter가 아니다.

</Details>

학습 초기에는 learning rate를 낮게 시작해 점차 높이는 **warmup**을 사용하기도 한다. 학습 후반의 **decay**는 갱신 폭을 줄인다. **Gradient clipping**은 gradient norm이 임계값을 넘으면 gradient를 같은 방향으로 축소한다. AdamW처럼 상태를 이용하는 optimizer에서는 이것을 최종 가중치 변화량의 직접적인 상한으로 해석하지 않는다. 세 방법은 역할이 다르므로 하나가 다른 하나를 대신하지 않는다. 실제 recipe를 읽을 때에는 learning rate뿐 아니라 전체 학습 길이, batch 크기, warmup 길이를 함께 확인한다.

예를 들어 gradient가 $(3,4)$라면 norm은 5다. 임계값을 1로 정한 norm clipping은 두 성분에 $1/5$를 곱해 $(0.6,0.8)$로 만든다. Warmup·decay가 **step에 따라 learning rate를 바꾸는 것**이라면, clipping은 **현재 gradient의 크기에 따라 적용하는 것**이다.

학습률 곡선도 숫자로 읽어 보자. 교육용으로 총 1,000번 갱신하고, 처음 100 step에서 0부터 최대 학습률까지 선형으로 올린 뒤 마지막까지 선형으로 내린다고 정할 수 있다. 50 step에서는 최대값의 절반, 100 step에서는 최대값, 550 step에서는 다시 절반이다. 실제 recipe는 cosine decay나 최솟값을 두는 방식도 사용한다. 같은 토큰 수라도 batch 크기가 바뀌면 optimizer step 수가 바뀌므로, warmup을 step과 token 중 어느 단위로 지정했는지 확인한다.

### 4-2. 검증 지표

Training loss가 줄어드는 것만으로는 충분하지 않다. 적어도 서로 다른 질문을 나누어 본다.

| 관측 | 답하려는 질문 |
|---|---|
| Training loss | 학습 데이터의 정답 토큰을 더 잘 맞히는가? |
| Held-out loss | 학습에 넣지 않은 같은 종류의 텍스트에도 일반화하는가? |
| 도메인별 평가 | 한국어·코드 등 목표한 능력이 개선되는가? |
| 생성 결과 표본 | 반복·형식 오류·데이터 암기 같은 문제가 보이는가? |

Perplexity는 평균 NTP loss를 지수화한 값이다. 위의 loss 1.040 예제라면 $\exp(1.040)\approx2.83$이다. 낮을수록 정답에 더 높은 확률을 준다는 의미지만, **서로 다른 tokenizer의 토큰 단위 perplexity는 곧바로 비교하지 않는다**. 토큰 단위와 평가 텍스트, 문맥 길이, mask 조건을 맞춰야 한다.[^perplexity]

매 위치에서 네 후보에 각각 $1/4$의 확률을 주고 정답이 그중 하나라면, loss는 $-\log(1/4)=\log4$, perplexity는 4다. 일반적인 경우에는 정답 확률 역수의 기하평균으로 볼 수 있다. 따라서 2.83이라는 값이 실제로 후보를 2.83개 남겼다는 뜻은 아니다.

평가할 때는 배치별 perplexity를 산술평균하지 않는다. 각 배치의 음의 로그 확률 합과 유효 정답 수를 전체에 걸쳐 합산하고, 그 평균 loss를 마지막에 지수화한다. 긴 평가 문서를 짧은 독립 구간으로 자르면 구간 시작에서 앞 문맥을 잃는다. 겹치는 window를 사용하면 앞 문맥을 더 보존할 수 있지만, 겹친 정답을 중복 채점하지 않도록 mask를 정해야 한다.[^perplexity]

데이터 구성과 검증 방법을 정해도 모델 크기와 학습 기간은 아직 선택해야 한다. 같은 계산 예산으로 큰 모델을 짧게 학습할지, 작은 모델에 더 많은 토큰을 읽힐지가 scaling의 문제다.
