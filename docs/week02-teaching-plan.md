# 2주차 수업 진행안

2주차 주제는 `Tokenizer & Pre-training`이며, 다섯 웹 노트의 순서는 유지한다. 이 문서는 강사용 진행안으로, 학생용 웹 노트 컬렉션에는 포함되지 않는다.

## 3시간 분량 검토

**3시간 수업을 구성할 내용은 충분하다. 다만 모든 표·유도·영상을 같은 깊이로 설명하면 시간을 넘긴다.** 1주차의 Transformer 기본 연산을 알고 있다는 전제에서, 휴식 20분을 포함한 180분으로 구성한다. 아래 시간은 실제 강의 속도를 측정한 결과가 아니라, 예제 설명을 포함한 진행 계획이다.

| 경과 시간 | 내용 | 배정 | 설명의 중심 |
|---|---|---|---|
| 0–25분 | 02a Decoder-only LLM overview | 25분 | 문자열 → ID → embedding → decoder → logits → 생성 |
| 25–55분 | 02b Tokenizer | 30분 | 바이트와 BPE 학습·인코딩·복원의 구분 |
| 55–65분 | 휴식 | 10분 | |
| 65–105분 | 02c Pre-training | 40분 | NTP 목표와 학습 데이터의 구성·정제·혼합 |
| 105–130분 | 02d Scaling | 25분 | 고정 계산량에서 모델과 데이터의 배분 |
| 130–140분 | 휴식 | 10분 | |
| 140–180분 | 02e Training engineering | 40분 | 메모리·padding·통신 병목과 병렬화의 역할 |

설명 160분 + 휴식 20분 = 180분. 영상 전편 재생, 코드 설치·실행 실습, 학생 확인 문제는 시간표에 포함하지 않는다. 순수 강의 시간이 180분이라면 추가 20분은 NTP 예제 5분, 데이터 정제 그림 해설 5분, 16 GPU 배치 설명 10분에 배정할 수 있다.

## 다섯 글을 연결하는 논리

1. **Overview → Tokenizer:** 모델의 계산은 정수 ID 열에서 시작한다. 토큰의 단위와 길이를 정하는 선택을 따로 살핀다.
2. **Tokenizer → Pre-training:** 고정된 tokenizer로 말뭉치를 ID 열로 바꾸면, 같은 열에서 입력과 다음 토큰의 정답을 얻을 수 있다. 이후 핵심은 학습에 사용할 문서와 분포다.
3. **Pre-training → Scaling:** 데이터 품질과 혼합을 정했어도 모델 크기와 읽힐 토큰 수는 선택해야 한다. 유한한 계산 예산이 두 선택을 묶는다.
4. **Scaling → Engineering:** 계산량의 추산만으로 실행 가능성이나 완료 시간이 정해지지는 않는다. 메모리에 들어가는지, 유효 토큰을 얼마나 빠르게 처리하는지, 통신이 얼마나 필요한지를 살핀다.

학습자의 관점에서는 ‘어떤 계산인가 → 무엇을 입력하는가 → 무엇으로 학습하는가 → 얼마나 학습하는가 → 어떻게 실행하는가’로 이어진다. 주제를 바꾸거나 순서를 재배열할 필요는 없다.

## 각 노트의 설명 깊이

### 02a: Overview — 25분

전체 경로 6분, ID·embedding 6분, decoder 블록 5분, logits·토큰 선택 6분, 학습과 생성 차이 2분을 기준으로 한다. `n × d`가 `n × V`로 바뀌고 생성에는 마지막 행을 사용한다는 점을 설명한다. Llama의 head 수와 FFN 차원은 표를 읽을 기준값으로 두며, RoPE·GQA·SwiGLU의 내부 수식은 유도하지 않는다. 3Blue1Brown 영상은 말미의 보충 자료로 접어 둔다.

### 02b: Tokenizer — 30분

분할 단위 5분, Unicode·UTF-8 8분, BPE 학습과 새 문자열 인코딩 12분, 전처리·어휘 크기 5분을 배정한다. `banana/band`에서 규칙을 만들고 `bandana`에 적용하는 예제가 중심이다. 실제 Llama tokenizer의 정규식 분석이나 여러 라이브러리 설치는 이 시간에 넣지 않는다. Karpathy 영상과 지정 Drive 자료는 선택 심화 자료다. 확인 문제 블록은 삭제했다.

### 02c: Pre-training — 40분

전체 학습 과정 5분, NTP와 입력·정답 7분, 데이터 구성·정제·혼합 18분, 시퀀스와 문서 경계 5분, 학습·평가 5분을 기준으로 한다. 데이터에 가장 많은 시간을 둔다. FineWeb의 필터링 그림에서는 모델·tokenizer·학습 토큰 수를 맞춘 비교라는 점을 설명한다. Optimizer는 역할을 이해하는 수준이며 AdamW 유도나 learning-rate tuning 실습은 포함하지 않는다.

### 02d: Scaling — 25분

계산 예산과 두 가상 loss 그래프 12분, Chinchilla 비교 6분, 추론을 포함한 비용 2분, emergence와 지표 효과 5분을 배정한다. 최적 비율의 미분 유도는 보충으로 남긴다. Emergence는 ‘규모 증가에 따른 유용한 능력 개선’과 ‘지표에서 급격하게 보이는 변화’를 구분하는 정도로 다루며, 논쟁 전체의 문헌 세미나로 확장하지 않는다.

### 02e: Engineering — 40분

메모리 5분, sequence packing 5분, DP·batch·ZeRO/FSDP 9분, TP·PP 8분, SP·CP·EP 4분, 병렬화 조합 6분, 도구·측정·복구 3분을 기준으로 한다. 가장 밀도가 높은 노트다. DP·TP·PP와 학습 상태 분산에 무게를 두고 SP·CP·EP는 해결하는 병목을 구분한다. EP의 router·expert 구조는 다음 주 범위다. TP의 행 방향 분할 식은 보충으로 접었다. 도구 목록은 별도 사용법 강의가 아니라 앞에서 배운 개념과 구현의 연결로 짧게 설명한다.

## Sequence packing의 위치와 예제

기존 예제는 padding 낭비를 충분히 보여주기 전에 두 문서의 shifted label과 7 × 7 attention mask로 들어갔다. 학습자는 해결하려는 문제를 이해하기 전에 구현 규칙을 읽어야 했다. 또한 문서 독립성을 보존하는 packing을 모든 pre-training의 기본 구성처럼 받아들일 여지가 있었다.

수정 후 설명 책임을 나누었다.

- **Pre-training:** 문서와 학습 시퀀스가 일대일이 아닐 수 있다는 점, 문서 이어붙이기와 문서별 attention 분리의 차이, 문서별 입력·정답 대응을 설명한다.
- **Engineering:** 길이 3과 4인 입력을 길이 8 배열에 각각 담으면 16칸 중 7칸만 유효한 상황을 먼저 보여 준다. Sequence packing으로 8칸 중 7칸을 사용하도록 바뀌는 예제를 설명한다. 문서의 문맥과 정답을 보존해야 한다는 원칙은 pre-training 예제와 연결한다.

이동의 이유는 ‘packing은 무조건 engineering’이라는 분류가 아니다. 현재 수업에서는 **데이터의 의미를 정하는 부분**과 **빈 연산을 줄이는 부분**을 나누면 두 글 모두 자연스럽게 이어지기 때문이다. 큰 attention 행렬은 제거하고, B의 첫 위치는 A를 보지 않으며 B의 뒤 위치는 B의 앞 위치만 본다는 설명으로 바꿨다.

예제의 43.75%→87.5%는 유효 입력 위치의 비율이며, 처리 속도 두 배를 의미하지 않는다. 개별 고정 길이 padding을 가정한 비교다. 이미 문서를 이어 고정 길이를 채우는 pre-training이나 길이별 batching에서는 이득이 달라질 수 있다. [Megatron Bridge Packed Sequences](https://docs.nvidia.com/nemo/megatron-bridge/latest/training/packed-sequences.html)의 현재 설명도 일반 pre-training의 문서 이어붙이기와 주로 fine-tuning에 쓰는 packed-sequence 기능을 구분한다(접근: 2026-09-14).
